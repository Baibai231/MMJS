# ZipfGuard 双端工具：验收与边界

**验收日期:** 2026-10-11。用户端是独立 Chromium 浏览器扩展，管理员端是独立管理网站，配套三个计算服务、两个业务服务、后台作业服务和接入样例。原研究展示网站保留。

本次已经跑通真实注册、私密登录、改密、恢复、注销、历史账户授权迁移、策略执行和整改任务。下表中的协议项目实际调用三方计算，不是前端模拟成功。所有账户和口令均为合成测试数据。

## 2. 两端及隐私边界

| 环节 | 实际实现 | 允许输出 |
| --- | --- | --- |
| 用户输入 | 只在独立扩展页面输入，固定64字节填充后分别发给三方 | 公开请求上下文和每方自己的随机份额 |
| 网站认证 | 网站核验三方签名、一次性挑战、站点和当前凭据版本 | 认证证明与本站业务会话 |
| 账户业务 | 用户查询本人；管理员管理最小账户状态 | 标识、启停、凭据版本、任务和实际完成状态 |
| 受保护画像 | 9个固定结构桶、每桶前三名匿名频谱、18类规则违反人数 | 含噪统计及其快照、预算，没有热门口令字符串 |
| 动态注册策略 | 同一秘密用于完整口令、结构规则与登记；实际联合阻断 | 公开要求、有限合并接受/拒绝结果 |
| 存量整改 | 三方内部判断资格，在人数预算内分配本人任务 | 必要分配和完成状态，没有逐账户口令结构 |
| 客户端与管理台 | 不同来源、密钥、会话受众和浏览器存储；无互发消息通道 | 只经后端传递已授权策略、本人任务和受保护汇总 |

管理员可以看到“某个固定结构中的匿名第几名及含噪频次”，不能看到该名次对应的口令字符串。结构名称来自事先固定的公共目录，不从用户秘密直接公布新的明文结构。OTHER桶不表示某一种结构。

注册策略的L/U/D/S结构与原存量研究的L/S/D结构语义不同。当前在线存量调整基于18类规则违反群体，未声称把原研究全部结构分组直接搬到工具。两类在线决策适配均只接收批准的数值画像。

## 3. 实测性能与观察到的问题

| 项目 | 结果 |
| --- | --- |
| 确认发布样本 | 7个合成账户 |
| 输出维数 | 36维结构人数与匿名频谱，加18维规则违反人数 |
| 确认发布总等待 | 200.454秒 |
| 三方节点计算 | 约197.389秒 |
| 发布快照 | `population-14-confirmation` |
| 本次记录中的累计隐私预算 | 3.0；这是累计值，不是该次发布单独花费 |
| 先前同规模分析发布 | 约246.710秒；发生传输超时后沿原请求恢复 |
| 典型登录 | 原始记录约1.3–1.5秒，未统计并发吞吐量 |

画像是昂贵的后台任务。串行计算中，已开始的画像不会被用户请求中断；用户操作优先于尚未开始的后台作业。生产容量需要另做样本规模、并发和跨网络实测。

结果未知时，用户端保留公开请求及查询凭据，管理端保留作业编号，继续核对原请求。没有重新上传口令或重复扣预算来掩盖第一次超时。业务核对服务能修复已经提交但尚未写入业务记录的最小状态。

## 4. 支撑什么结论

本次结果支撑：在可信扩展、可信TLS、至多一方被动腐化和固定统计目录的假设下，系统能够把秘密输入、认证、贡献更新、含噪统计、实际规则执行和用户整改串成可操作的闭环。理论依赖与新增54维发布的预算口径见 [隐私输出论证](现实工具_隐私输出与新服务论证.md)。

本次没有证明：恶意计算方安全、PAKE安全、两方串通安全、受感染客户端安全、任意网络或磁盘故障无损恢复、大型网站容量、真实用户未来重选成本或策略的长期攻击收益。

自动候选在缺少本站响应和成本确认时记录保持，管理员可单独手动应用快照联合限制。独立确认发布验证统计稳定性的用途与未来用户行为预测不同。含噪人数不适合在7人样本中解释为准确热门排名。

登录、接受/拒绝和必要任务状态属于允许的业务输出，存在推断信息；查询限额只是控制在线试探。明文扫描未命中测试字符串，只证明检查产物未直接留存这些字符串。秘密分享和差分隐私的理论保证必须同时写明假设、预算和有限采样尾界。

## 5. 实际交付与使用

交付包括用户扩展包、管理台构建包、完整工具源码包、验收证据包和SHA256清单。用户扩展使用MV3，管理台使用独立网站入口，源码包负责配置并启动后台。管理台构建包单独解压不能替代后台服务。

本机7个服务全部由同一台电脑控制，因此本机只能复现流程，不能据此声称三方独立托管已经实现。独立部署模板见 [部署说明](../deploy/README.md)，安装及操作见 [安装与使用](现实工具_安装与使用.md)。

验收结束后停用QA管理员，生成一份新的单次负责人安装凭证，凭证保存在本机私有目录，不放入交付包。源码安装会重新生成自己的密钥、信任配置和邀请；原运行私钥、份额数据库及个人恢复秘密不随包分发。
