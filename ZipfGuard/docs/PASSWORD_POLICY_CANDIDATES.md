# 口令策略候选池：现状、组合与可讨论的扩展

本文件只提供规则目录与研究说明，不修改运行中的候选池。策略是接受或拒绝口令的条件；示例字符串用于解释条件，不是从用户私有口令中摘取。

## 为什么当前先采用这些规则

当前研究只有口令字符串、频数和模拟注册顺序。长度、字符类别、黑名单、重复与顺序模式可以直接从这些数据判定，已有网站或企业口令系统使用类似机制；规则易解释，也便于计算修改成本。历史热点黑名单的形式属于常见阻断表，按已注册分布更新的方式则是本项目的研究设计，不是已有统一标准。

“市场上存在”与“现代标准推荐”需要分开。NIST SP 800-63B-4 强调长度和常见、已泄露口令阻断，并禁止额外的字符组成要求；传统企业复杂度规则仍可作为实验对照。当前长度 8 是共同实验起点，不代表其符合 NIST 最新的单因素认证最低长度 15 要求。

## 当前代码能够表达的单项规则

| 类别 | 参数或动作 | 精确定义 | 当前状态 |
| --- | --- | --- | --- |
| 最短长度 | 8、10、12、14、16 | 至少达到所选长度；每轮只提供下一档更长的候选 | 默认启用 |
| 字符类别 | 至少 2 类、至少 3 类 | 从小写、大写、数字、其他字符四类计数；不指定必须出现哪一类 | 默认启用 |
| 开发热点黑名单 | Top 100、1,000、10,000 | 禁止与开发训练数据中高频口令完全相同；每轮提供下一档尚未完全覆盖的名单 | 默认启用 |
| 历史热点黑名单 | 历史 Top 100 中使用次数至少 2 的口令 | 只读取已完成批次，合并到现有黑名单，后续批次拒绝这些完整口令 | 默认启用 |
| 连续重复字符 | 禁止连续 3 个及以上相同字符 | 如 `aaa`、`111` 出现在任意位置 | 可选，默认关闭 |
| 连续数字 | 禁止代码列出的连续 4 位升序或降序数字 | 如 `1234`、`6789`、`4321`；不是任意长度数字串检测 | 可选，默认关闭 |
| 键盘或简单序列模式 | 禁止 `qwerty`、`asdf`、`zxcv`、`1234`、`4321`、`abcdef` 子串 | 不区分大小写；当前是少量模式匹配，不是通用键盘随机游走识别 | 可选，默认关闭 |
| 保持 | `hold` | 沿用当前完整策略，不增加限制 | 每轮必有 |

当前类别检查的 Unicode 行为以代码为准：英文字母使用 `[a-z]` 与 `[A-Z]`，数字使用 `\d`，其他字符使用 `[^A-Za-z0-9]`。这并不等同于覆盖所有语言文字的互斥分类系统；修改这一点属于另一项候选定义变更。

## 所有组合如何表示

所有规则以“同时满足”组合，并归一化为：

`最短长度 L + 最少类别 C + 开发黑名单 B + 历史黑名单 H + 模式限制集合 D`

- `L ∈ {8, 10, 12, 14, 16}`。
- `C ∈ {不额外要求, 2, 3}`。
- `B ∈ {关闭, Top100, Top1000, Top10000}`，这些开发名单按相同排序构建并嵌套。
- `H ∈ {关闭, 按历史热点扩展}`，实际名单只能来自此前批次。
- `D` 是重复字符、连续数字、键盘模式三项的任意子集。

共 `5 × 3 × 4 × 2 × 8 = 960` 个结构模板，完整清单见 [policy_candidate_profiles.json](policy_candidate_profiles.json)。其中 120 个模板不含默认关闭的模式规则。模板数量不是当前每轮实际评价的候选数，也不是具体口令数量；历史黑名单内容会随数据变化，成本条件还会排除部分模板。

同一维度只保留最强条件，例如“长度至少 8 且至少 12”归一为至少 12；开发黑名单 Top100 与 Top1000 合并为 Top1000；两个黑名单取并集。这样避免重复计算语义相同的规则。

组合示例：

| 示例 | 组合规则 | 说明 |
| --- | --- | --- |
| A | 长度至少 8 | `meadow47` 满足长度条件 |
| B | 长度至少 12＋至少 3 类字符 | `River!Cedar8` 满足可见条件 |
| C | 长度至少 12＋开发 Top1000 黑名单 | 除满足长度外，还须不在实际名单中 |
| D | 长度至少 12＋至少 3 类＋禁止连续重复 | 排除用 `aaa` 等简单重复补足长度的候选 |
| E | 长度至少 16＋开发 Top10000＋历史热点 | 可见长度与两种完整口令阻断表同时生效 |
| F | 长度至少 16＋至少 3 类＋三种模式限制＋两种黑名单 | `V7!mR2@kP9#tD4$z` 可演示长度、类别和模式条件；最终能否通过仍取决于实际黑名单 |

## 兼容性的必要条件

1. 兼容性约束针对同一批同时生效的规则。最新自由选择试验允许下一批改选其他完整模板或重复当前模板，不自动继承上一批的额外限制；“只能加严”是旧控制器的限制，不是规则不矛盾的必要条件。
2. 不同时加入相互冲突的允许范围，例如“只能用数字”与“必须含字母”，或“禁止特殊字符”与“必须含特殊字符”。
3. 若未来引入最大长度，必须不小于最短长度，并能容纳所需字符类别；当前不使用较短的最大长度作为加严手段。
4. 规则不矛盾不代表成本可接受。每个组合仍须检查有无可生成的合规口令、修改率、额外修改成本及风险代理。
5. 名单必须来自独立开发数据或过去批次，不能读取未来注册口令或用正式攻击评估结果挑选规则。

## 可讨论、尚未接入的常见扩展

| 规则族 | 可讨论的单项设置 | 条件与边界 |
| --- | --- | --- |
| 更长口令 | 至少 15、18、20 位 | 15 位与 NIST 单因素要求相关；具体阶梯是实验设计，不是统一市场标准 |
| 更多类别 | 至少 4 类，或指定至少含数字／大小写／符号 | 传统企业或网站常见；不是 NIST 当前推荐的组成政策 |
| 参数化重复限制 | 同一字符最多连续 2 或 3 次 | Linux libpwquality 类机制；需说明是否只限制连续重复 |
| 参数化顺序限制 | 禁止连续 4 或 5 位字母、数字顺序 | 应定义升降序、大小写及检测边界 |
| 更完整键盘路径 | 对固定键盘布局禁止长度达到阈值的相邻键路径 | 商业产品有类似限制；需固定布局、邻接关系与阈值 |
| 外部常见或泄露名单 | 完整口令命中则拒绝 | 使用独立来源并版本化，避免把正式测试语料全部放进名单 |
| 用户名、姓名、邮箱或组织名相关项 | 禁止相同或明确约定的包含关系 | 企业系统常见，但当前数据没有这些字段，暂不引入 |
| 同类字符连续上限 | 同一字符类别最多连续若干位 | libpwquality 的 maxclassrepeat 类机制；与长度和类别约束一起做可满足性检查 |

历史口令复用、定期更换、登录锁定和多因素认证不放进当前首次注册的字符串策略池。它们需要其他状态或影响认证流程，不能用当前数据诚实模拟。
