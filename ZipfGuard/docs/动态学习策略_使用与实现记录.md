# 动态学习策略：使用与实现记录

## 本次新增内容

新增独立的上下文候选搜索控制器、实验管线、三档配置、运行入口和结果汇总工具。原控制器、原配置、已有网页和发布快照均保留；新实验只写入 `reports/contextual/` 指定目录，不更新 `published/intervention/latest.json`。

第一版实现以下机制：

- 群体、局部规则和通知人数共同构成动作，复用原有候选生成与响应模块。
- 以经验对数排名 W1 为目标，使用共享线性模型及乐观评分分配候选模拟机会。
- 从独立开发 tuning 出现记录构成的群体预热，然后仅用各方法实际执行后的反馈更新。
- 筛选、独立复核、实际执行分别使用不同随机流；新增四组使用相同的随机流命名规则以减少噪声。原控制器保留原命名方式，故与原控制器的比较只配对初态，不保证逐账户响应随机数也相同。
- 所有最终采用的新口令通过固定 PCFG 和作者版 OMEN 的实际猜测前缀门槛。
- 保留经验准入和严格 Hoeffding 下界准入两种模式；本次效果实验使用经验模式。
- A1 在独立参考群体按公开动作迁移后的数据上重训，不用目标终态口令训练。
- 独立记录通知、编辑、显式补全、失败、响应调用量、运行时间和停止原因。

## 当前实现与方案的具体差异

当前特征为 35 维，包含分布、预算、轮次、群体、规则、人数及简单交互项；历史迁入与编辑成本特征尚未加入。所有特征按预定尺度转换，不在目标数据上拟合标准化参数。

第一版先运行一条开发群体预热轨迹，最多 5 轮。若很快达到单例分布，实际反馈样本可能很少；报告明确给出数量，不能把它描述为充分训练。多开发场景预热、响应偏移、漂移窗口和两步规划是后续研究，不属于本次已实现效果。

未添加额外的扩大搜索重试：一次独立复核没有通过即明确停止，这有利于固定计算预算。构造失败也停止，不自动重复利用同一验证随机流。未实现任意规则的逻辑等价判定；仅合并“同一规则且所选账户完全相同”的候选。

新管线中的原控制器参考复用原 `select_action`、拟合目标、组合动作与两步前瞻。外层使用同一通知上限和最多 40 轮，关闭原非 Google 分支的相对攻击收益提前停止条件；因此是原选择算法的受控重跑，不是原发布实验的逐位复现。它不受新搜索器每轮模拟上限约束，须单独披露资源。

前四组具有相同每轮模拟上限，但终止轮次和实际模拟次数可以不同。原参考组的响应计数还包含其内部参考重放；新组计数把参考重放放在控制时间内，但不混入目标候选的响应调用计数。因此原参考组的响应调用总数只作资源提示，不应直接换算成速度倍数；墙钟时间也受机器负载影响。

## 如何运行

以下命令在 `ZipfGuard` 目录执行。双攻击评价需要已有语料、Python 环境和能运行作者版 OMEN 的 WSL；不下载新数据，不替换原模型。

```powershell
.\.venv\Scripts\python.exe tools/run_contextual_study.py --config configs/contextual_smoke.json --output-dir reports/contextual/my_smoke
.\.venv\Scripts\python.exe tools/run_contextual_study.py --config configs/contextual_medium.json --seed 42 --output-dir reports/contextual/my_medium_seed42
.\.venv\Scripts\python.exe tools/run_contextual_study.py --config configs/contextual_full.json --seed 42 --output-dir reports/contextual/my_full_seed42
```

三档为 1,000、10,000、100,000 个账户。配置存在不表示该规模已完成实验，以输出目录内 `report.json` 的 `status=complete` 为准。相同目录已有完整结果时会拒绝覆盖，换用新目录即可。

结果文件包含完整配置、源码哈希、语料摘要、共同起点哈希、预热情况、逐轮选择与验证、F/A1 曲线、实际通知与资源计数。`progress.json` 用于查看进行状态；最终交付以 `report.json` 和对应 SHA-256 文件为准。目录内不导出完整口令或账户 ID。

汇总多个已完成结果：

```powershell
.\.venv\Scripts\python.exe tools/summarize_contextual_study.py reports/contextual/seed42_1000/report.json reports/contextual/seed42_10000/report.json --output docs/动态策略实验结果_汇总.md
```

## 如何读比较结果

优先比较原控制器与新策略在相同实际通知人数下的分布效果。若实际通知人数不相同，先看共同预算上限下各自停止的位置；终态攻击率不能解释成等实际成本比较。

如果所有方法都达到经验距离零，就转而比较达到该状态所需的通知人数和计算成本。经验距离零只说明样本内完整口令不同，不代表攻击命中率为零。

学习与不探索版本表现相同时，说明本次没有观察到探索的额外收益；如果原控制器效果相同且资源更少，当前应继续使用原控制器。新增实现保留为研究对照，不因算法更复杂而替换原默认入口。

## 测试范围

新增测试核对配置隔离、学习更新、预览不改状态、随机流分离、模拟次数上限、个体门槛、整批失败不扣通知、账户去重、预算上限、固定前缀风险精确下降、严格模式拒绝未认证收益，以及结果单独保存和拒绝覆盖。

已有双攻击与分布测试也应一并通过。Windows 测试临时目录若不可写，可将当前进程的 `TEMP`、`TMP` 指向项目内可写的测试目录，不修改系统设置。

## 新增：十万账户与 Yahoo! JAPAN 三方法对照

独立配置 `configs/contextual_yahoo_100k.json` 只运行新老虎机、原动态控制器参考和 Yahoo! JAPAN 全站策略，目标与开发样本均为 100,000。不改变原全量配置与历史结果。

```powershell
.\.venv\Scripts\python.exe tools/run_contextual_yahoo_comparison.py --output-dir reports/contextual/seed42_100000_yahoo
```

新入口支持在局部完整报告已保存后继续 Yahoo 阶段，拒绝覆盖完整的 `comparison.json`。缓存与结果都附有 SHA-256 校验。为恢复完全相同的样本，新入口在已忽略的本地结果目录另存 `private_sample.json`，其中包含原始抽样口令；这是本地计算缓存，不是公开报告，不应发布。前文“不导出完整口令”描述的是原 `run_contextual_study.py` 的结果文件；本次三方法入口的私有缓存属于新增例外。完成对照的公开分析不包含这些口令。

图和分析从完整 `comparison.json` 生成，输出 PNG、SVG 和独立 Markdown。绘图使用本机已安装 Matplotlib 的 Python 环境；实验仍使用项目虚拟环境。

```powershell
& 'D:/Anaconda/anaconda/python.exe' tools/plot_contextual_yahoo_comparison.py reports/contextual/seed42_100000_yahoo/comparison.json --output-dir docs/figures --markdown docs/十万账户_动态策略与Yahoo对照.md
```

两个局部方法共享 8 字符基线起点，累计局部通知上限为 20%；Yahoo 从相同原始目标样本执行全站合规迁移，不受局部上限约束。图中同时报告攻击结果和从原始样本起算的修改成本，不能把结果解释为等实际修改人数的比较。
