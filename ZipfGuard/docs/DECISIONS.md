# ZipfGuard 技术决策记录

## D001：当前主线仅使用本地合成数据（已被 D008 取代）

- 日期：2026-09-18
- 状态：历史决定；2026-09-26 起由 D008 取代，旧实现仍按此运行
- 原因：先验证实验逻辑、数据隔离和自适应攻击闭环，避免真实口令数据带来的隐私、授权和频次质量问题。
- 影响：所有结论必须表述为“在当前合成语法和实验协议下”。

## D002：策略公开，攻击者可以自适应

- 日期：2026-09-18
- 状态：已接受
- 原因：网站口令规则通常可见，不能把“攻击者不知道规则”当作安全来源。
- 影响：每个策略同时接受冻结攻击和重新训练后的自适应攻击。

## D003：主实现统一到 Python

- 日期：2026-09-18
- 状态：已接受
- 原因：当前分布、流水线、报告和 Web 主体均为 Python；维持两套核心实验会造成指标与结论漂移。
- 影响：`src/lib/redteam.js` 暂作经过验证的参考实现，关键逻辑逐步迁入 Python。

## D004：安全指标以攻击预算为中心（由 D010 明确新主指标）

- 日期：2026-09-18
- 状态：已接受
- 原因：长度和字符类别提高不必然降低自适应攻击风险。
- 影响：核心指标采用 `cracked@K`、Top-K 质量、覆盖率、置信区间和最坏攻击者结果；长度与字符类别只作解释变量。

## D005：策略必须模拟用户响应（由 D011 扩展为解析或样本式响应）

- 日期：2026-09-18
- 状态：已接受
- 原因：被规则拒绝的用户会重新设置口令，不能从评估样本中直接消失。
- 影响：策略评估必须记录采用率、修改率、修改次数和修改后的口令分布。

## D006：测试集只用于最终评价

- 日期：2026-09-18
- 状态：已接受
- 原因：反复依据测试结果选择策略会造成评估泄漏。
- 影响：攻击器训练使用 train，攻击参数使用 tuning，策略选择使用 validation，最终报告使用 test。

## D007：第一大点工程整改

- 日期：2026-09-22
- 状态：已实施
- Python 为唯一权威实验核心；两个网页共享展示；JavaScript 只作为历史原型。
- 所有结果带完整配置与环境清单，精确文件哈希放在边车文件。
- 可选攻击器失败后从整次比较排除并重算；不得静默替换；必选模型失败终止。
- PassLLM 环境检测与实际参与分开；聚合数据不附带合成策略结果。
- 本轮不声称完成开放生成预算协议、独立公开基准或真实用户研究。

## D008：真实口令及频次作为主实验数据

- 日期：2026-09-26。
- 状态：已实施。
- 依据：本轮用户指定真实泄露口令为被攻击数据，并结合近三小时关于筛选/重新选择的讨论。
- 决定：以真实频次数据建立固定加权划分；合成数据保留为测试、演示与压力场景。
- 影响：新增正确的带频次解析与字符串数据通路；来源、计数、重复行和编码核验独立记录。旧聚合入口与旧合成实验不代表新主实验。

## D009：取消公共候选允许列表，采用开放生成

- 日期：2026-09-26。
- 状态：已实施。
- 决定：“无限空间”解释为不人为取共同候选交集；各模型独立生成，实际仍有预算与资源上限。
- 影响：独立生成器不能读取 test 或精确响应全集；数据观测支持与模型支持不必一致。旧 fit_select_rank 仅服务 legacy_closed。

## D010：主风险采用逐口令 Min_auto

- 日期：2026-09-26。
- 状态：已实施。
- 依据：Ur et al., USENIX Security 2015，第 3.3 节及本任务对本地论文的核对。
- 决定：对各模型首次命中位置逐口令取最小值，再按用户/出现频次权重计算预算内命中率。单模型曲线保留诊断用途。
- 影响：M2、M3、M4 与报告采用同一聚合；旧“最大单模型命中率”退出主推荐目标。Min_auto 的 K 是每模型预算，不是组合总预算，也不是所有攻击者的理论界。

## D011：真实分布重新选择连接筛选与用户响应

- 日期：2026-09-26。
- 状态：已实施 R0/R1/R2；R0 为默认解析基准，行为参数外部校准与正式稳健性研究待完成。
- 决定：R0 采用独立重新选择直到成功，最终分布为策略条件分布；分别报告接受率和额外尝试期望。R1/R2 在真实初始数据上检查固定修补和混合响应。
- 影响：先划分再响应，攻击器仅学习响应后的 train。筛选本身不自动证明真实修改行为。有限重试/放弃需单独处理完成率、成本和风险分母；不可行策略不记为零风险优选。

## D012：主预算按不同有效校验候选计数

- 日期：2026-09-26。
- 状态：已实施；替代 2026-09-24 实施稿的原始输出主预算。
- 决定：open-minauto-v1 中按允许的公开策略过滤、模型内去重，然后对提交校验的候选计费；目标语料以外的候选也计费。
- 影响：另保留原始生成位置、过滤/重复数和资源成本。超时与自然耗尽分开，不完整预算不能以零命中进入推荐。口径不一致的模型先适配或单列。

## D013：以自适应风险和用户负担选择需求对应策略

- 日期：2026-09-26。
- 状态：已实施；需求参数在测试前冻结。
- 决定：A1 自适应 Min_auto 为主要终点；常见规则在相同数据、预算和响应下形成对照前沿，按风险要求最小化成本或按成本上限最小化风险。
- 影响：F/A0 解释知识和训练变化，A2 单列压力；不同需求允许选择同一策略、常见规则或无可行改进。不预设推荐一定优于对照，不从 test 挑选有利参数。

## D014：分布分析通过规则发现连接最终评价

- 日期：2026-09-26。
- 状态：已实施训练频次特征发现与等规模消融入口。
- 决定：训练频次画像用于提出可解释候选；交叉拟合攻击标签作为尚未启用的扩展，最终选择由响应后的自适应 Min_auto 与成本决定。
- 影响：频次排名 CDF 不当作实际攻击排名；用相同候选规模与资源上限的消融检验分布引导贡献。Min_auto 为引用的已有方法，项目贡献需由整合流程和实验支撑。

## D015：新协议实现与工程验收

- 日期：2026-09-26。
- 状态：已实施。
- 默认 CLI、轻量网页与 Streamlit 切换到 open-minauto-v1；legacy 闭集入口保留历史复现。
- 数据四划分 train/tuning/validation/test 为 60/10/10/20。采用全文件出现抽样，不截取频次文件头部。
- n-gram 为长度条件化概率模型，使用精确后缀界的 A* 枚举；PCFG 原始流统一计费，均不接收目标允许列表。
- 配对比较仅在预算可完整评价时运行；测试需求不达标会覆盖改善标记。无可行与无改进证据是正常输出。
- 75 项测试通过；真实数据、四模型响应与实际浏览器验收见 [项目状态](PROJECT_STATUS.md)。该验收不等于科学有效性已获证明。

## D016：外部语料只输出聚合，不改写已冻结的建议权重

- 日期：2026-09-25
- 状态：已接受
- 原因：E2.6 需要至少一个未参与方法设计的公开语料。MAYA 基准的 Google Drive 文件可以在本地核分布和特征排序，但不能把明文写进报告，也不能拿这些结果回头改验证集上选出的策略。
- 影响：`local_datasets/` 不进入版本库。外部结论只包括曲率拟合、该站点自己的 IGR，以及和已复现 RockYou 排序的 Spearman。猜中率、跨站防御和论文里的 69%、25%、80.23% 都不从这里推出。站点语言不是英语时，英文词表特征只作为迁移失败的证据。
