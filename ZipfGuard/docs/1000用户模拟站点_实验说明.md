# 1000用户模拟站点：实验说明

本次用于扩充双端工具的操作展示。网站后台共有1000个合成账户：保留原来的8个演示账户，由模拟客户端新增992个合成历史账户。新增账户是离线预置的测试输入，不是1000次网络注册，也不是真人用户实验。

## 账户和口令怎样准备

新增账户使用固定种子241012构造，包含常见短长度、重复使用、八类公开结构和OTHER结构。所有输入都是人工构造的合成数据，不从真实用户收集口令，也不读取泄露语料。

模拟客户端分别生成每个计算方的随机份额。网站业务数据库只有账户标识、凭据版本、启用状态和任务状态。生成的合成口令及恢复材料保存在私有模拟客户端目录，不进入管理员接口和分发包。

为控制本机运算量，初始化时模拟客户端另行准备随机份额形式的秘密频次表。该准备方式仅允许在本机合成数据环境使用，不提供真实网站的公开导入接口。原演示账户通过秘密比较并入统计，不重新打开原口令。之后，真实注册、改密、恢复与注销操作同步更新秘密频次表；匹配位置、计数和热门字符串都不向管理员公开。

这一过程依赖受信任的合成数据准备者，不能作为1000名真实用户上传一致性的验证。统计发布本身由三个计算方实际执行，输出按原机制加噪并扣除预算。

## 分批调整安排

| 项目 | 设定 |
| --- | --- |
| 后台总账户数 | 1000 |
| 新增模拟账户数 | 992 |
| 保留原演示账户数 | 8 |
| 每轮最多通知 | 20人，占总人数2% |
| 本次计划轮数 | 5轮 |
| 本次计划通知 | 100人，占总人数10% |
| 站点累计分配上限 | 200人，占总人数20%，原有名额不返还 |
| 本人任务要求 | 口令至少15字符 |
| 每轮模拟响应 | 16人提交合规新口令，4人暂未响应 |
| 本次实际完成与待处理 | 80人完成，20人待处理；来自已验证的三方改密结果 |
| 公开基础要求 | 新注册和改密至少12字符；原有短口令仍能登录 |
| 统计发布 | 调整前后各一次ε=1的受保护快照；同一快照读取缓存 |

选择20人单轮上限用于展示有限通知规模，100人本次计划用于保留明显的已完成和待处理状态。80%的响应比例是预先设定的测试条件，没有据此估计真实用户接受率。

计算方根据秘密口令判断是否违反任务要求，再按上限分配。每轮16名模拟响应者逐个通过真实私密登录和改密流程。每轮另提交一次满足网站12字符要求、但不满足本人15字符任务的口令，检查拒绝后任务是否仍待处理。管理员只取得必要任务状态。

调整前快照为population-17，调整后快照为population-97，均覆盖1000个账户、各消耗ε=1。原有ε=3保留，最终累计消耗ε=5。管理员端已经显示两次快照的结构人数对照，统计数字是含噪估计。

## 管理员端怎样查看

- **运行总览：** 1000个账户、明确的合成模拟提示、本次五轮分配和完成记录，以及站点累计额度。
- **受保护画像：** 最新1000账户的结构人数和结构内匿名频次。实验完成后，页面展示调整前后快照对照。数字均为含噪估计。
- **存量分布调整：** 每轮上限20人、累计上限200人，并保留实际计划记录。
- **账户与任务：** 按000-sim-筛选新增模拟账户，查看凭据版本及待处理或已完成状态。
- **决策与效果：** 查看真实三方操作回执对应的业务记录。

原有任务、策略历史和发布预算均保留。因此总览的累计任务数包含原来的2项，不能把累计总数直接当作本次100人实验的数目。新注册和改密也不会修改已发布的历史快照。

## 实际任务结果

五轮均实际分配20人、完成16人、保留4人待处理。本次共通知100人，占后台总账户数10%；实际完成80人，20人仍待处理。五次不满足本人任务要求的改密均被拒绝，拒绝时任务没有被误记为完成。

原有2项已完成任务保留。因此后台累计102项任务、82项已完成、20项待处理，与本次100人实验单独列出的数字含义不同。

## 本次结果的用途

本次说明双端工具能够在1000个后台合成账户上形成统计、任务分配、用户执行和反馈的运行流程，并展示拒绝与未响应的处理。它不是1000次逐笔注册或并发负载测试，也不估计真人响应行为。

离线参考指标只针对新增的992个模拟账户，单独存放于实验结果。管理员端不发布对应的精确频次或口令列表。对口令分布、攻击效果和隐私保证的论文结论，仍应按各自实验和安全条件解释。

## 验收结论

- 秘密合并统计与逐账户计算的101项三方一致性检查通过。
- 四项提交与恢复测试通过，已使用的预算和任务名额保留。
- 真实浏览器的九项检查通过，包括1000账户显示、前后对照、同一待处理账户的双端状态、管理员接口不含模拟口令或份额、只读角色不能分配、管理员会话不能访问用户本人接口。
- 网站和计算节点均拒绝21人的超额请求；单轮上限20人，拒绝后累计名额仍为102、隐私预算仍为5。
- 两次画像的分母、人数约束、匿名频次范围、三方共同状态及最终发布签名等11项一致性检查通过。

长时间运行中客户端管理员会话曾过期，使用正常通行密钥重新登录后续查同一个请求，没有重新发布统计。结果文件中的操作用时包含等待与运行中断，不把这些用时当作协议性能基准。

## 复核材料

结果写入reports/tool_population_1000_20261012。result.json记录最终一致性核对、每轮结果和范围；baseline-profile.json与final-profile.json保存已发布的受保护快照；compact-protocol-check.json记录秘密合并统计与逐账户计算的一致性检查。

私有运行目录保存初始化前的数据库与账本备份，停止与重启不返还已使用的隐私预算或通知名额。不要把该目录作为工具分发材料上传。

## 运行中的存储问题及修复

第四轮已完成58次改密时，E盘剩余空间不足。旧实现为每次登录和改密保留完整账户副本，千用户环境下占用增长过快。修复后，仅在尚未提交的修改操作中保留完整恢复状态；提交完成后，当前状态与回执一起持久保存，旧准备记录保留回执和版本。

恢复前逐方完成完整数据库备份，并核对当前份额、预算、事务决定、完成回执和原请求均未改变。四项独立存储测试覆盖提交前恢复、提交后状态保留、非修改请求精简及旧备份缺少份额时拒绝恢复。恢复使用原请求续跑，没有重新初始化账户、返还预算或重置已完成次数。该检查不替代实际部署所需的独立计算方安全条件。
