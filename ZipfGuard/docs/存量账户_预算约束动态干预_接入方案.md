# ZipfGuard 存量账户预算约束动态干预：接入与改进方案

日期：2026-10-01。

本文基于当前工作区源码、配置及项目状态文档的静态核查，结合用户提出的“改谁、怎么改、改多少”目标编写。附件《ZipfGuard_Implementation_Guide(1).md》作为设计参考，其中的排期、四模型、19 数据集和实施指令不视为用户本次要求。本文提出实现方案，没有修改实验代码、重新运行实验或证明安全收益。历史数字引用现有项目文档，不能当作本次复测结果。

## 1. 核心建议

新增一条“存量账户、固定总人数、预算约束、局部改密”的实验协议，保留当前“新用户分批注册、网站规则路径”的协议作为历史对照。复用数据读取、Rule、特征、PCFG、分布统计和图表组件，重建账户状态、响应语义、局部动作、预算账本和闭环控制器。

推荐新协议标识为 selective-intervention-v1。第一版使用 PCFG 蒙特卡洛索引做快速决策，增加可核查的小预算猜测序列及终态适应攻击。不要同时把 PCFG 蒙特卡洛估计全面替换、四模型接入、前端重写作为第一版前提。

## 3. 先固定实验对象和状态

### 3.1 固定存量人群

第 0 轮即有 N 个模拟账户。每轮只改变选中账户的口令，总人数固定。第一版不引入新注册、流失、自然改密，避免把不同机制混在一起。

输入仍可来自已有带频次语料和抽样机制；对 10 万级实验，为抽到的出现记录分配稳定匿名账户 ID。原始语料没有真实身份，因此覆盖率称为“模拟账户累计受影响比例”。数据量更大时再改为带历史状态的 cohort 整数计数。

每个账户至少保存：当前口令、首次干预轮次、通知次数、实际修改次数、最近结果、适用规则版本。聚合 cohort 时，这些影响后续选择或攻击假设的状态必须进入分组键。

### 3.2 两层信息

- 全站分布：回答哪些精确口令或结构正在聚集，并作为风险分母。
- 可干预分布：仅包含仍有干预资格的账户，回答下一轮还能选谁。

二者必须分开。已干预者迁移到新口令后，不能因“字符串是新的”而被当成新账户重新计费。

第一版每账户最多干预一次。规则在本次改密中生效，平台基础规则继续存在；不自动要求所有账户遵守每轮新增规则。不允许通过新基础规则预先修改大量账户却不计入预算。

### 3.3 成本账本

记录本轮通知人数、累计不同被通知人数 U、累计不同成功修改人数、成功修改事件数 V、标准化编辑距离总量 E、未响应与未完成数。所有比例以固定 N 为分母。

即使用户不响应，也计入 U；旧口令继续参与风险评价。通知成本不能用“成功修改人数”替代。重复干预版本必须同时追踪累计覆盖与事件数，不能简单累加每轮比例。

## 4. 决策单位：群体、规则、整数人数

动作 a = (g, rule_version, n)，另保存群体筛选器、选人种子和规则内容哈希。n 明确表示账户数，避免“群体的 2%”与“全站的 2%”混淆。

第一版按确定优先级构造互斥群体：热门精确口令；剩余高风险口令的结构群体；剩余重复/连续/键盘模式群体；其他。保留非 head 但容易被猜中的群体。同群体内以固定匿名 ID 哈希排序选人，避免虚构用户个体行为差异。

候选首先支持三类：冻结热门名单、重复/连续模式限制、局部长度提升。可复用 Rule，但为每条规则明确适用对象。长度候选可先取局部 +1/+2 或少量预设阈值；字符类别要求作为普通候选或基线，不默认更安全。两规则组合放在单规则流程稳定之后。

每动作枚举全站 0.5%、1%、2% 等少量规模，然后截断到群体实际人数、单轮上限、累计剩余预算，去掉重复人数和零人数候选。这些是起步参数，需做敏感性分析。

Zipf head 用于提供候选和解释，不把 Zipf 参数本身当作安全目标。已有曲率实现按连续极值取 floor；若新增邻近整数曲率比较，应单列新方法版本，不能悄悄修改历史基线。

## 5. 优化目标和选择方法

### 5.1 主指标

先设一个便于与项目历史解释对齐的主攻击预算，例如 10^6，同时报告 10^3、10^4、10^5、10^6 曲线。具体预算在开发阶段固定。

账户加权风险为：

$$
R_{m,G}(D_t)=\frac{1}{N}\sum_p f_t(p)\mathbf{1}[r_m(p)\le G].
$$

若 r 来自蒙特卡洛估计，必须标为估计命中率；若来自实际猜测列表，则记录模型内去重、生成顺序、有效预算和停止状态。两种 r 的排序定义不同，不能直接混在一张未标注方法的排名表中。

第一版以 PCFG 为选择模型。以后再扩展“各模型多预算风险加权后取最大值”，并保留原始曲线。不要将 PCFG 概率、神经模型 likelihood、Zipf 参数直接相加。

### 5.2 先可行、再比较净收益

1. 根据剩余人数预算截断候选。
2. 在当前真实模拟状态的独立副本上预测响应。
3. 计算全站风险差和增量成本；不能用群体内部风险差替代全站贡献。
4. 排除净收益不足、模型可靠性不足或触发配置中风险回退限制的动作。
5. 按预期风险下降 / 新增受影响比例选优；编辑成本和修改事件可以作为约束或预先固定的次级排序。
6. 只执行一个动作，然后重建候选。第一版不同时采纳多个在旧状态上独立估值的动作。

相应启发式为：

$$
\operatorname{score}(a)=\frac{\mathbb{E}[R(D_t)-R(D_{t+1}^{a})]}{n_a/N}.
$$

因第一版不重复干预且 n_a 大于零，分母是确定的增量覆盖。需要复合成本时再加入预注册权重，保留 U、V、E 的独立结果。该贪心法不保证全局最小成本。

候选可先粗评 3 次，对少量候选精评 10 次；预测与执行使用分离的随机流，不能挑预测样本中最理想的一次作为执行。可用共用随机数减少候选比较噪声，但不要让候选遍历顺序改变结果。

通知预算可严格保证；实际编辑成本若只按预测均值限制，就不是硬预算。需要严格事件或编辑预算时，用保守上界或明确的逐账户截断机制。

### 5.3 达标可行性检查

对固定模型、固定猜测排名，最多修改全站 B 比例账户，风险最多下降 B 个百分点；未响应会进一步压低可达收益。更紧的上限是可干预且当前已命中账户的质量。

例如初始固定模型风险 40%、最多干预 20% 账户，不能承诺降到 10%。这个上限用于目标预检，不直接用于每轮重训后排名变化的 A1。

### 5.4 动态不一定必然胜过一次排序

若攻击排名固定、每账户响应分布固定、没有群体间约束且不允许重复干预，各账户预期收益可加。此时初始排序可能已经足够，每轮重算未必提供额外收益。

动态反馈的实际价值应来自可验证的状态依赖：热门名单更新、新口令聚集、适应攻击改变风险排序，或基于真实反馈修正响应估计。不能为了展示规则变化强迫轮换，也不能事后改变模拟器制造动态优势。

因此需分别验证“局部干预更有效”和“反馈比一次排序更有效”。即使第二点不成立，第一点仍可能成立。

## 6. 响应模拟应单独实现存量版本

现有 simulate_users 适合注册实验，可复用片段词表、编辑距离和随机数工具，但不直接用其 final 作为存量全站分布。

新模拟器支持：不响应、可预测简单修改、局部多样修改、重新选择。各比例属于情景假设，应保留当前显式补齐行为作为一个对照情景，并加入偏向年份/数字/符号的保守情景。

所选账户有限次尝试后仍未满足要求，保留旧口令并标记未完成。原口令与新口令相同不记成功改密。响应生成只读旧口令、规则、独立参考资源和随机数，不读取攻击排名，更不能反复生成直到攻击器猜不到。

对每次迁移验证：

$$
\sum_p f_{t+1}(p)=\sum_p f_t(p)=N.
$$

同一旧口令的 1,000 名用户可以只选 200 名；这 200 名可以产生多个结果，也可以迁移到已存在口令。其他 800 名不受该动作影响。

## 7. PCFG 与 F/A0/A1 的具体改造

### 7.1 优先复用蒙特卡洛索引，但增加可靠性筛选

当前 query 可直接查询新字符串，无需只在旧口令词表中查缓存。新评估接口统一返回风险、方法、预算、未覆盖比例、低采样支持比例和模型版本。

当前 evaluate_mc 披露低支持与模型未覆盖质量，但不会阻止优化器依赖这些样本获得较低点估计。新控制器应单独检查候选是否主要把账户移入模型不支持区域；这种下降标为证据不足，安排独立攻击器或可核查猜测流复核，不能当成已证实的安全收益。提高采样量只能降低采样误差，不能修复训练模型的支持集缺口。

索引的逐口令区间是单点区间，不自动等于全站风险差的 95% 区间。入围动作需用独立采样或更多样本复核，不根据一次阈值抖动决定大批干预。

保留 core/open_attack.py 的实际候选流评估路径作为小预算校验。附件的 first-rank 实现不应替换当前 MonteCarloIndex 后继续使用同一个实验标识。

### 7.2 A0 不可全站过滤

原实现对每批所有完成注册用户应用同一规则，因此按该批规则过滤有明确条件。新方案只有局部账户受规则约束，且被通知者可能没有成功修改。

新 A0 至少区分：攻击者是否知道被干预对象，以及是否知道其成功完成修改。只有明确已满足约束的账户，才能在该知识假设下用新规则过滤猜测。对未干预和未响应者，不使用局部规则掩码。若攻击者不知道响应状态，不能凭内部真实状态替它选择有利模型。

第一版可主要报告 F 和 A1；A0 作为显式假设的补充实验，不能为了沿用原来的九条曲线而生成语义错误的结果。

### 7.3 A1 不能沿用轮次均分开发数据

现有 _development_response 将开发出现记录按策略数量交错分组，再分别应用规则。这对应注册批次。新模式应维护独立的开发参考群体，根据公开群体筛选器、干预率和相同响应协议模拟局部迁移，然后训练 A1。

若参考群体的组成不同，应报告匹配率和实际干预率；不能将目标集终态口令直接喂给 A1，也不能用各轮均分代替风险群体选择。攻击者可读取哪些公开规则、聚合统计，需在配置中注明。

第一版候选决策复用冻结 PCFG，A1 在终态评价；需要逐轮 A1 时，明确它是事后评估还是在线选择信号。每条方法轨迹均采用相同的 A1 训练与信息条件。

## 8. 新聚集检测应作为辅助防线

每轮记录最大精确口令占比、固定 k 的 Top-k、HHI、主要结构占比，并检查流入已有热门口令的质量，而不只检查新字符串。

不能把“新口令占比不超过初始最大值”视为充分条件：初始最大值很高时，仍可能允许严重聚集。阈值在开发阶段配置，并做有/无约束对照。

所有人追加同一年份可能使精确口令分散，却使规则感知攻击容易命中。因此必须增加独立参考口令上的公开变换攻击或 A1；单看 HHI 无法发现全部可预测结构。

正式轨迹保留偶发反弹。停止可依据目标达到、预算用完、无可行正收益动作、连续停滞或轮数上限，并保存最后一次执行后的终态。

## 9. 分离候选粒度与反馈贡献的实验矩阵

所有方法从同一初始账户状态出发，使用相同基础规则、响应情景、模型知识和成本口径。主要横轴为实际累计受影响比例，纵轴为账户加权猜测风险；同时报告实际修改和编辑成本。

| 对照 | 目的 |
| --- | --- |
| 不干预 | 给出初始风险 |
| 固定 Google / 其他网站规则全量应用 | 保留与历史研究的关联，单列实际成本 |
| 固定 Google 分批，只选不合规账户，匹配覆盖预算 | 排除“只是少改了人”的解释 |
| 固定 Google 分批，按同一风险标准选择不合规账户 | 提供比随机选人更强的固定规则基线 |
| 相同局部规则库、随机选择账户 | 检验风险定位的价值 |
| 相同局部规则库、初始一次规划后执行 | 检验反馈的增益 |
| 相同局部规则库、每轮重算、固定批量 | 检验反馈，避免与规模选择混杂 |
| 完整方案、每轮重算、可选批量 | 检验额外规模选择的作用 |

一次规划对照需要在第 0 轮构造无重复账户的计划，不只冻结规则名称却继续按新分布选人。所有对照到最后一批可截断人数；若因不合规账户不足而未用满预算，报告实际成本，不能强制合规者改密来凑预算。

建议第一轮验证覆盖预算 5%、10%、20%，单轮 0.5%、1%、2%，采用多个配对执行种子和至少两个响应情景。先做一个真实频次数据来源的可信对照，再扩展独立数据集和其他模型。同源不同种子不是独立网站证据。

至少保留一个未参与候选选择的攻击评估条件。若只完成 PCFG，则结论限定为 PCFG 与已执行的规则感知攻击结果，不预先宣称跨模型稳健。

实施顺序：

1. 先做合成手算例与状态迁移：局部抽人、整数计数、失败保留、累计去重、终态保存。
2. 接现有 PCFG 索引：风险指标、未覆盖与低支持披露；统一新旧指标名称。
3. 接三个基础局部规则和独立预测/执行随机流；完成一次贪心与多轮闭环。
4. 完成固定规则分批、随机选人、一次规划三个关键对照，绘制风险—覆盖曲线。
5. 正确实现局部 A1 和规则感知评估；以保守响应情景复核。
6. 再接页面：显示群体、人数、规则、选择原因、预测/实现收益、剩余预算和停止原因。之后才扩展有限前瞻、更多模型及更多数据集。

先不穷举所有动作序列，也不引入强化学习。若一步贪心的局限有证据，再对前三个候选增加深度 2 前瞻并单独比较计算开销。

## 11. 核心验收

- 1,000 账户手算例能得到固定模型风险 0.60 → 0.50 → 0.40、覆盖 0% → 10% → 20%；这只验证账目。
- 未响应者仍在旧口令分布中，通知成本已计入。
- 同一热门口令只迁移选中的人数，非目标账户保持原状态。
- 已干预者迁移后不会被重新当成未干预；群体重叠不会重复计费。
- 所有预测试验相互隔离，不污染执行状态；下一轮只读实现后的状态。
- 新字符串查不到缓存时实际补查询，不直接记为未命中。
- 局部规则不被错误套到未干预/未响应账户的 A0。
- A1 开发训练数据不来自目标集终态；模拟局部筛选与实际比例有记录。
- 所有用户追加共同后缀的反例会被规则感知攻击揭示，不能仅凭熵提升判定成功。
- 固定独立收益案例中，允许动态与一次排序相同；具有状态依赖的案例中检查反馈确实改变后续估值。
- 同规则重复被选中可解释；无正收益正常停止，不通过强制换规则制造“动态”。

## 12. 项目表达建议

推荐描述为：“基于口令分布反馈的预算约束选择性干预：联合选择干预群体、局部规则与规模，在控制模拟账户扰动的条件下优化给定攻击预算下的猜测风险。”

待验证的贡献分别是局部候选、成本约束、反馈收益和对新聚集的稳健性；闭环本身不直接宣称为首次提出。附件关于 HTPG 原论文的具体页码与结论仍应在正式论文写作时对照原文核验。

真实平台通常不能从带盐哈希恢复当前精确明文分布。第一版明确为授权数据上的离线研究；线上扩展需另定义注册/改密时可获得的风险标签与聚合统计，不能声称直接读取哈希库即可运行本方案。
