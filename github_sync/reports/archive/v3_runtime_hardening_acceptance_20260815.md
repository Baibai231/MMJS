# v3 服务器运行时保守加固验收（2026-08-15）

## 结论

- 本轮保持 `misc/measure_version.txt = v3`，没有修改分类器规则，也没有把候选轮次覆盖到
  `reports/sites/sites_latest.jsonl`。
- 正式权威数据在验收前后哈希相同：302 条、151 站、302 个唯一
  `(hostname, entry_kind)`、全部 v3、0 error。
- 运行时加固通过单元、并发、故障、真实 HTTP 与两轮全量回归；正式 v3 继续保留，
  原因是无头候选虽提高部分覆盖率，但注册侧正确率从 80.0% 降至 78.8%，且本轮没有
  分类器变更，不能把动态页面波动冒充识别优化。

## 已复现并修复的运行时问题

1. 并发写同一网站登录/注册时，JSONL 已有双侧结果，但 SQLite 可能只留一侧，另一请求
   报 `UNIQUE constraint failed`。网页写入、审核、同步和建库现共用跨进程锁。
2. 六小时同步原先可能与网页写入、待审核提交或 SQLite 原子替换交叉；现完整临界区串行，
   Git push 前释放数据锁，并另有同步任务互斥锁。
3. Git 基线读取失败原先会被当作空基线，可能全量误回放；现安全中止并保留工作树。
4. 旧 SQLite 无法读取时原先会静默丢弃仅存其中的待审核记录；现取消重建并保留旧库。
5. `api/export` 原先从 SQLite 反向拼记录并把历史版本排在当前版本后，Mac 合并时可能
   旧版本覆盖当前；现一致性锁内原样导出两份权威文件。
6. 手动全量重测原先直接清空正式 JSONL，并会抹掉固定清单外的网页新增站；现先写临时
   完整结果，成功后在锁内按键合并、生成报告并建库，macOS/Linux 均可用。
7. 提交已成功但建库/重启失败时，下一轮原先可能因 HEAD 不再变化而永久跳过部署；现用
   本机部署标记和 `/api/stats` 健康检查决定是否重试。
8. 公网实时分类限制并发 Chrome、拒绝内网/本机/保留地址与非标准网页端口；匿名只可查
   单站待审核数量，完整人工内容需管理员口令；网页写入模型固定为 v3。
9. 命令行审核不再把 feedback 写成人工结论，并保留结构化双侧字段；离线人工审计将
   一致、不一致、证据不足分别统计和完整列出。

## 正式数据保留决策

| 数据 | 登录正确率 / 覆盖率 | 注册正确率 / 覆盖率 |
|---|---:|---:|
| 当前正式 v3 | 72.7% / 66.3% | 80.0% / 60.2% |
| 本轮审计候选 | 72.9% / 71.1% | 78.8% / 62.7% |

候选使部分 unknown 取得现场证据，但也新增注册侧明确不一致；本轮目标是服务器运行时加固，
没有分类算法改动。因此保守结论是：保留现有正式 v3，不用这次动态回归刷新正式站点判断。
这同时证明新运行时代码没有破坏测量程序，并避免把一次无头环境波动写进长期报告。
