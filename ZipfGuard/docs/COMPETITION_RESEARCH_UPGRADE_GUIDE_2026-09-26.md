## 1. 总体定位：作品最终要回答什么

推荐的问题表述是：

> 在 HTPG 的分布驱动口令策略场景下，如何更可靠地识别有限攻击预算下的高风险部分，并用多种攻击模型、明确成本和跨站验证，判断固定修改机制是否真正降低风险？

这使你们的五个重点方向形成完整链路：分布描述人们怎样选口令，拟合估计规律，分析判断规律是否对应风险，攻击提供实测压力，评价判断优化是否成立。固定修改建议层负责把上游判断转为可检验的应用结果。

作品使用离线研究数据与受控模型评测。真实数据研究只导出必要的聚合统计；演示使用明确标注的合成样本或已脱敏结果。当前 19 站范围不含足够的用户 PII 或密码复用关联证据，因此优先研究 trawling 场景，不把 PassLLM 的 PII/reuse 分支强行纳入。

## 3. 文献已经做过什么：先排除“看起来新”的旧工作

### 3.1 HTPG 是应用场景基线

HTPG 将分布划为头尾，并基于特征和信息增益率生成策略。你们可研究它的风险识别是否受规模、拟合和攻击模型影响，但当前实现偏差必须单独记录，不能把修复原算法错误产生的收益记为新方法收益。[HTPG，IEEE TIFS 2022](https://ieeexplore.ieee.org/abstract/document/9715109)

### 3.2 替换成 stretched-exponential 不足以单独证明新颖性

Hou 与 Wang 的工作已经研究口令分布拟合优度、样本规模影响，并比较替代分布，包含 stretched-exponential。因此你们若采用它，应视为有依据的候选或强基线；进一步贡献要落在实际风险估计、模型选择规则、稳定性或决策收益上。[New Observations on Zipf’s Law in Passwords，作者公开版，TIFS 18](https://wangdingg.weebly.com/uploads/2/0/3/6/20366987/tifs22-n2-final.pdf)

通用幂律分析文献也提醒：对数图接近直线和最小二乘拟合不足以证明幂律成立。但该文针对的随机变量及抽样假设不一定等于“排序后的口令频次”，不能直接搬用 KS/似然检验而不核对统计模型。[Clauset、Shalizi、Newman，SIAM Review 2009](https://arxiv.org/abs/0706.1062)

### 3.3 统一评测和简单多模型并集已有直接相关工作

MAYA 已提出统一评测，并讨论不同模型学习到不同分布以及组合收益。因此，“我们接入五个模型，组合比单个强”不能直接当作原创主张。应进一步核对其组合成本、训练信息和场景，再提出明确超出它的条件或方法。[MAYA 原文入口及作者仓库](https://arxiv.org/abs/2504.16651)，[作者实现](https://github.com/williamcorrias/MAYA-Password-Benchmarking)

本项目的“19 个本地数据集”不能直接改写为“MAYA 论文实验用了 19 个”。仓库资源范围与某篇论文的实际实验集合应分开核对。

### 3.4 PassGPT、PassLLM 是强压力测试，不是接入即创新

PassGPT 提供生成式口令建模及受约束生成思路；本项目可以用它检验分布和策略结论是否依赖传统模型。[PassGPT 作者预印本](https://arxiv.org/abs/2306.01545)

PassLLM 包含不同信息条件和生成技术。当前蒸馏随机采样路径不覆盖整篇工作；只引用它，也不能证明本项目的方法对全部分支有效。[PassLLM，USENIX Security 2025](https://www.usenix.org/conference/usenixsecurity25/presentation/zou-yunkai)

有序生成与随机采样的差异也已有相关研究，评价路线需将其纳入查新，而非把“排序提高效率”直接称为首次发现。[Search-based Ordered Password Generation，作者预印本](https://arxiv.org/abs/2403.09954)

### 3.5 多攻击器、迁移与偏差是既有研究问题

口令可猜测性建模的准确性与偏差已有系统研究；跨域、训练选择和攻击器能力应属于你们实验设计的一部分。[Ur 等，USENIX Security 2015](https://www.usenix.org/conference/usenixsecurity15/technical-sessions/presentation/ur)

动态字典等工作进一步说明固定攻击器可能不能代表真实对手。对修改后口令只测一个不适应的模型，容易得到过于乐观的结果。[Pasquini 等，USENIX Security 2021](https://www.usenix.org/conference/usenixsecurity21/presentation/pasquini)

以上来源支持问题和基线选择，**不证明下文候选方向首次提出或一定有效**。正式选择路线前，agent 还应检索近邻方法，填写“已有工作—差别—验证办法”矩阵。

## 4. 最终质量标准：怎样才配得上“论文水平”

| 问题 | 最低应给出的证据 | 不够的替代品 |
| --- | --- | --- |
| 问题是否真实存在 | 数学分析或跨站诊断，量化发生条件 | 一张图、单个异常例子 |
| 方法是否有明确内容 | 输入、输出、目标、约束、选择规则和复杂度 | 模块改名、笼统“融合 AI” |
| 与已有方法差在哪里 | 原文逐项对照、强基线、消融 | 只对照原 HTPG 一个实现 |
| 优势是否公平 | 相同允许信息、明确成本、匹配训练条件 | 每个模型都花 B 再说并集也只花 B |
| 结论是否稳健 | 留出站点/数据、多种子、配对差异、区间和失败站点 | 一个 seed 的百分比提升 |
| 优势来自哪里 | 去掉关键设计的消融和分层误差分析 | 所有模块一次性改变 |
| 能否用于原场景 | 固定修改层，修改前后及适应性评估 | 只有分布拟合误差下降 |
| 能否被复查 | 数据/模型/代码身份、命令、日志、自动主表 | 截图和手填 Excel |
| 竞赛是否能展示 | 实际系统输出与研究证据连接 | 只有离线脚本或只有漂亮页面 |

没有通用的“提升 5% 就能发论文”门槛。应在确认实验前定义对本场景有意义的最小改善及成本约束；统计显著不等于有用，小样本不显著也不自动证明无效。最终可以是算法改进、可信的测量发现或有深度的系统研究，但必须准确说明属于哪一种。

## 6. 路线 A：风险约束的稳定头尾切分

### 6.1 问题与当前差距

现有曲率切分取决于频数坐标。对连续模型 f(r)=C r^(-α)，当前代码的峰值满足：

\[
r_* = \left[C^2\alpha^2\frac{2\alpha+1}{\alpha+2}\right]^{1/(2\alpha+2)}.
\]

因此固定 α、固定拟合支持域时，将所有频数乘 k，有 r_*(kC)=k^(1/(α+1))r_*(C)。经验概率没有改变，连续切分位置却会改变。**这是由当前公式直接得到的分析，不是对所有实际重拟合的无条件结论**：frequency>3 过滤、估计 α 变化、取整、并列名次和边界裁剪都需另做实验。

这给出真实研究问题：当数据量变化而选择规律近似不变时，策略覆盖对象是否应大幅变化？但简单换成累计质量 q 只能解决一部分尺度问题，且目前 q=0.5 的探索并不更稳定。不能将其直接命名为新方法。

### 6.2 可实现的候选方法

先将候选定义为训练侧可计算的风险区域规则 Hθ。最小候选是训练频次排序下的累计质量阈值；另保留固定头部数量/比例、概率阈值以及原曲率。规则在测试时只能使用训练阶段固定的信息，不能重新用测试频次排序选头部。

在验证集上，对预先声明的攻击器与预算，评价 Hθ 捕获了多少已命中 occurrence，以及它覆盖了多少 occurrence/不同字符串。可以探索“在最差攻击器风险召回达到目标的约束下，尽量减小需干预的质量或比例”，也可以使用固定干预率比较风险召回。两者先选一个作为主协议，不能事后挑有利的方式。

这里的“最差攻击器”仅指预先选定且运行完成的有限模型集合，不代表对所有可能攻击者的安全保证。若某模型该预算无命中，召回分母为 0，应记不可定义并另报数量，不可填为完美召回。

### 6.4 何时继续，何时停止

继续条件：在验证阶段，至少显示稳定性或风险捕获有清楚改善，同时其他重要指标没有不可接受退化。最终成立需留出确认，而非每站测试上挑一个最佳阈值。

停止/调整条件：只在放大头部集合时变好；优势被固定头部比例基线解释；跨模型风险召回明显退化；对未见字符串始终失效；或者接入修改层后改善消失。此时保留尺度诊断发现，不能把阈值选择包装为已证实算法优势。

竞赛展示：同一经验分布的不同规模副本下，显示原规则和候选规则的边界、干预量与实测风险。必须同时给出真实下采样和留出结果，避免只用最有利的合成图。

## 7. 路线 B：面向风险的拟合与模型选择

### 7.1 核心研究问题

全局 CDF 更接近经验分布，不保证有限预算下最容易被猜中的区域估计更准。模型可能把大量精力用于尾部，却没有改善策略关心的高风险区域。这是待验证的问题，不是已经观测到的结论。

应将“分布拟合质量”“风险预测质量”“最终策略质量”分别度量，再检查三者关系。Zipf、CDF-Zipf 和 stretched-exponential 都作为有出处的候选，而非本项目原创模型。[分布比较依据](https://wangdingg.weebly.com/uploads/2/0/3/6/20366987/tifs22-n2-final.pdf)

### 7.2 实施路线

1. 明确定义被拟合对象：口令字符串的概率、固定训练排名上的质量，还是频次直方图；不能在几种对象之间混用似然。
2. 在训练数据固定支持与排序，验证/测试投影到该支持。未见字符串单列质量，或使用有依据的平滑/外部支持模型，不能把测试排序后的曲线当部署预测。
3. 重现原 OLS 基线，并实现同支持域的候选。若 CDF 拟合仅为曲线损失，不能伪称完整生成概率模型；BIC 只在可比较的似然与样本定义下使用。
4. 先比较全局、头部、尾部误差；再预测选定预算下的风险或头部召回。将“预算 B 等于排名 B”限制于相应排名基线，不能套给所有生成攻击器。
5. 候选选择可探索头部质量加权误差或验证风险损失，但权重必须在开发/验证阶段固定，并与不使用风险标签的拟合选择对照。
6. 做跨站留出，检验更好的拟合是否带来风险预测和策略决策改善；同时报告成本和参数不确定性。

| 必需对照 | 为何需要 |
| --- | --- |
| 经验频次/累计质量 | 排除“复杂模型不如直接统计”的情况 |
| 原 HTPG OLS | 连接原场景 |
| 常规似然/全局误差选择 | 检验风险相关目标是否提供额外价值 |
| 简单长度/频次集中度 | 排除收益只是几个基础统计量解释 |
| 不同尾部处理 | 检验未见质量与平滑假设是否支配结果 |

最终交付应含模型定义、可扩展实现、留出误差、风险预测、决策收益和失败域。只做出“某模型 R² 更高”不够支撑该方向为主创新。若拟合选择对最终风险没有增益，可以将模型比较作为支撑分析，避免继续堆复杂模型。

## 8. 路线 C：考虑重叠和迁移的固定成本模型配额

### 8.1 当前没有实现的是什么

目前已经正确跑通等额配额，但等额配额不是分布驱动优化。多模型本身也不是新贡献，MAYA 已有相关组合研究。需要提出并验证一个具体选择问题：在固定原始生成预算或固定实测成本下，怎样分配多个模型的份额，让联合覆盖优于有竞争力的单模型与简单配额。

### 8.2 数学对象与信息边界

设模型 m 的原始前 b 条输出集合为 Gm(b)，并集验证只计算一次相同候选；原始生成费用仍按各模型实际前缀计入。可在验证集上研究：

\[
\max_{b_1,\ldots,b_M}\ \widehat{\mathrm{Coverage}}_V\left(\bigcup_m G_m(b_m)\right),
\quad \sum_m b_m\le B.
\]

这是预算约束优化的定义，不是新算法证明。若用耗时约束，应改为实测成本函数 cm(bm)，同时报告硬件和候选池准备费用，不能假定不同模型每条生成成本相同。

局部验证场景可以使用审计方允许的本地训练/验证数据；纯跨站攻击场景不能读取秘密目标数据的频次作为选择特征。必须在协议中分别声明，否则“分布感知”会通过额外目标信息获得不公平优势。

### 8.3 从简单到复杂的 agent 步骤

| 步骤 | 实施内容 | 验收关注 |
| --- | --- | --- |
| C-1 | 用既有模型在开发站点生成固定块大小的前缀，记录原始成本、唯一数和验证命中集合 | 每块成本包含重复和无效输出；无测试反馈 |
| C-2 | 建立强基线：最佳验证单模型、等额、按验证独立收益分配、考虑并集增量的简单贪心 | 不只战胜等额这个弱基线 |
| C-3 | 在小网格枚举可行配额，作为验证侧搜索基准 | 搜索本身使用的计算/数据成本另报；测试 oracle 仅作不可部署上界 |
| C-4 | 评估长度、集中度、未见比例、拟合参数等少量特征对最佳配额的解释 | 19 站不是海量独立元样本，先用低复杂度模型 |
| C-5 | 采用外层留站、内层选参预测配额；留出站点不得参与元模型选择 | 有无目标验证样本的场景分别报告 |
| C-6 | 做移除分布特征、移除重叠修正、去掉神经模型等消融 | 证明收益具体来自哪个设计 |
| C-7 | 检查不同 B 和耗时约束下能否保持收益 | 原始次数、公平验证数、实际计算成本不混称 |

不能直接宣称贪心有 1−1/e 保证：固定候选集合的覆盖性质不自动覆盖模型前缀依赖、搜索成本和跨块约束。若需要理论保证，先证明当前问题满足所用定理前提。

继续条件：在留出数据上优于验证最佳单模型或提供明确成本收益，并且分布特征对简单验证分配确有增量。停止条件：优势仅来自额外总预算、看到测试反馈、公开模型训练暴露、某一站异常或元模型过拟合。若只证明模型互补，可保留为评测结果，不宣称分布驱动创新成立。

竞赛展示：固定总预算滑块，展示各模型成本、重复重叠、独有覆盖以及组合结果；未知预算不插值伪装实测。算法推理可现场运行，耗时长的攻击使用可核验的离线记录并标明。

## 9. 路线 D：成本口径改变安全结论的测量研究

### 9.1 为什么值得做，怎样避免只是在修 bug

原始生成次数、有效输出、唯一候选和排序后验证次数反映不同成本。随机采样和有序枚举的重复率、准备开销不同，若只显示一条 Cracked@B 曲线，比较可能偏向某类方法。

可研究的问题是：在明确的实验范围内，模型排名或 HTPG 改善结论是否会随合理成本口径改变？原因是什么？已有可猜测性偏差研究和有序生成工作构成必须比较的近邻文献。[评价偏差](https://www.usenix.org/conference/usenixsecurity15/technical-sessions/presentation/ur)，[有序生成](https://arxiv.org/abs/2403.09954)

### 9.2 具体步骤

1. 修复并冻结三轴与候选池账本，列出适用语义；一个 run 同时导出多个视角，避免每种口径使用不同随机样本。
2. 对五类现有路径记录生成、排序、去重、验证和训练成本。PassLLM 当前只返回排序池时，不推断不存在的原始逐条命中位置。
3. 定义模型两两排序一致率、排名翻转发生条件、覆盖—时间前沿；预先设定主要对照，不能从大量预算里挑翻转例子。
4. 做重复率、无效输出率、支持域和训练暴露分层，分析翻转是否由这些因素解释。
5. 在相同修改策略上重算原始/修改后差异，确认口径会否改变“策略有效”的判断。
6. 输出操作性评价协议：什么问题使用哪根轴，什么图必须报告准备成本，哪些结果不可比较。

必要边界：单次离线明文成员检查耗时不等于真实密码哈希验证耗时；若将成本换算为部署风险，需要明确 KDF、硬件和测量条件。未测量时只报告生成与离线评测成本，不能换算“需要多少年破解”。

能成为主贡献的条件是存在跨站、可解释、可复现的系统性测量发现，并且相较已有研究提供具体新增见解。只有“我们现在记录重复了”属于工程成果。若观察不到显著翻转，仍保留统一计量作为全项目基础，不强行扩写结论。

## 10. 路线 E：跨站、跨模型的风险解释

### 10.1 从 IGR 排名走向什么

IGR 可以说明特征与头尾标签的关联，但头尾本身来自频次切分。高 IGR 并不直接说明该特征决定攻击成功，更不证明修改该特征会使口令更安全。

研究目标应是：在控制频次、长度、训练是否出现和字符域之后，某些结构特征是否仍能解释被哪类模型先猜中；这种关系能否跨站保持。它为主算法提供可信解释，而不要求单独造一个复杂模型。

### 10.2 实施步骤

| 步骤 | 内容 | 防止的误判 |
| --- | --- | --- |
| E-1 | 在同一 split 上生成多个预算的命中标签和首命中位置 | 不同数据批次无法比较 |
| E-2 | 未命中记录为预算右删失；若用预算二分类，明确只代表该预算 | 不把未命中当永远安全或指定巨大精确名次 |
| E-3 | 简单长度/频次/训练可见性作为基线，再加入固定结构特征 | 防止把频次效应写成特征机制 |
| E-4 | 用分层统计或低复杂度模型分析，必要时按站点分层 | 防止站点、语言、训练条件混杂 |
| E-5 | 对词表、语种、特征定义做敏感性分析 | 英语词表未匹配不等于没有词汇结构 |
| E-6 | 留站检验解释稳定性，并连接 A 的风险区域 | 防止只在训练站点解释得很好 |

交付：可复核的聚合风险表、特征定义、区间、跨站变化及反例。对模拟修改的分析只解释模拟机制，不自动扩展为真实用户行为的因果结论。

若特征结果被长度/频次完全解释，就报告这一限制，并缩小解释模块。不要把 SHAP 图或一张相关性热图本身当研究贡献。

## 11. 路线 F：固定修改层在适应性对手下的收益边界

这是最终必须有的应用验证；如果发现原场景的某种收益只在受限对手下存在，它也可能成为有价值的测量结论。动态字典等相关工作意味着对手适应能力不能被忽略，但需要按你们实际数据条件定义，而非任意增强攻击者。[相关研究](https://www.usenix.org/conference/usenixsecurity21/presentation/pasquini)

### 11.1 必须分开的场景

| 场景 | 模型允许看到什么 | 验证什么 |
| --- | --- | --- |
| original + frozen | 原训练数据 | 原始风险基线 |
| modified + frozen | 仍只用原训练数据，保持攻击配置 | 固定攻击器下修改效果 |
| modified + adaptive | 仅允许的独立修改训练数据、公开策略或协议声明的信息 | 对手适应后收益是否保留 |
| 跨站迁移 | 预先声明的源站和公开信息 | 策略是否依赖同站训练环境 |

adaptive 不能偷偷获得测试目标、逐条命中反馈或测试频次。用户响应模拟的训练与测试也要分离。每种攻击者知识条件在实验前固定，并与原论文设定逐项对照。

### 11.2 agent 实施步骤

1. 冻结 paper-compatible 原 HTPG 规则，原文未定义的响应细节单列为项目模拟假设；修复原实现和研究优化分开。
2. 原方法和新方法使用相同的修改执行器、可用操作、随机种子约定和次数约束。
3. 比较自然干预规模和匹配干预规模两种视角；匹配方式不能由测试命中反向选择。
4. 记录修改比例、编辑量、长度变化、碰撞/合并等代理成本，禁止称为用户记忆率或满意度。
5. 分别训练或准备冻结/适应性攻击器，核对允许信息；在同预算及成本说明下评价。
6. 做配对安全差异及成本分析，对无收益、收益反转和不适用数据如实报告。

最终作品要回答“什么时候有效、对谁有效、代价是什么”。如果只在 frozen 下有效，应限定结论，不写普遍安全提升。比赛中无需为了补可用性数字临时开展缺乏合适设计的用户调查；没有真实用户证据就清楚使用代理成本。

## 12. 共同实验协议：六条路线共享的底座

### 12.1 数据与独立性

全部 19 站都要有身份和资格记录，不等于强行对所有站计算所有指标。LinkedIn/Ashley Madison 等语义不明对象可以保留描述性分析，并对 occurrence/account 指标限制；范围缩减必须解释，不能只删表现差站点。

occurrence 划分回答记录层面的泛化，可以存在同字符串跨集；unique-disjoint 回答新字符串条件下的能力，分布和难度本来不同，两者分别呈现。跨站同字符串重叠与同一用户重叠也是不同问题，不能凭口令重叠推断用户身份。

hak5、Twitter 已多轮用于开发，不宜再作为唯一独立确认依据。可以使用尚未参与选方法的站点和明确隔离的数据作为确认；如果全部站点都已用于调参，就承认探索性质，并重新设计更有限但诚实的外部/后续验证。

### 12.2 模型与预算

首层基准为频次、PCFG、OMEN、PassGPT、PassLLM 当前可核验路径。PassLLM 作者搜索路径是需补任务，FLA/PassGAN/PassFlow 为条件扩展。无需因缺一个可选模型暂停全部研究，也不能把模型缺失填成零。

预算先用 10³ smoke 测通，再在开发阶段测 10⁴、10⁵ 的资源与趋势，决定正式梯度和主预算；10⁶ 以上依据硬件与目标另定。预算建议是执行规划，不是论文标准。若所有方法在所选预算几乎全零，扩大合理预算或调整可回答的问题，不靠微小相对百分比制造效果。

多 seed 同时覆盖数据划分随机性与随机生成，二者分别记录。建议先以少量开发种子估计方差和资源，再冻结确认次数；不能声称三个或五个 seed 自动足够。

### 12.3 统计与消融

主结论报告绝对命中差、对应分母、预算和成本，再给相对变化；基线为零时不造相对提升。站点宏平均与记录加权平均分开，避免 RockYou 等大站掩盖其他域。

相同数据和 seed 的方法比较采用配对分析。重采样单位应尊重重复口令、同站和同 run 的依赖；用户身份不可用时不能声称用户级独立置信区间。探索多个阈值、模型和预算需要限制主假设或处理多重比较。

置信区间用于量化不确定性。若使用 95% 区间等常见选择，写入协议；区间跨零不表示两法等价，区间不跨零也不证明效果在实际场景足够大。

必须至少能回答：没有分布信息会怎样？没有风险选择会怎样？换攻击器会怎样？匹配干预量后怎样？对手适应后怎样？这些分别是消融和稳健性问题，不应混成一张只有最佳结果的主表。

## 14. 最终竞赛作品应长什么样

推荐以“可解释的口令策略风险评估与优化原型”组织展示，是否使用此名称由团队决定。界面分四个自然步骤：选择研究数据/合成示例，查看分布与风险，比较多模型评估，查看固定策略的修改前后证据。

界面不需要暴露内部 run_id 和 hash 作为主流程，但研究报告应能追溯它们。普通视图解释预算、覆盖域和结果边界；专家视图提供来源、配置、运行日志和失败单元。重实验允许离线预计算，页面必须区分预计算结果与现场运行，不能把进度动画伪装成真实攻击。

| 演示环节 | 想让评委理解的事情 | 最好展示的证据 |
| --- | --- | --- |
| 数据与范围 | 19 站不是 19 个同质账户库 | 当前/历史/语义受限标记 |
