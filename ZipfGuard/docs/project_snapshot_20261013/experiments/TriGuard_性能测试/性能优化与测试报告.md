# TriGuard 工程优化与快速性能测试

本次修改真实工具的计算与持久化实现，随后进行优化前后的配对测试。按用户要求提前停止扩展规模，图表只使用已完成的数据。

## 工程优化

- 秘密口令比较采用无碰撞分块编码，同一对口令的频次比较结果复用；结构内热门项仅秘密选取前3名，避免全量排序。
- 字符类型与连续序列判断复用中间结果；私密规则检查按当前策略所需特征计算。
- 登录、检查省去整份站点状态的复制和无变化写回。认证输入的分块比较覆盖全部字节值，避免非ASCII进位混淆。
- 大型数据库记录采用带版本标识的无损压缩，兼容旧JSON格式，不删除份额、预算、回执或恢复信息。

## 时间开销

时间图左侧：10个普通账户、3次不同快照的新统计发布，均经过真实三方协议、TLS、签名与业务完成接口；每次隐私预算为0.5，保留全部18项规则人数统计。每账户使用完整64字符填充份额，不使用客户端预聚合直方图。

统计发布时间中位数由117.981秒降至57.734秒，本次测量降低51.1%。

时间图右侧：100个账户，登录、私密规则检查和改密各进行5次预热后的测量。计时覆盖版本读取、请求签发、份额生成与提交、结果轮询、回执核验及业务完成。

| 操作 | 优化前中位数 / 秒 | 优化后中位数 / 秒 |
| --- | ---: | ---: |
| 登录 | 1.160 | 0.927 |
| 私密检查 | 1.995 | 1.761 |
| 改密 | 2.223 | 1.928 |

## 存储开销

在10、25、50、100、200、500、1,000、5,000个账户上，将完全相同的普通逐账户秘密份额分别写入优化前后的实际SQLite实现，并逐项读回核对。测量业务数据库和三个计算方数据库的物理页总量；配置、证书、程序、运行日志及审计历史不计入这条账户规模曲线。

5,000账户的数据库总量由25.898 MiB降至14.645 MiB，本次测量降低43.5%。

## 验证与边界

- 真实三方协议通过41项核验，覆盖18类规则的接受/拒绝、空账户集、重复与同频口令及恶意字节比较；15项存储、预算、签名和恢复回归检查通过。
- 正式计时使用本机回环网络上的三个独立进程，属于小样本工程实测，不代表跨网络或高并发性能。
- 25账户原版统计遇到HTTP读取超时；优化版完成了一次108.412秒的新发布。该规模未完成配对重复测量，不纳入主时间图。
- 时间图没有5,000账户的全量统计结果。全量统计仍有两两秘密比较开销，不能用存储曲线或100账户交互结果推断大规模统计性能。
- 预热、未完成操作、缓存统计读取和早期优化试验均未混入主时间图。
