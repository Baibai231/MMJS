# ZipfGuard 统一实验实施方案：真实口令、开放候选与 Min_auto

版本：v2.1，2026-09-26。状态：P0—P7 主流程已迁移并通过小规模真实数据及双界面验收；P8 正式规模效果实验待执行。本文件替代 2026-09-24 版“多类合成主线加真实静态验证”的实施顺序。

研究定义以 [论文主方案](../DP_HTPG_AI_竞赛详细方案.md) 为准。实际 API、运行边界和文件映射见 [开放协议说明](OPEN_PROTOCOL.md)。本文件规定模块契约、改动顺序和验收要求，不把待实现事项描述为已完成。

## 1. 总体迁移原则

主数据改为真实口令及出现频次；攻击器取消公共候选允许列表；风险由逐口令 Min_auto 聚合；推荐目标改为自适应风险与用户负担的约束优化。分布、响应、攻击、搜索必须一起对齐，不能将新指标套在旧闭集结果上。

| 旧设计 | 新设计 | 必须一起改动 |
|---|---|---|
| 合成 576 项承担主结论 | 真实带频次语料承担主实验 | 输入解析、加权划分、响应和报告来源 |
| 扩大固定公共候选空间 | 独立开放候选流，无共同交集 | 攻击接口、n-gram 生成、PCFG 流处理 |
| 原始输出预算作为主指标 | 策略过滤和去重后的不同校验候选为主预算 | 统一计费器及原始/计费双序号 |
| 整体最强单模型风险 | 每个口令取最小猜测位置后聚合 | M2/M3/M4、报告和置信区间 |
| 合成确定修补与短语回退 | R0 真实分布重新选择；R1/R2 路径敏感性 | 完成状态、成本分母和攻击者知识 |
| 手设宽松成本阈值保证产出 | 按安全需求/成本上限选 Pareto 策略 | 常见规则前沿、不可行状态、测试冻结 |

R0 是默认解析基准；新主指标不沿用旧“原始输出次数”或“最坏单模型”的名称和数字。旧流程标记 legacy_closed，继续用于历史复现和小型正确性测试。

## 2. M0：真实数据与加权划分

### 2.1 读取接口

新增显式 source_format：raw_occurrences、password_with_count、unique_dictionary。frequency_interpretation 作为来源语义另存，不能只改标签而不改变解析逻辑。

当前 core/rockyou.py 将整行作为字符串，不能直接正确载入“计数加口令”的文件。新入口需要保留口令字段字节/编码语义、有效空格与大小写，识别重复行，保存解析失败、排除质量及完整文件哈希。数据核心提供字符串与权重，聚合导出器只输出统计。

已新增通用加权数据结构：splits 保存每个划分的字符串与次数映射，metadata 保存来源语义，split_hashes 保存内容校验；避免让真实数据通过 validate_synthetic_dataset。password 只在本地核心和受控中间文件内流转。

只有频次时按出现次数做种子固定的划分，使每个原始计数的 train、tuning、validation、test 之和守恒。攻击器只能读取本划分 train 的频次；不得使用原文件全局行序当字典排序。抽样覆盖完整文件范围，不按排序文件截取前 N 行充当随机样本。

### 2.2 已有数据证据

[frequency_data_precheck.json](frequency_data_precheck.json) 是 2026-09-24 保存的全文件频次字段预检：14,344,391 行，频次和 32,603,388。本轮另完成严格解码与控制字符校验：排除 10 行、349 次出现后，保留 32,603,039 次有效出现。样本内同字符串已合并；全文件重复行审计与来源真实性核验仍未完成。

主样本规模在开发数据资源预实验后确定。计算上使用权重，不能把多次抽样包装成多份独立真实数据，也不能根据最终 test 命中率调整抽样方案。

### 2.3 验收

- 微型计数文件与手算权重一致；同一口令多行正确合并。
- 含空格、大小写、异常编码的条目遵循显式规则，不默默合并。
- 划分频次守恒，同一随机种子结果相同；训练频次不含验证/测试分配的出现次数。
- 去重字典不能被输出为“已知真实用户频次”。
- 修改 test 内容不改变训练产物、候选规则和生成流。

## 3. M1：分布、特征与候选策略

保留三类分布模型，但将输出定位为真实语料的集中程度与规则发现依据。频次排名 CDF 不作为攻击器命中率，拟合好坏不直接决定哪个策略安全。

新增训练侧加权特征统计、支持度及风险方向。若使用猜测命中标签做特征发现，在 train 内交叉拟合攻击器；最终 validation/test 不参加标签学习。特征评分只生成候选，不能跳过响应与自适应评价直接形成最终规则。

候选库包含预注册常见规则和训练派生规则；每个派生规则记录 source_split、特征、阈值、支持质量及产生方法。常见/泄露阻断表只能来自独立资源或 train，严禁使用整个被测文件。

验收应包括规则可解释性、测试独立性，以及“去掉分布引导但维持相同候选/计算预算”的消融。若 M1 只画图而不影响候选，报告中不能称已完成分布驱动推荐。

## 4. 开放攻击接口与统一计费

### 4.1 新接口

旧 fit_select_rank(train, validation, candidates) 保留为 legacy_closed。新协议分离训练、调参、生成和评价：

~~~python
fit(train_counts, training_config) -> ModelArtifact
select(model_configs, tuning_split, protocol) -> FrozenAttackConfig
generate(model, knowledge, limits, seed) -> Iterator[CandidateEvent]
evaluate(stream, target_weights, protocol) -> AttackResult
~~~

以上是职责分解的概念契约；当前实际 API 为 select_ngram、各 stream/generate 方法、consume、evaluate_runs 和 AttackEngine.attack，见 OPEN_PROTOCOL.md。生成器不接收 target_weights、test 或公共候选清单；评价器持有目标但不反馈命中来调整生成。

频次攻击生成 train 中的不同字符串；字典规则使用约定数据来源及通用变形。字符 n-gram 必须实现明确的生成/搜索算法，不能继续只给目标清单打分。PCFG 保留上游原始流，取消按实验空间成员资格筛选；第三方源码和版本继续保持隔离固定。

若使用概率阈值模拟猜测位置，必须验证数值与同协议枚举的一致性，说明近似误差。仅有目标概率、beam 内部位置或未经说明的近似排名，不能填成精确猜测次数。

### 4.2 CandidateEvent 与 AttackResult

当前 GuessRun 在内存保存已计费候选及首次原始/计费位置，过滤与重复事件保存总计数；不持久化全部明文事件日志。计费执行器的顺序固定为：合法事件解析 → 当前知识允许的公开策略过滤 → 模型内去重 → 计费 → 目标匹配。

主 budget_unit 为 unique_policy_eligible_checks。F 不知道新策略，不能过滤新策略；A0/A1 知道策略，可以过滤。raw_generated_count、policy_filtered_count、duplicate_count、charged_count 与运行开销分别记录；候选流与计数可按配置重放核查，工具日志不伪装为候选。

示意验收序列：

| 输入 | 条件 | 目标计费位置 |
|---|---|---:|
| A、B、目标 | 都合规，A/B 不在目标语料 | 3 |
| A、A、目标 | 都合规，重复候选统一去重 | 2；原始位置另记 3 |
| 不合规、目标 | A1 知道该策略 | 1；原始位置另记 2 |
| 不合规、目标 | F 不知道新策略 | 2 |

主协议与原始输出计数分别报告；当前不单独输出按原始序号计算的第二条风险曲线。生成器内部搜索开销和后处理耗时不因过滤免费而消失；二者均列在资源表。

### 4.3 模型运行状态

AttackResult 至少保存协议、模型/训练/策略/知识版本、first_hit_ranks、各计数器、耗时、停止原因、requested_budget、completed_budget 和 exhausted 标记。没有命中时保留 censored 状态，不向外导出伪造的精确无穷次数。

停止原因区分 reached_budget、exhausted、timeout、raw_limit、memory_limit、expansion_limit；运行错误由单独失败记录处理。只有确定自然耗尽可以延伸为该固定算法的风险平台。因资源上限中断时，其后预算为未完成。

关键模型失败不得给策略记零风险。若可选模型移除，统一模型集合后重做整个比较；保存原失败记录，不把缩小威胁集合的结果伪装成完整模型实验。

## 5. Min_auto 聚合与不确定性

对相同策略、响应情景、知识条件和测试分布，各模型的首次命中位置按口令取最小值，再按出现权重计算命中比例。聚合输入必须具有同一 protocol_id 和 budget_unit；拒绝混入 legacy_closed 或不一致计数结果。

例：A 在前 K 次命中 20 个用户，B 命中 25 个，交集 10 个，则 Min_auto@K 为 35/100；不能实现成 max(20,25)/100。

在 K 处，若有模型已命中，联合命中确定；若无模型命中且有模型尚未完成 K，结果未知。当前记录 hits、unresolved_weight、all_models_completed 及各模型完成状态。原始频次权重不因多模型命中而重复累计。

可以报告已知命中率下界以及包含未决质量的上界；不完整结果不能自动当完整风险进入优化。即便已观测某个首次命中位置，另一个中断模型仍可能更早命中，因此 exact_min 和 observed_min 的状态也应区分。

单个固定、完整 Min_auto 指标在独立用户条件下可以有比例区间；加权条件分布、配对差值、响应随机性和搜索选择需要对应重采样。主要评价器输出原始聚合量以便配对 bootstrap，不只保存已经汇总的百分比。

## 6. 响应模型与攻击者知识

R0 对各划分分别计算接受率 a 和条件分布 Q。a=0 时不可行；无限重试成本为初始拒绝率 1-a 及每名初始用户额外尝试期望 (1-a)/a。接受子集条件风险与“R0 下全体用户最终风险”可数值相同，但报告必须注明不同解释。

A1 只使用 Q_train 学习；Q_validation/Q_test 仅用于对应目标评价。成本也按对应划分的原始质量计算，不能以筛选后人数作干预比例分母。有限重试、R1 修补、R2 混合单独配置，不能复用无限重试成本公式。

R1/R2 的响应参数只在开发阶段确定；尝试耗尽、失败和放弃都是完整结果。对没有完成新账户的用户，报告完成率并对主推荐施加约束。账户迁移保留旧口令必须单开威胁情景，记录遗留风险。

F 冻结原模型和知识，不冻结为旧口令清单；A0 获得策略但不重训；A1 获得修改后的训练分布并重训；A2 是机制知识压力组。自然支持规模变化是模型与策略的结果，不通过统一清单人为抹平。

删除主流程对 response_candidate_space() 的依赖。该函数只可继续服务旧合成实验，不得把真实用户响应结果或枚举全集传入普通攻击器。

## 7. 推荐目标、对照与验证隔离

默认目标为指定响应情景下的 A1 Min_auto 风险。给定风险要求最小化成本，或给定成本上限最小化风险，并约束完成率和规则复杂度。多响应稳健目标及是否纳入 A0 必须在验证前配置。

常见规则至少包含无约束、长度系列、长度加字符类别系列、长度加来源明确的阻断表系列。相同用户、响应、模型族和预算下形成对照前沿，再检验同成本更低风险或同风险更低成本。

低摩擦/均衡/高防护来自预设选择规则。无满足约束的策略，输出 no_feasible_policy；有可行策略但无优于对照的改进，输出 no_supported_improvement。允许选择常见规则和多个档位相同，不为了演示自动放松约束。

将验证区区分为攻击器调参与策略选择，或采用嵌套验证。冻结选择后批量评价 test 上的选中策略和预注册对照；未经预注册的 test 探索结果不能回写为新的验证依据。

缓存仅存在于单次固定配置、固定数据的运行中；配置、协议、种子和响应参数通过运行实例隔离。攻击流键包含训练/调参哈希和有效策略，F 共享原始流；评价键包含策略、响应、划分与知识。跨运行不复用评价缓存，攻击流不含 test。

## 8. 实施顺序与验收矩阵

| 阶段 | 文件或模块 | 必须完成的工作 | 进入下一阶段的条件 |
|---|---|---|---|
| P0 数据 | core/rockyou.py、core/data.py 或新加权模块 | 正确计数解析、权重划分、语义清单 | 微型手算和数据隔离通过 |
| P1 开放流 | core/attackers.py、ai/pcfg_adapter.py、ai/attacker_adapter.py | 独立生成、统一过滤去重计费、停止状态 | 目标外/重复/策略过滤排名正确 |
| P2 聚合 | core/metrics.py | 逐口令 Min_auto、权重、截断/未决状态 | 并集例与不完整预算检测通过 |
| P3 规则发现 | 特征模块、policy/engine.py | 训练侧分布引导与固定基准 | 无测试派生规则，支持度方向可追溯 |
| P4 响应 | policy/response.py | R0 解析、R1/R2 情景、完整成本与完成率 | R0 等价性、不可行情景和分母正确 |
| P5 攻击整合 | experiments/policy_attack.py | F/A0/A1、统一模型集合、取消响应全集 | 原始和响应 train 隔离，知识条件正确 |
| P6 推荐 | experiments/policy_search.py | 验证 Min_auto 目标、常见规则前沿、需求约束 | 无可行解和无改进均可正常输出 |
| P7 交付 | experiments/config.py、pipeline.py、web、报告 | 新 schema、复现键、来源和状态展示 | 小规模真实数据全链路与回归验收 |
| P8 正式实验 | 冻结配置及实验清单 | 主实验、种子、预算/响应敏感性和消融 | 根据真实结果写结论，保留负结果 |

各阶段属于同一最终迁移，局部通过不代表新协议已经端到端完成。新增测试应针对数据泄漏、计费、并集、不可行和分母等真实错误风险，不仅镜像内部实现。

## 9. 新报告的最低字段与图表

实验清单至少包含 dataset_id、source_format、source_semantics、source_hash、split_hash、protocol_id、budget_unit、attack_family、knowledge_level、response_scenario、policy_id、model/config_hash、seeds、stop_reason、completed_budget、cohort_denominator、acceptance/completion/cost 与 Min_auto 状态。

图表显示真实语料还是合成测试、单模型还是 Min_auto、F/A0/A1、预算是否完成、用户响应假设和分母。来源只有聚合排名频次时不生成虚假的攻击/策略图；PassLLM 仅环境检测时不进入模型列表。

主结果为预算曲线、常见规则与推荐的风险—成本前沿、不同需求选择表及配对差值区间。运行时间与原始生成量另报，K 不解释为跨模型总工作量。

## 10. 需经预实验或应用需求确定的参数

以下内容已有明确选择方式，但尚无本轮验证后的最终数值：语料版本与编码、训练规模、主预算 K、响应概率与重试上限、安全需求、允许用户成本、完成率阈值、规则复杂度上限以及最低有实际意义的改进。

这些值在开发数据上进行资源/统计预实验，或由应用要求指定，随后冻结。旧提案的 10%/20%/30% 干预阈值、98% 完成率、0.85/0.15 权重、0.5 个百分点收益均不是已验证标准，本版不默认继承。

本次已完成默认代码、两种界面、报告、配置及批量实验入口的统一迁移。75 项回归测试及真实数据验收证据见 PROJECT_STATUS.md。当前特征发现采用频次头部标签；交叉拟合攻击标签、A2、外部模型和外部用户校准仍是明确扩展项。正式效果结论须按冻结配置完成 P8，多种子执行入口不代表相关结论已经成立。
