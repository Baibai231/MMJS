# 比赛范围与证据对应

比赛名称、截止日期、提交格式、报告长度、演示时长和开源条款：组织者还没有单独发给本仓库。这些空格不能临时编造。下面按路线图已经确定的研究问题，把评分意图对应到现有证据。规则一到，只改这一页的表头，不改已经跑完的协议。

研究问题：在相同离线猜测预算和模拟用户成本下，按验证集上的风险收益重排建议，是否比论文的 IGR 特征排序更稳。

主指标：测试用户 `cracked@B` 的绝对百分点差。相对百分比不与百分点混写。主预算固定为 40 次离线猜测，不是在线登录。主攻击器是训练集频次、固定阶字符 n-gram，以及标明不是 OMEN 的固定阶马尔可夫。主要比较对象是无策略、传统字符类别、长度加黑名单、论文 IGR 和预算/成本排序。这些名字写在协议常量里。已经公布的表用的就是它们，不能再说成看测试结果之前从未看过测试集。

工程计时在每次场景结果的 `engineering` 字段里：分布扫描、建议选择、攻击评分和峰值内存。没有真实被试时，初始接受率、平均尝试次数和改变率只来自事先设定的采用率，不报告实测记忆率。

主要数据：合成协议（652 个支持字符串）用于策略对照。RockYou 带频次文件用于论文 Zipf 核对。MAYA 五个站点只做分布和特征排序。算力按无 GPU 的本机 CPU。
