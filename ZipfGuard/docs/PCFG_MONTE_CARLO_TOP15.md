# PCFG 前置蒙特卡洛与 Top15 网站策略

## 当前实验

主入口为本地网页的首页和 /dynamic。只运行 PCFG，保留 F、A0、A1；历史多模型代码和旧报告保留，但不作为新实验结果。动态候选改为整条网站规则，不使用 960 个模板，不穷举策略路径。

网站名单采用队友的 [Top15 文件](top15_teammate_source.md)，机器可读定义位于 [网站规则配置](../configs/top15_sites.json)。原始文件没有提供排名来源、官方证据链接或观测日期，不能据此称为某一权威榜单的最新 Top15。

默认可执行 Google、Instagram、Wikipedia/Wikimedia、Netflix、GitHub、Amazon 的已知强制规则子集。Instagram 至少 6 字符的强制下限来自[官方帮助中心](https://help.instagram.com/273359857992105/)，是在既有十场景全量报告生成后补证，不能将旧报告改称已评价 Instagram。Google 和 Wikimedia 当前可编码子集同为长度至少 8，曲线可能完全重合；它们不能算两份独立的有效性证据。未公开黑名单、泄露检测、用户名相关限制和口令历史没有用自造规则替代，因此本实验比较的是规则子集，不是这些网站的实际完整安全水平。

YouTube 继承 Google；WhatsApp 不属于此传统口令实验。Facebook、OpenAI 的普通账户硬规则仍缺少可执行参数；[官方核验与十批路径搜索状态](TOP15_SEQUENCE_STATUS.md)记录了缺口。Reddit、X、TikTok、Yahoo、LinkedIn 的建议保留为单独场景：将 controller.include_recommendations 设为 true 后纳入，但始终标注为“建议采纳场景”，不能称为实际注册硬规则。

GitHub 正确实现“长度至少 15，或者长度至少 8 且有小写字母和数字”。Netflix 保留 6 到 60 字符范围。没有把 TikTok 的建议长度上端 15 当作最大允许长度。

## 数据与查询

从同一语料的出现记录中，用固定随机种子无放回抽取互不重叠的位置，形成注册用户集和开发集；开发集再分为训练、调参与预览验证部分。相同口令可以出现在不同划分，这符合频次数据的用户抽样，但同一出现位置不会重复使用。PCFG 只用开发训练部分；用户集用于查询与评价，不回流训练。

1. 先训练原始 PCFG，采样并建立 F 索引，再模拟注册。
2. A0 复用 F 的样本，通过规则掩码累计合规候选数量，不重新采样。
3. A1 用策略修改后的开发训练集训练；每次训练后立即采样，再查询用户口令。相同训练频数复用同一索引。
4. 保存原始 F 和动态策略 A1 的私有查询文件，后续查询无需重新训练或采样。

网页查询返回猜测次数估计、采样标准误和实际热门排名。热门排名按用户集出现次数降序，同频并列，使用 competition ranking。F/A0 的热门排名来自初始用户集，A1 来自动态策略最终用户集。缺失的口令返回“未出现”。模型概率为零返回“模型未覆盖”，不伪造有限猜测次数，也不代表安全。

本地查询工具：

~~~powershell
python tools/query_pcfg.py --index reports/dynamic/<run_id>/pcfg_frozen_private.json
python tools/query_pcfg.py --index reports/dynamic/<run_id>/pcfg_frozen_private.json --policy site_github
~~~

默认隐藏输入口令，避免将口令放进命令参数。批量输入可加 --stdin，每行一条。私有索引含模型词段、采样及用户口令频数；公开页面只返回汇总或用户主动提交的单条查询结果。

## 估计原理与限制

使用现有固定版本 upstream PCFG 的训练结果，coverage=1，未添加 OMEN 或其他攻击模型。一个字符串可能有多个推导，评分将全部推导概率相加；相同概率按字符串字典序打破并列。因此本实验的排名是按字符串边际概率排序的唯一猜测数，与 upstream 按推导优先队列输出的原始序号不完全相同，不能混用。

若 $X_i$ 独立采自模型 $P$，$X_i\prec w$ 表示其模型概率更大，或概率相同但字典序更靠前，则

$$
\widehat{G}(w)=1+\frac{1}{n}\sum_{i=1}^{n}\frac{\mathbf{1}\{X_i\prec w\}}{P(X_i)}.
$$

A0 在求和项中再乘以策略接受指示量，分母仍是全部 $n$ 个原始样本，不能除以筛选后样本数。这样统计的是排序在目标之前的不同合规字符串数量。

样本只抽一次，按概率和字典序排序，保存重要性权重前缀和。之后的查询包含一次 PCFG 评分和二分查找。采样与评分使用同一个归一化模型；相同字符串的多次抽样保留频数，不误作不同候选。

返回的采样标准误只是 Monte Carlo 不确定性，不包含训练数据和模型错设的不确定性。另提供逐查询 Hoeffding 95% 界限，利用前驱重要性权重不超过 $1/P(w)$；这是保守的单点界限，不是多口令同时置信带。前驱样本少于 30 会标为 low_sample_support；零前驱样本的点估计为 1，但不能据此断言真实排名为 1。极低概率尾部可能需要增加样本。

方法参考实现：项目已固定版本的 PCFG upstream/lib_trainer/future_research/monte_carlo.py。本版重新实现索引与统计，处理多推导字符串概率、A0 掩码、同概率排序和支持集外状态，没有直接照搬该研究脚本的最大推导概率及目标列表内强制递增排名。
