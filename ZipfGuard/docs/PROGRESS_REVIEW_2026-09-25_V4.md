## 二、本次实际验证

### 2.1 定向测试

14 项 HTPG 基线测试，加上修改漏收标记、拒绝与长口令响应、来源参数三项测试：合计 **17 项通过**。

没有运行完整测试套件。这 17 项也不等于新增候选生成器的完整覆盖测试；候选生成和旧伪收益回归另做独立探针。

### 2.2 正式入口参数

模拟调用 CLI，跳过昂贵实验及文件写入：

- 请求：budget=17，seeds=[7]，sizes=[300]，response_mode=diversified，adoption_rate=0.4。
- 主网格收到上述全部参数。
- 顶层来源正确记录 robustness-v4、17、[7]、[300]。
- 同一调用中的 ablation 和 response_sensitivity 未收到响应模式／采用率，仍是各自的固定协议。这些附属结果不能直接当成与该主网格同条件的消融。

### 2.3 旧伪收益回归

本次使用当前公开候选，固定种子 1、总用户 900（540 训练／180 验证／180 测试）、预算 40，检查 Zipf／长尾 × 确定性／多样化响应。当前公开支持集在两个场景相同，候选预先由该支持集生成，没有使用测试口令补候选。

| 场景 | 响应 | 选择动作 | 频次攻击下降（百分点） | 修改测试用户 | 三阶段修改导致漏收 |
| --- | --- | --- | ---: | ---: | --- |
| Zipf | 确定性 | 无 | 0.00 | 0 / 180 | 均为 0 |
| Zipf | 多样化 | 无 | 0.00 | 0 / 180 | 均为 0 |
| 长尾 | 确定性 | 无 | 0.00 | 0 / 180 | 均为 0 |
| 长尾 | 多样化 | Length | 1.11 | 16 / 180 | 均为 0 |

候选数为 314,135，本机首次生成约 60.69 秒，完整探针约 61.89 秒。上次的确定性 5.00、11.11 个百分点伪收益没有再次出现，当前选择器也不再选中制造这类收益的 LSD 动作。

长尾多样化保留的 1.11 个百分点仅为单种子、频次攻击的诊断，尚未比较相同成本基线、运行多种子区间或其他攻击器。不能据此宣称创新有效，也不能把本探针视为完整的 v4 主实验。

## 三、新保护还没有贯通所有输出

### P0：主指标隐藏，衍生统计仍保留被污染的收益

为验证异常处理，本次故意提供不完整候选并仅用频次评分跑主评估流程。确认：

- 主指标 absolute_point_change_vs_none 正确变成 None。
- headline_published 正确为 False。
- 但 paired_vs_none.frequency.point 仍为 0.03333。
- head_users.frequency_absolute_point_change 仍为 1.0。

这两个数只是受控漏收反例中的错误收益，不是当前完整候选的实验结果。它们说明保护只覆盖部分字段。run_grid 仍会汇总这些配对和头部统计，后续图表可能继续使用。

**处理目标：**统一结果有效性状态。受候选错误影响的封闭收益、相对收益、头部收益和配对区间应一致标为不可发布；原始诊断数据单独存放。开放攻击是否有效独立判定，不与封闭错误自动混为一谈。

代码：experiments/robustness_protocol.py 第 584–607、799–823 行。

### P0：不可发布的空值会导致展示报错

同一受控反例传给 public_comparison_html，实际抛出：

```text
TypeError: unsupported format string passed to NoneType.__format__
```

原因是主指标可能为 None，而 HTML 仍使用数值格式。命令行打印和旧表格生成器也存在直接格式化空值的路径。

**处理目标：**显示“未发布：修改导致候选漏收”，并保留原因与人数，不能报错、显示 0 或留下旧图。

代码：experiments/robustness_protocol.py 第 949–961、1001–1004 行；experiments/freeze_directed_table.py 的数值表格渲染。

### P1：缺失种子不能悄悄变成完整实验均值

_mean_range([None, 0.2]) 得到 mean=0.2、seeds=1、withheld=1。实现有记录缺失数量，但其均值只代表有效子集。

**处理目标：**显示有效／计划种子数与缺失原因；事先规定有无效种子时能否发布主比较。不能把有效子集均值命名为完整五种子均值，或据此与另一方法的完整种子均值比较。

## 四、其他需统一的路径

1. **预算曲线只检查测试漏收。** 当前主表检查三个阶段，multi_budget_curve 只检查 test。训练漏收同样会污染自适应排名，应复用主表的完整审计。
2. **旧 compare_scenario 仍用旧 registered_candidates。** 虽然 unique 已修复，候选生成和发布保护尚未统一。应迁移、归档或明确标记旧入口。
3. **no_igr 尚不是真正只去掉 IGR。** 现在固定返回 Length／LSD，不再运行原先预算／成本选择；同时 _apply_plan 仍按头尾条件筛建议。它更接近“固定两特征对照”，需要准确命名或重新定义消融。
4. **新正式结果尚缺。** reports 中最新主表仍为 v2，不能证明 v4 的收益。源码和文档修复完成之后，需要生成一份当前环境的完整报告。
5. **可追溯性仍需补全。** 响应配置、执行统计、数据划分与候选哈希应随运行保存，不能只在程序内部或事后表格里存在。
