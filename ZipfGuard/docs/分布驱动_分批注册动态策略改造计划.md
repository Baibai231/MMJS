# ZipfGuard 分布驱动的分批注册动态口令策略改造计划

日期：2026-09-28。状态：已开始实施；当前实现与验证进度见 [动态实验实施状态](DYNAMIC_IMPLEMENTATION_STATUS.md)。本文件仍作为设计和验收依据。

## 1. 本轮目标与核心决定

将当前静态策略实验扩展为：真实泄露口令初始化 → 模拟注册顺序 → 分批执行策略 → 观察累计分布 → 选择下一批策略 → 对比均匀程度、猜测难度及用户成本。

主要研究问题是：**在不要求老用户反复修改、限制新用户修改负担的条件下，仅利用历史注册分布，能否通过常见口令规则的动态组合，使累计口令分布更分散，并降低独立自适应攻击的成功率？**

创新候选是“基于历史累计分布反馈、带用户成本约束的批次策略选择方法”。常见规则本身不作为创新；动态优于静态的效果必须由对照实验验证，不能预先承诺。

| 项目 | 本计划默认决定 |
| --- | --- |
| 正式注册流 | 100,000 条按原始频次抽取的出现记录，每条对应一个模拟用户 |
| 注册批次 | 10 批，每批 10,000 人；末批不足时保留真实人数 |
| 注册顺序 | 固定种子随机打乱，不将泄露文件行序视为实际注册时间 |
| 初始策略 | 第一批使用最小长度 8，作为预先固定的实验起点 |
| 更新频率 | 每批结束后选择下一批策略，每次至多新增一项规则或提高一档阈值；允许不更新 |
| 策略兼容 | 主实验采用单调累积规则，不删除已有约束；支持集不得为空 |
| 老用户 | 保留注册时口令和策略版本，后续策略不追溯强制改密 |
| 新用户修改 | 使用逐用户、有限尝试的随机修补模型；保留失败和放弃状态 |
| 优化顺序 | 成本及完成率先作为可行性约束，然后优先改善分布，再比较猜测难度，最后择低成本 |
| 攻击预算 | 每模型最多 1,000,000 次不同有效猜测；同时报告原始输出、耗时及实际完成预算 |
| 主要攻击场景 | 自适应攻击 A1，另报冻结 F、只知策略 A0 |
| 单条口令提升 | 同一评估攻击流下修改前后猜测排名变化，完整报告精确值、界限和无法判定 |
| 正式稳定性实验 | 5 个预先固定种子；响应、成本阈值及注册顺序敏感性分别报告 |

长度 8 是研究起始规则，不代表适用于所有认证场景的安全推荐。本文涉及的概率、成本上限和规模调度属于待开发预实验检验的实验设定。

## 2. 对当前项目的实际判断

本计划以当前 README 和开放主流程为基础，不沿用旧合成流程作为主实验。已检查以下代码：

- core/corpus.py：完整文件范围按出现次数抽样，解析计数，保留频次和数据哈希。
- policy/open_policy.py：Rule、训练侧头部分布特征发现、R0/R1/R2 响应、编辑距离。
- core/open_attack.py：独立候选生成、策略过滤与去重计费、原始位置、完成状态、Min_auto。
- experiments/open_pipeline.py：AttackEngine、静态搜索、响应、F/A0/A1 和报告整合。
- experiments/open_config.py 与 configs/open_full.json：当前完整预设为 20,000 次出现，最高预算 10,000；配置支持的最高预算已到 1,000,000，但资源限制需要一起检查。
- web/open_interface.py、web/open_presentation.py、web/app.py、web/server.py：当前两种界面的共用入口与展示。

主要缺口不是重新接入真实数据，而是：

1. 当前按聚合频次及 train/tuning/validation/test 组织，没有稳定的注册用户编号及批次状态。
2. 现有分布引导用于静态候选发现，没有将前批注册后的累计分布作为下一批的反馈状态。
3. R0 是解析条件分布，records 为空，不能支撑每个模拟用户的原口令到新口令配对。
4. R1/R2 有逐出现记录，但修补主要仍是固定后缀等少数路径，缺少独立的响应事件模型与逐规则快照。
5. 当前 Rule 没有批次、生效范围、版本继承与兼容性检查。
6. 百万预算会放大猜测流缓存、PCFG 原始生成上限、超时和图表体积问题，不能只改 budgets 数字。

开始实施时，工作区已有开放流水线、报告和测试的修改；这些既有修改应继续保留，不作为本计划的改动成果。

## 3. 数据：将 10 万条变成可追踪的注册流

### 3.1 抽样与角色

主实验采用完整频次文件中均匀抽取 100,000 次出现，不按唯一口令均匀抽样，也不取前 100,000 行。重复口令必须保留，否则 baseline 会被人为变平。

额外从同一文件的其他出现位置抽取开发参考样本，建议先设 100,000 条，分为攻击训练 60%、攻击调参 20%、策略开发验证 20%。这部分不计入 100,000 名注册用户。两组出现位置不重叠；相同字符串可以自然跨组出现，须披露这是同源 occurrence 评测而不是字符串隔离或跨库外推。

若后续使用全量数据，仍保留开发角色与正式注册角色的边界；不能一边把同一批出现记录用于训练，一边把其命中率当作独立评价。

当前 load_corpus 将样本直接聚合并划分，需拆出“抽取出现记录”和“分配用途”的接口，避免把现有 60/10/10/20 划分误认为 10 个注册批次。

### 3.2 用户身份与初始状态

每条注册记录建立稳定 user_id、registration_index、cohort_id、original_password_ref。原始口令和最终口令只在本地实验数据层使用；公开报告使用随机用户编号和统计，不输出泄露口令清单。

打乱顺序前后保持计数守恒。每个策略实验臂共享完全相同的原始用户、注册顺序及用户响应随机种子。多个用户即使原口令相同，也拥有独立响应随机流，不能强制得到相同新口令。

没有真实注册时间时，报告必须写“模拟注册顺序”。用户数量属于模拟身份数量，不宣称是语料已验证的真实独立账户数。

### 3.3 baseline

在任何修改前保存：全体 100,000 人 baseline、每批 10,000 人 baseline、前 t 批累计 baseline。绘制全体 baseline 只用于描述与最终报告，不将未来批次内容反馈给策略选择器。

每轮同时保留以下比较对象：

- 同批原始口令与同批修改后口令：判断本轮改变。
- 同等累计人数的无策略分布与动态策略分布：判断整体收益。
- 更新前历史累计分布与加入本批后的累计分布：解释反馈过程；因人数不同，不直接将所有数值差异视为策略效果。

## 4. 口令策略候选池与兼容性

候选池采用现实系统能解释和实现的规则族。规则“常见”不等于规则一定有效，更不等于现代指南普遍建议强制字符类别；必须通过响应和攻击评价筛选。

| 规则族 | 初始候选档位 | 主实验用途与兼容规则 |
| --- | --- | --- |
| 最小长度 | 8、10、12、14、16 | 逐档提高；不增加最大长度限制，允许长短语 |
| 至少若干字符类别 | 2、3 类；4 类作敏感性项 | 类别定义冻结，阈值只提高；与长度组合 |
| 常见/泄露弱口令精确阻断 | 开发训练 Top-100、Top-1,000、Top-10,000 | 只阻断完整字符串，采用嵌套集合；不直接把完整测试文件加入黑名单 |
| 历史高频完整口令阻断 | 从已注册历史中挑选高频热点，按开发阶段冻结阈值扩展 | 复用常见口令阻断机制；累计只加不减，属于待验证的动态更新机制 |
| 重复字符限制 | 连续相同字符最多 3，再到 2 | 放在企业式规则扩展池；阈值越低越严格 |
| 连续数字/键盘序列限制 | 禁止固定词表中长度至少 4 的明显序列 | 序列定义固定，只增加禁止集合，不临时创造任意模式 |

主实验优先使用长度、字符类别、完整弱口令阻断三类；重复和序列规则作扩展池或消融，避免以大量不普遍的限制撑出创新。用户名/邮箱重叠规则缺少真实上下文，本轮不启用。生日、年份后缀一刀切禁止、任意英文单词禁止、固定必须含某符号、不准其他用户使用相同口令，均不作为主候选。

历史热点阻断不等于“凡前人使用过就禁止”。只使用达到预注册频次与支持度门槛的头部完整字符串，并记录发现批次、支持度、加入理由和版本。训练黑名单不读取正式注册流的未来部分。

兼容性检查包括：新规则接受集合包含关系、参数范围、重复规则合并、至少存在有效构造、开发响应完成率和攻击器长度/字符域覆盖。主实验形式为：

$$
\mathcal A(\pi_{t+1})\subseteq\mathcal A(\pi_t).
$$

“不冲突”本身并不一定要求单调加严；这里主动选择单调版本，是为了满足逐项增加规则的展示和追溯需求。若后续需要撤销、替换规则，应单独设策略版本可替换的研究臂，不混入本次主结论。

每轮保留当前策略作为候选。没有可行改进时输出 hold，不强行增加规则。候选池不能保证最终均匀，必须允许 no_feasible_update 或 no_supported_improvement。

## 5. 修改口令的方法与脚本

### 5.1 主响应模型 R3：逐用户随机有限修补

新增 R3，不改变现有 R0 的语义。通过策略的用户原样保留；未通过者按固定行为倾向生成提案，每次提案必须检查当前全部规则。

响应提案分三类：

1. 小幅修补：随机位置插入、追加、替换、改变大小写、增加所缺字符类别。
2. 片段扩展：从独立开发词表抽取片段，进行组合、分隔或插入；不是所有用户统一追加同一数字或符号。
3. 重新选择：从开发分布重新抽取口令，或采用更大词表构造短语，再检查完整规则。

先设三个透明的行为情景：保守修补为主、混合响应、重选为主。例如混合情景可暂设上述三类概率为 0.60/0.25/0.15，额外尝试最多 8 次；这些是模拟参数，不冒充真实用户统计。参数只在开发阶段调整，随后冻结。

提案概率允许依赖“违反了哪项规则”，不允许直接查看当前最缺哪类口令、目标攻击排名或测试结果。否则会把优化收益悄悄放进修改脚本。分布驱动的个性化推荐如需研究，必须单独列为另一干预方法。

可以保留一定的常见后缀修补概率，让自适应攻击确实有机会学到用户习惯；不能通过强制所有人选均匀随机串来保证分布变平。

### 5.2 失败、尝试与成本

达到次数上限仍不合规，记录 failed；放弃记录 abandoned。两者不当作“强口令”或“未猜中口令”，也不从初始用户分母静默消失。

主要统计每批：修改人数、成功修改率、初始拒绝率、失败/放弃率、尝试次数、编辑距离、长度增量。平均值与中位数/P90 分开保存，重选比例作为额外负担指标。编辑距离只是修改量代理，不能直接称为记忆成本。

同一用户的跨候选对比使用按 user_id、提案步骤和操作类型派生的稳定随机流，确保比较不被随机种子重置左右。保存每一步的拒绝原因和操作，不只保存最后结果。

### 5.3 逐项加规则的快照

策略候选搜索在历史/开发副本上进行；正式注册批次只执行最终公布的策略。假如某策略由三项规则组成，则展示无规则 → 第一项 → 第二项 → 第三项的前缀快照，每个前缀都从同批原始口令出发，用相同响应随机机制模拟。

这些前缀快照是“反事实解释”，不能算成同一用户实际被迫修改三次。真实成本取最终策略的一次注册响应。若未来专门模拟交互式多次加规则，再独立记录每次真实修改成本。

拟新增 tools/simulate_registration.py 作为离线填充脚本：读取冻结抽样与策略清单，生成逐用户响应、轮次汇总和快照。脚本不访问网站或真实账户。

## 6. 什么叫分布趋向均匀

不将长度直方图变平等同于口令字符串分布变均匀，也不要求整个无限口令空间均匀。主目标是在给定样本、用户负担和常见规则库内降低频次集中程度。

设 n 个完成注册的用户中，口令 w 的出现次数为 c_w。主分布指标为同口令碰撞概率的样本估计：

$$
\widehat C=\frac{\sum_w c_w(c_w-1)}{n(n-1)},\qquad n\ge2.
$$

越低表示两个不同模拟用户采用相同口令的比例越低；全不相同则样本碰撞为零，不等于证明总体不存在热点。用户不足 2 时记为不可计算，不填零。

同时报告：Top-1/10/100/1000 占比、唯一口令率、经验熵、有效支持规模、频次排名曲线、累计频次曲线。经验熵采用：

$$
H=-\sum_w p_w\log_2p_w,\qquad H_{\mathrm{norm}}=\frac{H}{\log_2n}.
$$

H_norm 的样本规模效应通过同等人数的对照控制；不把每轮变动的唯一支持集当作相同的总体空间。按“当前已观察到的不同口令”计算熵均匀度可以做辅助指标，但 10 个口令各占 10% 也会完全均匀，不能独立作为安全目标。

每张字符串分布图显示完整统计和固定 Top-K 视窗，尾部单列质量。各实验臂同人数、同坐标、同单位，不能各自缩放后制造变平。按长度、类别、后缀等作辅助特征图，用于解释候选规则来源。

### 6.1 老用户带来的可达边界

前几批已经形成的热点不会因后续规则消失。设历史总人数为 N，某热点人数为 c，新增 m 人后，即使没人再选择它，该口令的占比也至少为 c/(N+m)。如果早期热点太强且后续用户太少，单靠后续注册不可能消除它。

策略选择应考虑这一下界。结果可以是“降低头部集中但未达到均匀”，不能为了达到图形目标偷偷修改老用户或删除高频记录。

## 7. 动态策略算法

### 7.1 历史状态与下一批预测

第 t 批注册前，控制器只能读取：前 t-1 批已完成的分布统计、历史初始意向统计及成本、冻结的开发参考数据、已公布策略。不能读取第 t 批或未来用户的原始口令来提前选策略。

对当前策略及每个允许增加一项规则的候选，在开发/历史重放样本上模拟下一批响应，得到预测分布 q_t。预测累计分布为：

$$
\widetilde p_t(w)=\frac{N_{t-1}p_{t-1}(w)+m_tq_t(w)}{N_{t-1}+m_t},
$$

其中 m_t 是预测完成注册人数，不直接拿尝试注册人数冒充。完成率在前置约束中检查，避免通过大量拒绝用户让分布表面变好。

关键是优化累计分布，而不是只让第 t 批看起来均匀。当前批次口令尚未出现，因此 q_t 是预测，不与实际效果混为一谈；批次结束后绘制预测与实际偏差。

### 7.2 有约束的分层选择

先冻结成本和完成率阈值，再执行：

1. 去掉不兼容、响应不可行、超出成本或规则复杂度上限的候选。
2. 比较预测累计碰撞率与 Top-K 集中度，保留在预设容差内接近最优的候选；要求超过开发阶段冻结的最小实际改善量。
3. 在这一组中优先选择自适应攻击下命中率更低、预算截断猜测难度更高的策略，并避免超出预设容差的安全退化。
4. 对收益接近者，优先选择修改率和编辑负担更低、规则更简单的方案。
5. 如果没有足够收益，保持原策略，并记录失败原因。

默认每批新增至多一个动作，故每次新增限制都有对应图。更复杂组合可作为后续 beam search 扩展，不能让规则个数与候选计算量失控。

成本至少包含绝对上限和相对上限：本批候选相比“同批仍用上一策略”的修改率增量、编辑距离增量，以及本批成本相比早期批次的增长。示例开发扫描可使用修改率上限 40%/60%/80%、相对增量上限 5/10/20 个百分点、完成率下限 95%/98%/99%；这些不是强行满足的正式标准。第一批固定起点单独测成本，不能因其超限而悄悄放松后续阈值。

### 7.3 每轮实际执行次序

~~~text
预先固定：数据用途、100000 名用户及顺序、开发参数、攻击协议
pi_1 = 最小长度 8
history = 空

for t in 1..10:
    只向响应执行器释放第 t 批原始记录
    在本批执行已经冻结的 pi_t
    保存逐用户响应、逐规则前缀快照、本批与累计分布、成本
    将本批完成注册统计追加到 history，老用户不修改
    保存只供报告使用的攻击评价，不用本批攻击成绩回调本批策略
    if t < 10:
        从 history 和开发数据产生兼容候选
        预测候选对下一批和累计分布的影响
        按成本、分布、安全性顺序选择 pi_(t+1)，或保持
        保存选择依据和生效区间

在整条轨迹冻结后，完成正式独立攻击、逐口令配对和对照报告
~~~

此实验是因果顺序的在线评价：过去正式注册的聚合分布按设计允许反馈；不能再称“所有正式数据永不参与任何后续决策”。正式攻击目标的猜测排名不进入控制器；超参数不根据这条正式轨迹调优。正式轨迹中的下一批始终是未见数据。

网站现实部署不应存储用户明文来做这一反馈。当前先做本地离线研究，数据可用性与统计反馈的部署实现另立课题。

## 8. 百万猜测预算与攻击者知识

复用开放主线的计费协议，不退回旧闭集候选空间：模型自行生成字符串，候选生成不接收测试目标清单；策略允许的不同校验候选计费，语料之外的猜测照常计费，原始输出和被过滤数量另外保存。

预算点固定为 100、1,000、10,000、100,000、1,000,000。一次流生成到最高预算即可计算多个点，不为每个点重训。

主要模型为训练频次、训练派生规则字典、字符 n-gram 和 PCFG。频次词典可能正常耗尽，不凑出百万条；PCFG/n-gram 如因原始上限或超时只做到十万级，标记未完成，不将百万预算处记作安全结论。至少有预先指定的开放生成模型完整运行到百万级，才验收百万预算目标。

现有 PCFG 原始上限在配置验证中最高为 1,000,000，去重和策略过滤后不一定够 1,000,000 次计费猜测。实施时同时修改资源配置验证、适配器上限与状态记录，先在开发样本测试效率，再冻结正式资源预算。

### 8.1 不同注册策略的适用范围

- F：冻结初始训练和知识，生成开放候选，不强行限定为旧字典。
- A0：知道相应账户注册时生效的策略，但不重训。
- A1：使用独立开发用户在对应历史策略序列下的模拟响应训练，不读取正式用户最终口令来训练。

最终累计评估按 cohort_id 使用各批真实生效策略。不能用最后一批的最严格策略过滤所有账户，否则会错误排除老用户的合法口令。主场景假设攻击者知道批次/策略版本，另外可做版本未知的敏感性组。

单模型预算是每目标账户的候选猜测上限，不是平台所有账户总计算量。Min_auto 延续当前定义：每个口令取各模型最早排名，K 表示每模型预算；M 个模型联合最高消耗可达 M×K，不能称作“全部模型总共一百万次”。另做总预算固定的预注册混合猜测流时须单列协议。

## 9. 猜测变难与每条口令的提升百分比

### 9.1 总体指标

报告 cracked@K、达到 10%/25%/50% 命中率需要的猜测数 G_q，以及每批和最终的预算截断平均猜测数。达不到 q 时写“超过预算”或“此模型未达到该覆盖率”，不外推出精确数字。

有限预算指标使用 min(G,K+1) 的均值，并清楚标记为截断值。不能只比较已被猜中的口令的平均排名，因为两组被猜中的用户集合可能不同。

### 9.2 逐用户配对定义

口令没有脱离攻击者的绝对强度。为分离“口令修改本身”与“攻击模型也变了”，新增统一参考评估流：同一个冻结版本的攻击模型、同一个候选顺序、对原口令和最终口令使用相同的过滤规则。优先用不含新策略过滤的共同流，确保原口令不会因为不满足新策略而被人为判为无法猜中。

设其修改前后排名为 G_before、G_after；两者均实测时：

$$
\Delta_G=100\%\left(\frac{G_{\mathrm{after}}}{G_{\mathrm{before}}}-1\right).
$$

同时保存 log2(G_after/G_before) 作为更稳定的图示刻度，称“猜测难度对数增益”，不冒充真实密码学熵。

在每模型充分完成 K=1,000,000 预算且联合状态可判定时：

| 原口令状态 | 新口令状态 | 展示 |
| --- | --- | --- |
| 两者均命中 | 两个排名明确 | 精确百分比，允许 0 或负数 |
| 原命中，新未命中 | G_before 已知、G_after>K | 提升下界：大于 100%×(K/G_before−1) |
| 原未命中，新命中 | G_before>K、G_after 已知 | 比例上界；明确出现退化，不编造精确降幅 |
| 两者均未命中且字符串不同 | 两个排名均被截断 | 无法判定提升比例 |
| 原样保留且使用共同评估流 | 两者是同一字符串 | 修改本身的相对变化为 0%；绝对排名仍可能未知 |
| 修改失败或放弃 | 没有最终有效口令 | 不适用，计入完成率和成本 |
| 攻击因资源限制中断 | 百万预算未完成 | 未决，不可假装为 G>1,000,000 |

有限模型完全耗尽时标记“模型不覆盖”，不能称无穷安全。单模型未命中范围和 Min_auto 的精确/观察最小值状态继续分开。不能通过给未命中统一填 1,000,001 来制造精确提升百分比。

每条用户记录都给出状态和说明，但不保证每条都有精确百分比。新增精确值、下界、上界、未决、不适用等类型；另报可精确计算比例，防止只展示成功改善者。

动态 A1 下每批策略前后风险变化另作系统指标，不能与上述同一参考流的个体变化混为一谈。共同评估流可以补充使用独立响应训练后冻结的 A1 模型，对前后两条口令仍保持同一模型及候选顺序。

## 10. 必须绘制的图与页面板块

| 页面板块 | 图或表 | 回答的问题 |
| --- | --- | --- |
| 数据与 baseline | 全体/逐批/累计频次排名曲线、CDF、Top-K、重复率 | 原始分布如何，数据规模和频次语义是什么 |
| 逐项策略过程 | 每次规则前后双面板：本批分布、累计分布 | 每个新增限定具体改变了什么 |
| 动态策略时间线 | 注册区间×规则启用矩阵，含 hold 与阻断表版本 | 哪一批用了什么策略，为什么变化 |
| 历史反馈 | 预测累计分布与实际分布偏差、热点质量变化 | 是否真正学习了前批分布 |
| 均匀程度 | 累计碰撞率、Top-K 占比、熵/有效支持随注册人数变化 | 整体是否更分散 |
| 攻击难度 | F/A0/A1 cracked@K、G_q、截断平均排名 | 自适应后是否仍然更难猜 |

逐项分布图必须有规则前后、同批无策略对照、累计人数、完成率和统一坐标。按排名重新排序的曲线看集中度；追踪同一热点是否减少另用稳定标识的热点图，不混淆两种横轴。

页面用批次滑块或下拉选择查看快照，正式报告导出全套图。维持现有网页和 Streamlit 共用结果 schema 与绘图器，不各自重算指标。图像文件和图下数据同时保存，下载不包含原始泄露口令。

## 11. 对照与消融：验证动态机制的增量

所有实验臂使用同一 100,000 人、相同注册顺序、响应机制和攻击条件。

| 实验臂 | 设置 | 用途 |
| --- | --- | --- |
| B0 无策略 | 原口令保持 | baseline |
| B1 固定长度 | 全程长度 8；补充其他开发选定长度 | 常见轻量对照 |
| B2 固定复杂度 | 开发阶段冻结的长度+类别组合 | 传统复杂度对照 |
| B3 静态最优 | 同候选池、同开发数据及成本约束选一次后固定 | 判断动态是否胜过一次性选择 |
| B4 固定加严日程 | 提前固定每批规则，不学习历史分布 | 区分动态反馈与单纯加严 |
| D 完整动态 | 历史累计分布+安全+成本约束 | 主方法 |
| A1 去掉累计反馈 | 仅优化预测下一批分布 | 验证历史累计项的作用 |
| A2 去掉分布选择 | 同候选库与资源预算，仅按风险/成本选 | 验证分布模块是否有增量 |
| A3 去掉后期成本约束 | 允许规则持续加严 | 量化成本约束代价 |

B4 的日程在开发轨迹上冻结，不从正式 D 轨迹抄答案。可增加“将动态最终规则从第一批起实施”的事后解释组，但必须标注 hindsight，不能当作公平静态基线。

主实验先冻结一个响应情景；再对保守修补、混合、重选及放弃参数做敏感性。除随机注册顺序，增加模拟弱口令先到、弱口令后到、分布漂移顺序，明确这些不是恢复的真实时间线。

单次轨迹内各用户共享历史反馈，不能把十万人简单视为相互独立来产生过窄置信区间。报告各随机轨迹结果及差异范围；对控制器总体收益的不确定性，需重采样并重跑完整注册轨迹。固定策略轨迹下的逐用户配对区间只解释条件结果，二者分开。

## 13. 性能设计与实施顺序

不能对每条用户运行一百万次猜测。正确方式是每个攻击模型先生成共享有序流，再一次性匹配整批/累计目标并查询各预算点。原始生成成本与验证预算分别累计。

候选策略阶段先做历史/开发分布与成本筛选，再对少量候选做攻击验证。共享同一训练/策略/知识版本下的流；缓存键必须包含训练数据、规则版本、响应、知识和配置哈希。与目标相关的匹配结果不反向进入生成器。百万字符串缓存需用流式或磁盘索引管理，不能同时永久保留所有候选×批次×模型×情景的 Python 字典。

| 阶段 | 内容 | 验收产物 |
| --- | --- | --- |
| P0 协议冻结 | 固定角色、时间因果、候选池、指标、预算和成本选择方式 | 动态协议与 schema、开发预实验清单 |
| P1 数据与 baseline | 100,000 人、10 批、稳定身份与频次守恒 | 全体/逐批/累计 baseline，顺序与数据哈希 |
| P2 规则与响应 | 兼容检查、R3、逐用户事件、单规则快照 | 小规模可手核例子；成本与合规完整 |
| P3 动态控制 | 只读历史、累计目标、保持策略、成本上限 | 10 轮完整轨迹和策略选择理由 |
| P4 攻击与个体指标 | 按策略版本攻击、百万预算、共同参考流、删失状态 | 完整预算证据及逐用户提升状态 |
| P5 页面与报告 | 全套图表、批次交互、共享数据源 | 两界面一致、图表可导出 |
| P6 开发与冻结 | 资源预实验、阈值/响应参数冻结 | dynamic_full 配置及正式实验计划 |
| P7 正式实验 | 5 种子、预注册对照、响应/顺序敏感性 | 如实报告收益、退化、无解及不确定性 |

开发分三级：先用微型手工数据验证逻辑，再用 1,000–5,000 人和较小预算排查性能，最后运行 100,000 人及 1,000,000 预算。小实验不能替代正式规模验收；运行耗时需通过本机预实验估计，不预先承诺分钟数。

## 14. 验收标准

### 14.1 正确性必须满足

- 100,000 个注册身份唯一，批次人数、原始频次和完成/失败/放弃状态守恒。
- 替换未来批次内容，不改变此前策略和攻击训练产物。
- 更改正式目标排名或匹配结果，不改变候选流生成。
- 每批只适用其公布策略，老用户不被最新规则追溯改写。
- 所有成功注册口令通过本批完整策略；失败不得当作安全提升。
- 相同原口令的不同用户可独立修改，相同种子可以重现。
- 每项新增限制都有本批与累计分布快照，反事实前缀成本不累加为真实成本。
- 碰撞率在全相同、全唯一、已知计数三类手算样例中正确；跨样本量比较配套同人数对照。
- 猜测计费、重复/过滤、耗尽/截断、联合预算和策略版本在所有模型一致。
- 原口令不能因不符合新策略而在个体参考评估中被排除。
- 个体百分比正确处理负值、未命中、相同字符串和资源中断。
- 页面、JSON、文字报告与导出图使用同一结果数据；小规模人工例和百万流计费例均可追溯。

### 14.2 效果只能据实报告

支持主要创新需要：在成本可比的静态与固定日程对照下，动态方案的累计分布集中度降低，同时在独立 A1 攻击下具有可重复的安全收益，后期用户成本仍处于冻结边界内。

若只是分布图变平但攻击未改善，只支持分布改善；若收益仅存在于随机重选情景，必须限定响应假设；若后期成本过高，需呈现取舍；若动态不优于静态，应报告未获支持。项目完成的标准是实验完整、指标诚实、结果可复现，不是预设一定得到正结果。

## 15. 推荐实施范围

第一版集中完成单语料 100,000 人、10 批、一个主响应情景、四类现有攻击器、常见规则主候选池，以及逐规则/逐批图表。保留现有静态开放实验作对照，不同时扩张 19 站和更多神经攻击器。

先完成“可追踪注册流 + R3 + 逐规则分布快照”，再加入动态选择和百万攻击。这一顺序能最早核验用户成本与分布变化是否真实来自同一批用户，也避免在身份和反馈尚不可靠时花大量时间跑高预算结果。
