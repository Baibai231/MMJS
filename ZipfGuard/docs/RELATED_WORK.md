# 相关工作与创新边界

Xiao 和 Zeng 的 HTPG 用 Zipf 曲率划分头尾，再用信息增益比给特征排序，然后对头部口令给建议。本项目把它保留为基线，不把它的 69%、25% 或 80.23% 写进自己的成果栏。这三项来自论文里不同的实验。

Segreti 等人在 SOUPS 2017 提出用自适应策略迫使口令分布更散。那是策略会随已有口令改变的先例。本项目不声称第一次做动态口令策略。

NIST SP 800-63B 的现行口径是：单因素口令至少 15 个字符，多因素场景里可以是 8 个字符，不强制字符类别混合，并拒绝已知的常见口令整串。字符类别混合只作为历史对照。

PCFG 按结构概率生成猜测。OMEN 按变阶马尔可夫的概率分箱枚举。本仓库的开放序号修正针对 PCFG。固定阶束搜索马尔可夫写明不是 OMEN，两者的 `cracked@B` 不混在一个协议里。

PassLLM / Zou 等人用大模型做口令猜测。本项目没有接入，界面和报告都标成未参与。没有接入不能用来论证“用了人工智能所以有创新”。

本项目把新颖性限制在一件事：候选建议已经由论文特征给出之后，在固定离线预算、模拟修改成本和自适应攻击下选择建议，并在同一批用户上报告收益和失败。如果以后找到更接近的工作，缩小这句声明，不改写前人的时间。
