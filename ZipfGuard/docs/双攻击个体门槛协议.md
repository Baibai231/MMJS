# 双攻击个体门槛与等通知成本协议

修订日期：2026 年 10 月 8 日。协议：`selective-intervention-v9-dual-individual-threshold`。

## 目的与模型

Wasserstein-1 距离继续用于选择需要分散的账户群体。后续被通知账户的新口令必须通过固定 PCFG 与马尔可夫 OMEN 的个体检查；不再以整批攻击曲线面积下降作为准入条件。修改后达到门槛不等于每个人相对旧口令都严格变强。

复用项目已有的作者版 [RUB-SysSec/OMEN](https://github.com/RUB-SysSec/OMEN)，原研究为 Dürmuth 等的 *OMEN: Faster Password Guessing Using an Ordered Markov Enumerator*（ESSoS 2015）。使用 stdout 无目标反馈模式、三阶模型、开发训练样本内的可打印 ASCII 字符（不含空格）、长度 3—19。PCFG 使用既有 lakiw/pcfg_cracker 纯语法生成，关闭内置 OMEN 混合。两种模型只接收独立开发训练记录。发布报告记录源码及二进制哈希；若本地源码包没有 Git 元数据，明确记录无法核实提交号，不把外层项目提交号冒充上游提交号。

不使用项目旧的束搜索马尔可夫替代程序。OMEN 可以组合未在训练中完整出现的口令结构，但仍有字符、长度和训练覆盖限制，不等于全口令空间攻击。

## 猜测次数与联合曲线

新协议使用实际生成的有序候选前缀，替代当前干预协议中的 PCFG 蒙特卡洛点排名。保留 PCFG、OMEN、二者命中并集三类曲线，分别在固定 F 和独立参考迁移后重训的 A1 下评价。

横轴 B 表示每模型前 B 次原始尝试。模型内重复输出仍占用尝试次数；不按评价目标过滤、压缩或重编号。联合攻击使用两份前缀，最多消耗 2B 次尝试；两个模型命中同一账户时只计一次。报告另记联合不同候选数，不能把联合曲线冒称为总共只有 B 次猜测。对原始未改组，A1 与 F 相同。

若前缀生成超时或异常退出，流程失败，不能把未完成的尾部记成零命中。模型正常耗尽时明确记录实际次数；在这个有限攻击模型下已查完全部可生成候选。候选明文、训练数据及私有缓存只存本地忽略目录，不进入公开报告。

## 个体门槛

正式预设取 B = 1,000,000。新口令必须不同于旧口令、满足分配规则和至少 8 字符下限，且在两模型前缀中均未命中。新口令若同时位于两个模型声明支持范围之外则拒绝，不能通过生成极长或模型外字符的方式取得达标记录。

先按既有三类响应生成提案；未通过规则或攻击检查的提案重新选择。达到常规尝试上限后显式构造合规候选，使用开发字符集和受支持长度，并继续执行相同攻击检查。构造有固定次数上限；不能构造时方案不下发、不记通知，记录失败原因。显式构造是一项模拟假设，必须报告补全次数、被拒候选次数与编辑成本，不能沿用“攻击盲自然响应”的说法。三种局部方法使用同一响应机制。

参考 [Florêncio、Herley 与 van Oorschot（LISA 2014）](https://www.usenix.org/system/files/conference/lisa14/lisa14-paper-florencio.pdf) 的在线猜测讨论，将一百万次作为实验门槛。论文同时讨论了不同的离线攻击数量级；本实验不能把一百万次称为普适或离线安全保证。

在固定 F 下，旧口令预算内命中、新口令未命中且有范围内验证时，可确定其跨越本实验门槛。新旧都未命中时只报告“均超过测试预算、具体大小无法比较”。A1 重新训练后可能猜中达标口令，必须独立披露，不能靠 F 的检查推断 A1 安全。

## 公平比较

统一称“8 字符基础规则”，不称完整 Google 策略。四个基础规则组使用同一份迁移后的账户状态。基础迁移只强制长度合规，费用单列；个体双攻击门槛适用于之后的局部修改。

先运行动态组，用其实际逐轮通知人数作为随机组与初始排序组的预算。随机组先从剩余账户抽取相同人数，再比较局部规则；初始排序组按照共同起点的完整口令频次一次规划，各批预留不同账户，后续不使用已修改分布重新选人。两组对照为完成等成本预算可以接受 W1 不下降的批次，但个体攻击检查不可放宽。动态组仍要求预计 W1 改善。

所有被通知账户均完成不同的新口令，后续每账户至多通知一次。若某个对照无法执行相同人数，则报告不匹配，不将其终态按等成本排名。独立参考群体按同样公开选择方式和干预比例重放，不使用目标账户新口令训练 A1。

Yahoo! JAPAN 从原始账户独立执行全站规则迁移，只在独立面板展示，不混入局部干预排名。历史实验仍保留原协议和原始数值，不能给旧轨迹加上新攻击达标结论。

## 运行

在 ZipfGuard 目录执行：

```powershell
.\.venv\Scripts\python.exe tools\run_intervention_study.py --preset intervention_smoke --output-dir reports/dual_attack_validation
.\.venv\Scripts\python.exe tools\run_published_intervention.py --preset intervention_full
```

Windows 复用已安装的 Ubuntu-20.04 WSL 运行作者版 OMEN。预设快速验证为 1,000 账户，仍使用每模型一百万次攻击预算；全量为十万账户。攻击缓存包含训练数据哈希、模型参数、源码/二进制哈希及生成预算，可重复使用，不随评价目标调整。全量新结果需重新运行，不接续旧 PCFG 单模型轨迹。

## 本机验证记录

2026 年 10 月 8 日，完成真实语料的 1,000 账户局部验证，开发参考出现记录为 3,000，种子为 42，实验编号 `3f7532b6a69a4b26`。本次独立配置关闭 Yahoo! 全站对照；Yahoo! 的另一份验证单独运行。公开汇总与核验文件位于本机 `reports/dual_attack_validation_local/`，展示入口为 <http://127.0.0.1:8770/intervention/validation>。

动态、随机、初始排序三组各实际通知 5 人、成功修改 5 人，所有新口令均通过两模型各一百万次门槛。动态组在下一轮因没有可靠的分布正收益动作停止。原始账户中 PCFG 命中 82 人，OMEN 命中 125 人，联合命中 169 人；两份前缀分别实际生成一百万次尝试，联合计费二百万次。

该结果用于核验模型互补、人数守恒、个体门槛、独立 A1 与网页功能，不用于十万账户结论或方法排名。网站主页仍读取已发布的历史全量快照。浏览器核验工具 `tools/verify_dual_intervention_ui.py` 读取已保存报告，检查六类攻击图、SVG 接口、图例开关和报告下载，不启动新实验。
