> 版本：2026-09-24。工作基线：`MMJS/ZipfGuard/`。网站分类项目退出本次参赛范围。

> 2026-09-25 状态：论文基线、开放序号、合成同预算对照、消融、配对下界、MAYA 聚合迁移、报告和演示稿已经落在 `docs/` 与 `experiments/`。比赛通知、论文 OMEN、PassLLM、真实用户研究和第二台机器复跑仍然没有。这些空项不能勾成完成。

## 0. 目标与完成标准

作品主线：**复现论文 HTPG 的核心方法，再验证“面向攻击预算、兼顾用户成本的个性化口令建议”是否优于论文的特征排序。**

```mermaid
flowchart LR
    A[来源明确的数据] --> B[论文 Zipf 拟合与曲率头尾划分]
    B --> C[论文 IGR 特征排序与逐口令建议]
    C --> D[预算和成本感知的新方法]
    D --> E[统一猜测预算下的对照实验]
    E --> F[统计结果、局限、可复现演示]
```

最终必须同时满足：

1. 论文方法能**独立运行**，RockYou 关键数值可核对。
2. 新方法与论文方法使用同一数据划分、攻击器、预算定义和测试人群。
3. 开放生成攻击的空间外猜测保留原始序号，不会筛掉后重新编号。
4. 至少存在一个独立于当前 576 项合成语法的验证场景。
5. 同时报告安全收益、用户成本、自适应攻击与不确定性。
6. 主要数字可由配置重跑；导出的结果不含真实口令。

优先级定义：**P0 必须完成**；**P1 建议完成**；**P2 有余力再做**。P0 缺失时，不把相关实验数字作为最终防御结论。

## 3. 阶段 1：复现论文 HTPG 基线（预计 5～8 人日）

### R1.1 全量频数读取与论文预处理｜P0，依赖 Z0.4

- [ ] 流式解析“频数 + 口令”，统计无效行、空值、编码异常、频数排序和总质量。
- [ ] 调查本地总频数 32,603,388 与论文 32,510,281 的差异；保存排查方法与结论。
- [ ] 保留全量频数统计；top-k 分析必须同时报告被截断的质量，不得把重新归一化结果标成全量分布。
- [ ] 真实数据特征处理在受控本地流程完成，只输出聚合特征统计。

**验收：**有 `RockYou` 处理报告；总频数差异得到解释或明确标为未解差异。

### R1.2 论文 Zipf 回归与曲率 `x₀`｜P0，依赖 R1.1

- [ ] 单独实现论文口径：使用频数 `>3` 的口令，做 `log f_r = log C - α log r` 回归。
- [ ] 对 `f(r)=C/r^α` 求最大曲率点，产出 `C`、`α`、`x₀`、HeadSet/TailSet 规模和头部频数质量。
- [ ] 与现有 `core/distributions.py` 的模型拟合、`q` 累计质量风险排名分开命名、分开展示。
- [ ] 记录曲率峰在整数排名上的取整方式、拟合频率门槛与预处理版本。

**硬验收：**RockYou 前 1,171 名频数和为 **3,899,108**；`α` 保留三位为 **0.914**；`x₀` 与论文差约一名的原因被如实记载，不能硬编码 1,171。

### R1.3 九类论文特征｜P0，依赖 R1.2

- [ ] 实现 LSD structure、Length、Capital、Date、Keyboard、Specplace、Lowercase、WordType、Lastname。
- [ ] 对类别型特征定义编码；对 Unicode、中文、空值和过长口令定义行为。
- [ ] WordType、Lastname 等词典依赖特征明确实际词表、语言范围和版本；不能以别的规则悄悄替代。
- [ ] 做少量人工可核的样例和边界测试，不将真实口令写入测试输出。

**验收：**九项特征均有定义、实现、版本与可核示例。

### R1.4 Information Gain Ratio（IGR）排序｜P0，依赖 R1.3

- [ ] 基于头/尾标签计算每项特征的 `IG/IV`，处理 `IV=0` 和缺失值。
- [ ] 预先确定“每个不同口令等权”还是“按账户频数加权”；论文描述不足时，两种均做敏感性对照，但主口径事先指定。
- [ ] 在开发数据计算排序；测试数据不得用于调特征、调阈值。

**验收：**输出九项得分、排序、权重口径和计算版本；小型构造数据可以手工核对。

### R1.5 Dynamic Policy Generator｜P0，依赖 R1.4

- [ ] 只为 HeadSet 内口令生成建议；尾部口令返回空建议。
- [ ] 比较输入口令特征与头、尾特征统计，按论文算法及 IGR 输出有序建议。
- [ ] 定义类别型特征的距离；检测冲突建议并固定处理方式。论文版与改进版的冲突处理分别记录。
- [ ] 输出解释：命中哪个头部条件、当前特征值、推荐变化、排序依据。

**验收：**相同输入与配置得到相同结果；头部、尾部和冲突三个场景都有核验。

### R1.6 论文迭代实验｜P1；如声称复现“动态”机制则为 P0

- [ ] 分别运行 1、2、5、10 轮；每轮重新计算频数、`C/α/x₀`、IGR 与策略。
- [ ] 把论文的“半数不改、其余采用两项建议”的响应方式标为论文模拟条件，不称为实测用户采用率。
- [ ] 记录每轮头部质量、最高频数、攻击曲线、修改人数和总人数守恒。

**验收：**每轮状态和变化可追溯；没有通过删除被拒用户制造安全收益。

## 4. 阶段 2：重建可信的攻击评测（预计 6～9 人日）

### E2.1 威胁模型与预算定义｜P0，依赖 Z0.1

- [ ] 区分在线限速猜测与离线数据库泄露猜测；为二者分别设预算，不把 `10^8` 解释成在线登录次数。
- [ ] 定义攻击者知道的策略、训练语料和用户响应信息；分别设冻结与自适应攻击。
- [ ] 定义指标分母：账户数还是不同口令数、头部还是全体；所有图表写明。
- [ ] 预先规定重复猜测、无效输出、超时和未覆盖口令如何计数。

**验收：**每张攻击图表有数据、攻击者知识、原始预算和分母四项说明。

### E2.2 分离“封闭排序”和“开放生成”｜P0，依赖 E2.1

- [ ] 封闭排序：所有模型对同一预注册候选集打分，比较排序能力。
- [ ] 开放生成：保存 PCFG/OMEN 原始输出序号；空间外候选同样占预算。
- [ ] 改 `ai/pcfg_adapter.py` 和 `core/metrics.py`，禁止“生成后过滤、过滤后重新编号”进入开放实验。
- [ ] 保留原始生成数、去重数、有效数、命中数和覆盖率，避免把匹配数叫生成数。

**硬验收：**输出序列若为“空间外 A → 空间外 B → 目标口令”，目标原始排名为 **3**，不是 1。

### E2.3 对照攻击器｜P0，依赖 E2.2

- [ ] 保留 Frequency、字符 n-gram 控制组与 PCFG；补论文所用 OMEN，或清楚标注 Markov 替代与论文的不一致。
- [ ] 每模型固定代码版本、训练集、参数选择集、生成上限、随机种子和运行资源。
- [ ] 必选模型失败则该实验失败；可选模型失败则标明未参与，所有比较保持相同攻击器集合。
- [ ] 最终报告中区分论文协议与新增模型协议，不混合不同预算语义的 `cracked@B`。

**验收：**攻击器横向表可以直接核对同一预算点，模型实际参与状态可查。

### E2.4 两套数据协议｜P0，依赖 R1.1

- [ ] 建“论文口径复现”协议，用于解释与原文数值的异同。
- [ ] 建“严格评测”协议：开发集估计分布与策略，validation 选参数，test 在方案冻结后使用一次。
- [ ] 防止同一用户及其口令变体跨集合泄漏；跨站训练不能偷用目标站点测试信息。
- [ ] 本地仅有 RockYou 时，不声称已经完成论文的六数据集跨站数值复现。

**验收：**能够逐项回答每个模型、策略看过哪些数据。

### E2.5 打破合成循环｜P0，依赖 E2.1

- [ ] 将数据生成器、公开候选来源和字典排序方法分开。
- [ ] 至少设计 Zipf、混合/长尾、开放未知结构三种场景；再测年份后缀、键盘模式占比变化。
- [ ] 选择不在主预算前饱和的空间；预算超过支持集时清楚标注饱和。
- [ ] 防守训练与攻击训练使用独立种子、独立数据角色。

**验收：**不利用生成器原始顺序，仍可完成基线评测；主预算点未被 576 项空间上限决定。

### E2.6 独立外部验证｜P0，数据条件允许时执行

- [ ] 寻找至少一个与 RockYou 独立、来源明确、用途允许的研究数据集。
- [ ] 区分“只有频数可验证分布”与“有受控明文可验证特征策略”。
- [ ] 提供不同语言、站点、时间的失败与迁移结果，不能只展示有效站点。

**验收：**至少有一组未用于设计方法的数据结果。若无法取得合适数据，最终范围收窄为机制复现与合成实验，不声称真实跨站防御效果。

## 5. 阶段 3：创新方法（预计 4～7 人日）

### I3.1 固定创新命题｜P0，依赖 R1.5、E2.1

核心问题：**在相同攻击预算和用户成本约束下，按实际风险收益排序建议，能否比论文 IGR 特征排序更有效、更稳定？**

- [ ] 将论文 IGR 保留为候选建议来源和必备基线。
- [ ] 新方法在 validation 上估计建议造成的 `cracked@B` 变化、用户成本及不确定性；最终测试评估整个策略后的总体风险。
- [ ] 多人采用同一建议会改变总体分布，因此不能把每个口令的局部收益直接相加当总收益。
- [ ] 写一页相关工作对照：论文 HTPG、已有 adaptive policy、现代认证指南、PCFG/OMEN、PassLLM。

**验收：**一句话能说清论文方法、新方法和验证新方法的主实验。

### I3.2 预算/攻击者/成本感知策略评分｜P0，依赖 I3.1、E2.3

- [ ] 固定预算 `B`，在同一验证集上测策略执行前后 `cracked@B`。
- [ ] 分别报告每个攻击器，并按预注册方式计算最坏攻击者风险。
- [ ] 纳入修改率、尝试次数、放弃率、记忆负担情景；保留现有固定追加与短语回退作为**一种模拟情景**。
- [ ] 让论文 IGR 排序与新评分排序使用相同候选建议、用户、攻击器和预算。
- [ ] 现有全局 Pareto 搜索扩展为可比较的逐口令建议策略；控制计算代价，优先只评头部候选并缓存重复场景。

**验收：**可一键切换论文版和新增版；新方法在测试集只评价冻结后的方案。

### I3.3 分布与模型不确定性｜P1

- [ ] 分布模型接近时展示风险预测范围，不选择最乐观模型当唯一真值。
- [ ] 测小样本、分布迁移、攻击者重新训练时的推荐稳定性。
- [ ] 对证据不足的建议显示不确定，避免虚假的精确数值。

**验收：**能说明在哪些条件下推荐改变、收益消失或成本过高。

### I3.4 现代规则基线｜P0，依赖 E2.4

- [ ] 加“最低长度 + 常见/泄露口令完整字符串 blocklist + 可操作反馈”对照组。
- [ ] 将字符类别强制规则标成传统历史对照，而不是默认部署建议；区分强制拒绝与可选指导。
- [ ] 分开单因素与 MFA 场景。若按 NIST SP 800-63B 设计部署基线，单因素密码最低 15 字符，MFA 中可为最低 8 字符，不强制字符类别混合。

**验收：**新方法至少与论文 HTPG 及现代基线同条件比较；若没有超过，如实报告。

### I3.5 PassLLM/RFGuess 等额外红队｜P2

- [ ] 在论文基线和开放预算协议稳定之后，再接神经或机器学习攻击器。
- [ ] 固定 checkpoint、prompt、解码、生成限制和模型版本；不接入则一直标“未参与”。
- [ ] 新攻击器用于检验策略迁移，不作为“已使用 AI 因此有创新”的论据。

**验收：**有真实生成次数、绝对预算曲线和可重复配置；不能静默回退并保留原模型标签。

## 6. 阶段 4：实验与统计证据（预计 5～8 人日）

### X4.1 冻结主要对照组｜P0

1. 无新策略。
2. 传统复杂度规则（历史对照）。
3. 长度与 blocklist 的现代基线。
4. 论文 HTPG：Zipf 曲率 + IGR + 动态建议。
5. ZipfGuard 新方法：同一候选建议下的预算/成本/自适应攻击感知选择。

**验收：**五组共享同一数据划分、预算与攻击器；头部和全体结果分报。

### X4.2 预注册指标｜P0

- [ ] 主指标为测试集 `cracked@B` 的**绝对百分点差**；相对下降单独计算，不能混写。
- [ ] 安全指标包括头部质量、最高频数、多预算曲线、冻结/自适应风险。
- [ ] 用户指标包括修改率、初始接受率、完成率、平均尝试次数；没有真实研究时不报告实测记忆率。
- [ ] 工程指标包括扫描时长、推荐延迟、攻击时长和峰值内存。
- [ ] 在看测试结果前固定主预算、主攻击集合和主要比较对象。

**验收：**每张图都能说明样本量、分母、预算、攻击器和结果来源。
