本文档对照当前双端源码和Overleaf中的2.2整理。现在只安排截图与章节内容，收到截图后再改报告正文。


当前截图将使用1000账户模拟站点：原8个演示账户保留，新增992个合成历史账户。总览展示本次五轮、100人实际通知、80人完成和20人待处理。原有2项任务保留，累计区为82完成／102已分配。统计图取最新1000账户快照，保留合成模拟与含噪估计标识；任务图以启动器登录的待处理模拟账户为准。具体设置见[1000用户模拟站点实验说明](1000用户模拟站点_实验说明.md)。

| 2.2.1 双端系统组成与运行流程 | 管理员网站、用户浏览器插件、业务后端和三个计算方分别做什么；两端独立，通过后端交换公开要求、本人任务和受保护汇总 | 把三个研究方案接成可使用的系统，让读者先理解整体 | 图01和图05；保留已有交互示意图 |

| 2.2.3 管理员制定注册要求 | 设置基础要求；按快照选择结构和完整口令匿名位置；剔除已被结构覆盖的热点；版本、回退与自动候选保持 | 把统计信息转成实际注册和改密限制，用户可以在插件中检查 | 图03 |

| 2.2.5 用户选取口令与完成账户操作 | 本地公开检查与本站私密检查的分工；注册、登录、历史账户接入；本地恢复凭证 | 给出能理解的修改提示，同时让网站完成认证而无需接收明文 | 图05和图06 |
| 2.2.6 用户改密与管理员查看完成情况 | 本人任务、旧口令验证、新口令检查；成功后替换凭据和统计贡献；管理员只查看必要状态 | 任务完成来自实际改密，形成反馈流程 | 图07和图08 |
| 2.2.7 网站接入、权限与运行管理 | 一次性挑战与三方签名证明；管理员角色；后台作业、原请求查询与受控重试 | 说明合作网站如何接入，以及系统如何处理权限和等待 | 可选图09至图11 |

## 二、先截这8张核心图

每张保留页面标题及选中的侧边栏入口。红框最多2至3个，集中圈功能区，避免把整个页面圈起来。保存没有红框的原图与标记图两份。

### 图01：管理员运行总览

- **入口：** 管理员 → 运行总览。
- **准备：** 点击右上角“刷新”，看到三个计算方就绪后截图。账户数、版本和预算按实际页面保留，不必凑成固定数字。
- **红框①：** “当前注册要求”卡片，包括长度、规则和版本。
- **红框②：** “真实任务进度”卡片，包括已完成／已分配和解释文字。
- **红框③：** “独立计算服务”中的三个就绪状态。
- **正文用途：** 展示管理员可以统一查看策略、执行进度和运行状态。已参与账户与两类预算在正文顺带解释。
- **取景：** 如全页过长，滚动后截两张重叠的原图；后续裁切拼排，不要为了容纳全部内容把字体缩得很小。

### 图02：受保护统计

- **入口：** 管理员 → 受保护画像。
- **准备：** 直接使用已有快照。为截图不用再点“联合计算并发布”或“独立确认发布”，避免额外等待和消耗预算。
- **红框①：** “热门结构的估计人数”中的结构标签和人数条形图。
- **红框②：** “结构内匿名频次”的表头及数据，尤其“结构”和“名次1／2／3”。
- **红框③：** 快照编号、分母、ε及“含噪估计”说明。
- **正文用途：** 解释结构集中程度和完整口令重复程度如何被管理员查看，以及为什么图中没有对应口令字符串。
- **取景：** 优先截两块统计卡片；顶部发布区不是这张图的重点。

### 图03：完整口令与字符结构联合限制

- **入口：** 管理员 → 注册动态策略 → 向下滚到“快照联合阻断 · 管理员手动制定”。
- **准备：** 可以勾选一个结构，再在另一个结构行勾选一个匿名名次，形成待提交的配置。图中应保留“管理员手动制定”和确认说明。仅为截图无需点击“应用实际联合阻断”。
- **红框①：** “结构限制（固定公开目录）”及所选结构。
- **红框②：** “完整口令热点（只显示匿名名次）”及所选位置。
- **红框③：** 被选结构所在行禁用的热点框，连同“避免重复占用名额”的说明。
- **正文用途：** 说明管理员不用看明文，也能把结构与匿名热门口令组合成限制；已被结构覆盖的热点不重复计入。
- **取景：** 保留卡片标题。不要只截数字和勾选框，以免看不出配置含义。
- **补充原图：** 再截上方“基础要求”和“完整口令与结构联合候选”区域，便于正文解释长度设置、自动候选及回退。是否放入论文，收到图片后决定。

### 图04：已有账户的分批改密安排

- **入口：** 管理员 → 存量分布调整。
- **准备：** 如已有画像，可点击“比较18类整改要求”，显示“候选估计”。这一比较使用已有统计，不需要发布新画像。仅截图不要点击分配按钮。
- **红框①：** “本轮分配上限”和“累计分配上限”。
- **红框②：** “候选估计”中的要求、违反人数估计及“等待真实改密反馈”。
- **红框③：** “批准并分配整改任务”的规则选择区及“在预算内分配本人任务”按钮。
- **正文用途：** 说明管理员如何选要求、控制规模，并由三方确认资格后安排任务。覆盖人数是含噪估计，未来攻击收益不能从页面数字直接得出。
- **取景：** 页面较长可分上、下两张原图，后续组成同一幅图；每张不必重复侧边栏。

### 图05：用户选取口令与检查反馈

- **入口：** 用户插件 → 口令助手。
- **准备：** 输入合成示例12345678，点击“本地检查”，出现红色反馈后截图。这张不注册账户、不修改策略。
- **红框①：** “本地检查”和“检查本站私密要求”两个按钮。
- **红框②：** 红色反馈中的具体修改原因。
- **红框③：** 右侧“本站当前要求”及策略版本。
- **正文用途：** 解释本地检查即时提示长度、弱口令或连续序列问题；本站私密检查由三方执行隐藏规则。公开规则和隐藏检查分工不同。
- **取景：** 保留两列内容和页面标题；口令输入维持掩码，不用打开明文。

### 图06：用户注册或私密登录

- **入口：** 优先用户插件 → 注册账户；若不想新增账户，则用私密登录成功的画面替代，并在文件名写清。
- **准备：** 若注册，使用一个未占用的合成账户标识，例如paper-demo-1012，以及满足当前要求的测试口令。可先在助手检查。页面出现“操作完成”后，停留在当前页截图。若存在联合限制，测试口令能否通过以实际检查为准。
- **红框①：** 顶部“操作完成”状态。
- **红框②：** “私密注册”或“私密登录”按钮及账户标识。
- **红框③：** “你的口令去了哪里”的说明卡片。
- **正文用途：** 说明用户在独立插件中输入，插件分别发送份额，认证和规则检查不通过网站明文表单进行。
- **取景：** 成功后口令框自动清空是正常行为，不要为了截图再次填入口令。恢复凭证只截说明区，不展开文件内容。

### 图07：用户的本人改密任务

- **入口：** 用户插件 → 我的任务。
- **准备：** 先确认当前登录账户是谁，再点“刷新”。优先截已有任务；“待处理”或“已完成”均可以，正文按实际状态说明。
- **红框①：** “待处理／已完成”状态。
- **红框②：** 任务要求，例如最低长度。
- **红框③：** “修改口令并处理任务”按钮及“失败不算完成”的说明。
- **正文用途：** 说明用户只处理本人的任务，改密要同时满足本站要求和本人任务。
- **补充原图：** 点击“修改口令并处理任务”，截“当前口令—新口令—再次输入新口令”和“确认改密”区域；可以保持输入为空，不必为截图再次改密。
- **没有任务时：** 不把空任务页面当作已完成示例。先把图01至图06发来，再安排一个专门的合成账户任务；不要为了凑截图反复给已有账户分配任务。

### 图08：管理员查看同一账户的实际任务状态

- **入口：** 管理员 → 账户与任务。
- **准备：** 点“刷新”，按图07中的同一账户标识筛选。
- **红框①：** 该账户行中的账户标识、版本和任务状态。
- **红框②：** “没有逐账户结构”说明及完整表头。
- **正文用途：** 与图07对应，解释管理员能跟踪任务结果，却不能在账户表中查看用户口令或个人结构。
- **注意：** 若图07显示待处理，这张也应显示待处理；只有真实改密成功后才截成“已完成”。这组截图用于说明运行流程，不以截图代替第三章的隐私证明。

### 图10：后台作业

## 四、截图前后怎样操作

1. 双击项目中的“打开可操作展示.cmd”，使用已配置的专用浏览器。
2. 先截管理员总览、统计、策略配置和分配配置；这些图多数只需要查看或勾选，不需要真正应用。
3. 再截用户检查和账户操作。只有你决定注册／改密并真实成功时，才把成功结果作为图中状态。
4. 最后截同一账户的用户任务和管理员状态，形成能够对应的流程。
5. 账户、任务、策略版本与统计快照按页面实际值保留。新注册或改密不会自动把旧统计快照变成最新数据。

统一使用PNG。尽量保持同一浏览器缩放比例；以输入框、表头和文字清楚为准，不建议把整条长网页缩成一张很小的图。每张图最多2至3个细红框，必要时加①②③，后续由报告文字解释编号。

建议命名：01-管理员总览.png、02-受保护统计.png、03-联合限制.png、04-分批改密.png、05-用户选取检查.png、06-用户注册或登录.png、07-本人任务.png、08-管理员账户状态.png。原图后缀写“-原图”，标记图后缀写“-红框”。页面过长可加a、b。

## 五、写报告时必须保持一致的说明

- 两个工具是管理员网站和用户浏览器插件。接入样例是合作网站的演示。
- 两端没有直接交换页面数据或共享登录会话；必要业务信息经过后端传递。
- 管理员看到匿名频次和结构汇总，不获得匿名名次对应的真实口令字符串，也不查看逐账户结构。
- 当前工具实际支持完整口令与整类结构联合阻断；结构内选择性规则尚未接入在线工具，不把3.2离线改进版的效果写成工具实际取得的效果。
- 缺少用户重选和成本依据时自动候选保持；管理员手动应用规则是另一条流程。
- 本地提示是公开规则检查，不是PCFG／OMEN攻击排名。私密检查通过也不是“绝对安全”。
- 注册和改密成功后更新当前秘密状态；已发布画像是含噪快照，新人口需要另行发布，不能宣称自动实时展示。
- 同机三进程展示说明运行可行性；实际隐私条件需要可信客户端、独立计算方及相应安全模型。
- 2.2说明构成、流程、界面和价值。性能结果及安全论证留在第三章。
