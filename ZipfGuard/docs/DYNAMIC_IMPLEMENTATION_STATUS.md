# 分批注册动态实验实施状态

日期：2026-09-29。旧协议已完成五种子 100,000 人、每模型 1,000,000 次猜测主实验及四类固定策略的同规模攻击对照；历史数字不代表当前协议。

## 当前口令修改协议

动态实验改用 `visible-first-hidden-retry-v2`，不模拟用户放弃或将重试耗尽解释为注册失败：

- 长度、字符类别等显式要求由构造算法在提交前一次满足；原口令已合规则保持原样。
- 黑名单和启用的模式限制只在提交后检查。实际命中时继续生成候选，不额外设置随机阻断概率；模式规则默认仍为可选。
- 连续 8 次新候选未通过触发报告但不终止。每人 1,000 次为计算保护上限，达到后仍未通过则保留原始身份、原口令及重试计数，标记为待处理。不能把缺失的最终口令编造成成功，也不能把它计入最终口令的攻击分母。
- 隐藏阻断后的修补、片段重组、重选权重是固定候选生成算法的参数，不是用户放弃概率。攻击训练样本若存在待处理项，停止并报告，不静默删除样本。
- 最终分布面板及导出图使用完整频数—排名双对数曲线，策略前后采用同一批用户。无法校验本机完整结果时明确标记仅有头部数据。

网页明确标识旧报告。下文多种子及敏感性数字均属于旧协议，保留用于历史追溯，须重新运行才能评价当前设定。

## 当前展示与对照协议：一个固定预设、三种攻击层次

用户选定固定预设为“长度至少 8”。协议更新为 `fixed-preset-three-attacks-v2`：固定方案从首批到末批始终使用这一规则；动态方案首批使用同一规则，之后才根据历史反馈选择加严动作。无策略保留所有原口令。此前的字符类别、开发集预选规则和固定加严日程不再运行或作为当前图例。

最终分布、各批累计分布、碰撞概率、修改成本和风险—成本图统一使用无策略、动态策略、固定预设策略三个方案。预算攻击图展示三方案各自的 F、A0、A1，共九个可独立选择的图例；页面不再展示逐注册阶段的冻结攻击板块，也不展示“相同完成用户原口令”重复曲线。该配对数据仍保留在内部报告，用于追溯和旧汇总兼容。

F 使用原始开发数据的共同冻结流；A0 按各用户注册时的规则过滤该流；A1 在独立开发数据上模拟对应方案的口令修改后重新训练。无策略没有规则过滤，开发口令也不改变，所以 F、A0、A1 在当前定义下完全相同，复用同一评价结果。固定预设的 F 和 A0 已实际计算，不从动态方案复制。A0 的高预算若因冻结流过滤后数量不足而未完成，仍报告区间，不能画成零或冒充完成。

该协议已完成种子 42 的十万人验收，输出目录为 `reports/dynamic/fixed_preset_three_attacks_100k_seed42/`，耗时 163.190 秒，全部 100,000 人完成注册。百万预算下，无策略 F/A0/A1 均为 30.131%；动态 F 为 5.793%、A1 为 8.035%；固定预设 F 为 7.419%、A1 为 9.905%。动态和固定预设的 A0 高预算仍有未完成项。30 条逐阶段完整分布均通过人数守恒检查，固定方案十批规则一致，首批与动态方案分布完全相同。浏览器验证了九个独立选择框、悬停和键盘突出，以及三方案分布与阶段切换。新旧对照协议不能混合做多种子汇总。

核查发现：开发集固定规则在首批前进行三步选择，最终从一开始使用一万条开发热点黑名单；动态方案从长度 8 起步，逐批增加历史热点，最终黑名单为 376 条。动态方案保留早期口令，且只按下一批预测碰撞率贪心选择，没有优化整个十批轨迹，也没有直接以 A1 命中率作目标。注册顺序由同源样本随机产生，未设置随时间改变的口令偏好，因此不能预设在线反馈必然优于预先选好的固定规则。

该历史版本将 3,000 条预览直接与历史频数合并，实际批次为 10,000 人；预览没有按实际批次大小重新加权。当前版本已完成上述起始策略、成本约束和批次预测改造。历史差距不能单独归因于预测近似，仍需通过独立验证和多种子比较检验动态反馈的增益。

成本图只画每批修改率。待处理人数为零时不绘制零线；存在待处理记录时显示异常提示，并保留逐批报告。

## 已接入的流程

1. 对带频次语料扫描两次，从全文件的不同出现位置抽取注册流和开发参考数据。固定种子产生模拟注册顺序；每条出现记录建立独立用户身份。
2. 第一批用最小长度 8；之后控制器读取已完成批次的累计分布，预测候选规则的累计碰撞概率，在预览无待处理用户、修改率和头部风险代理限制内选择下一批规则或保持原策略。规则单调累积，不追溯修改旧用户。
3. 逐用户记录显式修正、隐藏规则阻断、重试报告及计算上限内的待处理状态。实际注册只执行最终策略；新增规则前后图属于从同批原始口令出发的反事实快照，不重复累计用户成本。
4. 最终用现有开放猜测器计算 F、A0、A1 与对照。F 固定原始开发训练，A0 将固定候选流按各批策略投影，A1 从按真实策略时间线模拟的独立开发响应中训练。A0 暂未实现针对策略重新生成候选，A1 使用整条轨迹的全局训练分布。
5. 同一不按新策略过滤的 A1 参考流计算逐用户修改前后猜测排名。精确、下界、上界、未决与未完成注册分开保存；公开报告不包含口令字符串。
6. 命令行生成 JSON、HTML 与 SVG；本地网页 `/dynamic` 和 Streamlit 展示批次、分布、成本、攻击曲线与用户提升状态。

## 历史验证证据（旧协议）

用真实 `rockyou-withcount.txt` 运行 `dynamic_smoke`：300 名模拟用户，另抽 300 条开发参考出现记录，三批各 100 人，最高猜测预算每模型 1,000。结果保存在 `reports/dynamic/ed1b6a03c847cad2/`，该目录不进入版本控制。结果生成时的配置版本早于 2026-09-29 新增的“相对第一批成本上限”和猜测次数汇总字段，不能把旧报告当作新版本的完整验收。

该快速实验首批最小长度 8，后两批都保持规则。原始累计同口令碰撞估计约 0.000111；模拟策略后为 0。完成注册 298/300，另外两人未完成。预算 1,000 时 F 与 A1 的 Min_auto 命中均为 13/298；三百人的结果不支持百万预算或动态优于静态的结论。

另用高重复人工数据放宽成本边界验证选择器会更新：三个批次的策略依次为长度 8、增加历史热点阻断、再扩展历史热点阻断；累计碰撞率从约 0.1679 降为 0.0154。这仅验证机制，不是现实效果证据。

十万人规模的资源预检使用同一真实语料、种子 42 和十批注册，先以每模型 1,000 次猜测、仅频次和字典攻击完成整条轨迹。动态策略在第 2、3、4、5、8 批新增历史热点阻断，其余批次维持已有规则；最终 98,635 人完成注册。全体原始口令的碰撞概率约 0.0001235，动态完成用户的碰撞概率约 0.00000176。这一对比的分母不同，因此新报告另外保存“相同完成用户的原口令”分布作为配对对照。预检报告位于 `reports/dynamic/preflight_100k/`；它生成于新增配对对照字段之前，不作为配对结论。

随后在同一数据与策略设定下，频次、字典变形和字符 n-gram 完成每模型 100,000 次预算的预检，报告位于 `reports/dynamic/preflight_100k_guess/`。字符 n-gram 的自适应流实际完成 100,000 次有效猜测，约用 23 秒生成；A1 Min_auto 在已完成注册用户中的命中率约 9.92%，F 约 9.06%。该预检整次运行约 124 秒。它仍不能代替百万预算，也没有计算全部静态对照臂的 A1 攻击。

单种子百万预算主实验已完成，报告位于 `reports/dynamic/million_primary/`。频次和字典流完整耗尽，字符 n-gram 的 A1 流达到 1,000,000 次有效猜测；F 和 A1 的 Min_auto@1,000,000 均有完整状态。98,635 名完成用户的原口令在 F 下命中 29.83%，修改后口令在 A1 下命中 10.98%；达到 10% 命中率的预算分别为 900 和 126,675。相同完成用户的原口令每百万对同口令数估计为 120.87，动态策略后为 1.76。该运行没有计算四个固定对照臂的百万预算 A1，因此只能支持“相对无策略有变化”，不能证明动态反馈优于成本相近的固定策略。A0 在百万预算下因固定流投影后的有效候选不足而未完成，其风险只能报告区间。

| 预定长度加严日程 | 97,637 | 70.15% | 4.11 | 5.76% |

这些是各方案完成用户上的描述性比例，完成用户集合不完全相同；同用户配对差见下段。动态方案的分布集中度最低且修改率略低于“开发集固定规则”，但其 A1 命中率高约 2.45 个百分点。因此单种子结果没有支持“动态反馈在相近成本下同时使分布和攻击风险优于静态规则”的强主张。固定复杂度和固定加严的 A1 更低，但明显增加修改率；后者完成率低于 98%。

共同完成用户的配对百万预算重跑位于 `reports/dynamic/million_paired_seed42/`。动态方案减固定方案的 A1 命中率差为：固定长度 8 为 −2.00 个百分点（98,635 人），开发集固定规则为 +2.40 个百分点（98,567 人），固定复杂度为 +3.97 个百分点（97,999 人），固定加严日程为 +5.16 个百分点（97,616 人）。这些差值的条件 95% 区间保存在报告里，只反映固定攻击流和选定策略下的用户配对差异，不覆盖其他随机注册顺序或重新训练造成的波动。由此可以确认：在该种子上，动态反馈优于固定长度 8 的攻击风险，但不优于成本相近的开发集固定规则。

五种子正式主实验的种子为 11、23、42、67、101；每个种子各抽取 100,000 名注册用户与互不重叠的 100,000 条开发出现记录，按 10 批注册。每条轨迹的频次和字典攻击器正常耗尽，字符 n-gram 在自适应 A1 流中达到每模型 1,000,000 次有效猜测。自动审计后生成的[五种子汇总](../reports/dynamic/multiseed_primary/cross_seed_report.html)、[机器可读摘要](../reports/dynamic/multiseed_primary/cross_seed_summary.json)和三张独立 SVG 位于忽略版本控制的本机报告目录。以下为五条轨迹的描述性均值与范围，不是总体置信区间：

| 指标 | 五种子均值 | 范围 |
| --- | ---: | ---: |
| 完成注册率 | 98.64% | 98.61%–98.66% |
| 原始用户中的修改率 | 50.50% | 50.26%–50.66% |
| 相同完成用户的原口令同口令数／百万对 | 111.37 | 102.92–120.87 |
| 动态口令同口令数／百万对 | 1.67 | 1.54–1.76 |
| 相同完成用户原口令在冻结 F 下的百万预算命中率 | 29.97% | 29.79%–30.21% |
| 动态口令在自适应 A1 下的百万预算命中率 | 10.88% | 10.65%–11.10% |
| 10% 命中所需猜测数：原口令 F | 886 | 841–935 |
| 10% 命中所需猜测数：动态 A1 | 164,417 | 112,222–222,244 |

最后一批相对第一批的用户修改率增加 2.44–3.76 个百分点；五条轨迹中单批最低完成率为 98.40%–98.50%。最后一批已修改用户的编辑距离 P90 均为 21，说明部分用户在此响应模型下付出较大修改成本，不能只看平均修改率。

逐用户私有文件为每个注册身份记录精确百分比或相应状态与界限。五条轨迹中各有 548–603 人（原始用户的 0.55%–0.60%）在修改前后均被共同攻击流命中，因而能计算精确的猜测排名提升百分比；更多用户只有提升下界、退化上界或双方都超过百万预算。未修改者的“修改本身提升”为 0，放弃或失败者不适用。不能给未知排名填上 1,000,001 来冒充每条口令都有精确百分比。

上述原口令 F 与动态 A1 使用不同攻击训练条件，其差值不能单独归因于口令策略；同一原口令在冻结 F 下和同一动态口令在自适应 A1 下各自是完整的百万预算结果。判断动态反馈是否优于固定策略，应以下面的同用户配对 A1 对照为准。

固定策略的其余四个种子也已完成；连同种子 42，审计后的[五种子固定对照报告](../reports/dynamic/multiseed_controls/cross_seed_controls_report.html)及[机器可读结果](../reports/dynamic/multiseed_controls/cross_seed_controls.json)位于本机忽略版本控制的报告目录。所有对照的字符 n-gram 均达到百万有效猜测；下表为“动态减固定”的同用户配对 A1 命中率差，正数表示动态口令更容易被猜中，均值与范围仅描述五条模拟轨迹：

| 固定对照 | 平均命中率差（百分点） | 五种子范围（百分点） | 动态命中率更低的种子数 |
| --- | ---: | ---: | ---: |
| 固定长度 8 | −2.01 | −2.11 至 −1.86 | 5/5 |
| 固定长度 8 + 两类字符 | +3.90 | +3.73 至 +4.10 | 0/5 |
| 开发集预选固定规则 | +1.97 | +0.39 至 +2.50 | 0/5 |
| 固定长度加严日程 | +5.11 | +4.94 至 +5.37 | 0/5 |

动态方案相对开发集预选固定规则，在五个种子的各自完成用户分布中都具有更低的同口令碰撞率（每百万对少 0.19–0.85）且在原始用户中修改率低 0.59–1.74 个百分点，但自适应攻击命中率更高。相对固定长度 8，动态的攻击风险与碰撞率都降低，但修改率高约 2.06–2.19 个百分点。因此目前不能宣称“相近成本下动态反馈同时改善分布与攻击抵抗”。各单种子的条件 95% 区间只适用于固定攻击流与策略，不合并为跨种子区间。

另以同一抽取样本做六种顺序／响应压力测试：5,000 名注册用户、5,000 条独立开发出现记录、每批 500 人、每模型最高 10,000 次有效猜测。报告位于 `reports/dynamic/sensitivity_5k/sensitivity_report.html`；所有情景的三个攻击器在最高预算点均可完整评价。弱口令先到／后到按开发训练频次排序，仅为模拟极端顺序。结果如下，不能代替十万人百万预算主实验：

| 情景 | 完成用户 | 修改率 | 同口令数／百万对 | A1 命中率 @10,000 |
| --- | ---: | ---: | ---: | ---: |
| 主响应、随机顺序 | 4,929 | 49.12% | 6.18 | 3.23% |
| 弱口令先到 | 4,931 | 48.38% | 13.16 | 6.12% |
| 弱口令后到 | 4,928 | 48.82% | 9.47 | 6.21% |
| 偏向修补 | 4,928 | 48.90% | 4.78 | 3.08% |
| 偏向从常见池重新选择 | 4,899 | 48.38% | 51.84 | 26.33% |
| 高放弃率 | 4,696 | 44.26% | 5.81 | 5.66% |

“偏向重新选择”仍比该情景相同完成用户原口令的约 70.68 次／百万对更分散，但自适应攻击命中率远高于主响应情景。这说明碰撞率下降和猜测风险下降不能互相替代。高放弃率情景改变了完成用户集合，不能把低碰撞率直接解释成无代价的安全收益。

`tests/test_dynamic_registration.py` 覆盖手算碰撞率、单调候选、未完成攻击流的提升状态、未来批次不改变先前规则，以及公开报告不含测试口令。完整项目回归状态以实际最新测试运行为准。

## 后续验证范围

- 对控制器本身做去累计反馈、去安全代理和去后期成本约束消融，再按完整注册轨迹重新估计不确定性；目前五种子固定规则对照已经证实分布与攻击风险存在取舍。
- 完整预设由频次、字典变形和字符 n-gram 参与主比较；PCFG 当前上游适配器原始输出上限恰为 1,000,000，过滤/重复后通常不能证明完成 1,000,000 次有效猜测，留在较低预算敏感性实验。
- 扩大顺序和用户响应敏感性到更多随机种子及正式预算；当前 5,000 人压力测试已显示对重新选择行为的明显脆弱性，不能假定主响应结论对真实用户稳健。
- A0 目前是固定流的合法候选排名投影，A1 是开发响应池的全局模型；若要模拟按批次条件化重训或更强的策略知识攻击，需再增加独立实验组。

逐用户私有结果会包含泄露口令明文，仅放在已忽略版本控制的本地报告目录；分享时使用公开报告和图，不直接复制私有结果文件。
