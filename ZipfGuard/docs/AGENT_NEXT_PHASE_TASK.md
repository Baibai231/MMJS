## T06. 在原场景中定义一个主优化方法｜P1｜依赖 T05 的可信最小版本

### 推荐主假设

> 在保持 HTPG 头尾框架和建议动作空间的前提下，依据验证场景中的有限预算攻击风险，联合选择至多两条建议，并受修改成本约束，可能比只按 IGR 排序取得更好的安全—成本权衡。

这是假设，不是已验证的创新；R4 支持把响应与策略诱导分布纳入问题定义，R5 支持检查修改后的集中模式，R6 支持避免对单一攻击模型过拟合。

### 实施步骤

1. 将待选对象明确为有顺序的建议组合 `π`，保持每用户最多两条，与基线一致。
2. 从同一候选建议集合构造单项、两项组合及不修改选项；通过现有执行器检查目标与冲突。
3. 在允许的验证数据上评价执行后的分布和攻击风险；优化用的攻击器实例不能偷用最终测试命中信息。
4. 成本主约束选用户修改率，补报归一化编辑距离、长度变化和失败率。它们不是实测记忆成本。
5. 优先采用可解释的约束形式：在 `C(π) ≤ c` 下最小化预定攻击风险；避免仅靠随意改 λ 产生看似优势。
6. 小规模动作集合先用枚举或简单 beam search，并与单项排序比较；不在没有必要时引入大模型。
7. 预算 B 作为输入。固定选择预算后的多预算曲线与“每个预算重新选择策略”分别命名。
8. 记录每个未选方案的风险、成本、冲突和无法执行原因，防止只保留最佳输出。

### 可用的形式化定义

`R_a,B(π)`：在已声明响应模型下，执行策略 π 后，被攻击器 a 在 B 次猜测内猜中的受评用户质量比例。

`C(π)`：相同受评人群的修改比例，或预先指定的另一个成本度量。

初版可比较：`argmin R_a,B(π), subject to C(π) ≤ c`；随后验证 `argmin max_a R_a,B(π)` 的多攻击器版本。每个攻击器各有 B 次预算时，这个最大值表示最坏单攻击器，不是总预算 B 的联合攻击。

**不声称：**该求解器全局最优、有理论保证，或是首次提出预算／成本优化。需结合实际算法与相关文献确认差异。

**交付：**方法说明、可配置实现、伪代码、复杂度与决策解释、开发结果。

## T07. 公平比较与有意义的消融｜P0｜依赖 T06

- 所有方法相同的无效运行处理，不丢不利种子。

### 最小消融集合

- 单项预算排序 → 联合组合搜索。
- 无成本约束 → 有成本约束，并报告两者实际负担。
- 单攻击器选择 → 多攻击器选择。
- 响应模型固定时比较策略；响应变化作为独立实验因素。
