# 工具验收脚本说明

脚本只用于专用本机安装中的合成数据验收。它们会注册账户、修改策略、消耗隐私和任务预算；故障脚本还会停止一个测试计算进程。不要连接真实用户服务。

这些是具有先后依赖的验收脚本，不是随时重复运行的无状态测试。原始证据见 `reports/tool_acceptance/`。部分脚本固定使用本次的账户及人口快照；复现不同数据时应重新生成快照并调整对应标识，不能复制旧画像充当新的计算结果。

## 依赖与顺序

完成安装并启动服务后，用 `client.py` 创建烟雾账户，再用 `browser_check.py` 登记QA负责人。浏览器检查另需Playwright及兼容Chromium，其浏览器路径需要改为本机实际路径。它使用隔离配置及虚拟认证器。

长时间测试前重新执行浏览器检查以取得有效管理会话。基础API验收、规则验收、任务故障、安全及迁移检查随后进行，再测确认画像、联合策略和会话重放。最后做审计、打包并停用QA身份。

| 脚本 | 用途及特定依赖 |
| --- | --- |
| `client.py` | 合成客户端拆分口令；直接执行创建 `integration-smoke` |
| `browser_check.py` | 管理员通行密钥、9页、扩展登录及站点签名核验；需烟雾账户和安装邀请或QA认证器 |
| `acceptance.py` | 基础真实链路与后台作业；需QA管理会话 |
| `complete_acceptance.py` | 本次原画像作业的恢复和后续验收；依赖先前作业及账户 |
| `rules_check.py` / `rule_party.py` | 18类规则，分别启动三个真实测试电路；每方只读自己的份额 |
| `task_fault_checks.py` | 真实整改、共同决定后单方退出与重启恢复；需QA管理会话 |
| `security_checks.py` | 非法输入、限额、高水位备份及明文扫描；会产生只提交一方的限额请求 |
| `migration_checks.py` | 历史迁移授权、现有凭据不能覆盖、删除再注册的会话边界 |
| `measure_profile.py` | 真正独立确认发布，消耗预算并记录等待时间 |
| `joint_policy_checks.py` | 使用本次固定确认快照，实际联合阻断及整改；会修改烟雾账户口令 |
| `session_checks.py` | 上一步改密后的烟雾账户，验证回执复用和退出后不可重签 |
| `control_checks.py` | 隔离队列与调度逻辑，使用测试健康响应，不能视为MPC发布成功 |

## 审计和交付

`ops/audit_acceptance.py` 汇总原始记录，保留已恢复超时，编译源码、检查Markdown、在隔离目录验证本机证书签发并扫描测试明文。它不重新运行昂贵的三方实验。

`ops/build_delivery.py` 生成两端应用、完整源码及验收证据包，排除运行私钥、数据库和依赖目录。`ops/new_installation_invitation.py --disable-test-identities` 停用QA身份并生成单次负责人邀请；邀请仅保存在本机私有目录。
