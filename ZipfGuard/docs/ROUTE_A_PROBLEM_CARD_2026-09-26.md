# 路线 A 研究问题卡

这是待执行的设计，不是已完成的实验，也不是“首次提出”。`claim_supported` 为否。

| 字段 | 内容 |
| --- | --- |
| 场景 | 审计方只使用一个站点的训练出现次数和预先冻结的攻击预算。攻击方是已经跑完的频次、PCFG、OMEN 等无测试反馈模型。测试频次和测试命中不能用来选阈值。 |
| 问题 | 当口令的相对频次规律大致不变、只是整体条数变化时，HTPG 曲率切分是否会改变要干预的头部；换成验证集选定的累计质量阈值后，有限预算下的命中召回是否更高，且干预规模没有不可接受地变大。 |
| 现有方法 | HTPG 曲率切分（IEEE TIFS 2022）。累计质量阈值是简单基线，不是新模型。Hou 与 Wang 已经比较过包括 stretched exponential 在内的口令分布，不能把换分布本身当成这条路线的创新。 |
| 新内容 | 还没有新算法。候选只包括原曲率、固定头部比例和训练侧累计质量。选择只发生在验证集。 |
| 预期机制 | 连续公式在固定 α 和支持域时，频数乘 k 会使曲率峰按 k^(1/(α+1)) 移动。这是公式推导。frequency>3、α 重估、取整和并列名次是否同样移动，还没有跨站实验。 |
| 对照 | 原曲率、固定比例、相近头部规模、相同干预质量。不能只和放大后的头部比。 |
| 主指标 | 验证集上，预先声明的攻击器和预算下，头部捕获的已命中 occurrence，除以该攻击器的命中数。同时报告头部覆盖的 occurrence 和不同字符串数。分母为 0 时记为不可定义，不写成完美召回。 |
| 失败条件 | 优势只来自更大的头部；固定比例基线就能解释；某个攻击器的召回明显变差；没见过的字符串上失效；或者还没做留出站点就宣称成立。 |
| 资源 | 开发只用已经重算的小站和现有 1000 预算。确认站不能再用已经反复查看的 hak5 和 twitter 当作未见数据。10^4 以上预算另做资源试验。 |
| 交付 | 选择日志、对照表和失败站点。当前还没有这些实验结果。 |
