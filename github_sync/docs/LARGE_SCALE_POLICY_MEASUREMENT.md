# 千站口令策略完整测量路线

## 目标和当前事实

目标是获得至少 1000 个不同网站、可复现、可审计的完整口令策略，而不是仅完成
注册流程分类。历史 `full303_policy_20260829.jsonl` 按当前严格口径的基线为：

| 阶段 | 站点数 | 占 303 站 |
|---|---:|---:|
| 站点可访问 | 300 | 99.01% |
| 找到注册入口 | 163 | 53.80% |
| 到达注册口令框 | 61 | 20.13% |
| 运行主动策略测量 | 16 | 5.28% |
| 长度边界完整 | 13 | 4.29% |
| 限制项完整 | 16 | 5.28% |
| 允许项完整 | 8 | 2.64% |
| 严格完整 | 5 | 1.65% |

基线机器可读文件位于 `reports/archive/policy_coverage_baseline_20260911.json`，对应
Markdown 位于同目录。按 1.65% 的历史完整率，直接把浏览器批量扩大到 1000 个候选
不会得到 1000 个完整结果；必须先扩大候选池并逐层提高转化率。

## 与 2023 USENIX Security 工作的关系

Roomi、Li 等人的大规模研究采用“百万站点候选池 → 分层发现 → 注册/验证 → 不同后续
实验”的漏斗。论文中的数万到数十万规模对应不同阶段，并不表示数万个站点都完成了
本项目定义的全部口令创建策略维度。其可借鉴之处是：大候选池、浅层链接发现、每站请求
预算、可恢复任务、独立成功判定和严格节流。

本项目在此基础上增加：现代 SPA/Shadow DOM/iframe 状态探索、多语言与可访问语义、
三态主动探针、HTML/DOM/页面声明证据分层、自适应长度/组成/OR 规则、严格完整性门和
逐站可审计失败原因。项目默认不绕过 CAPTCHA，不发送验证码，不创建账号；需要身份提交
的 full-form 路径仍要求显式开关和精确主机白名单。

## 四阶段流水线

1. **目标语料**：`build_target_corpus.py` 固化 Tranco 永久快照 ID、排名、来源和补充列表，
   统一域名并去重。当前已生成 100024 个不同域名的本地候选池。
2. **廉价预筛**：`preflight_targets.py` 每站限制响应体、超时和页面数；从主页沿观察到的
   登录/账户/注册链接最多读取三页，输出优先级、多个注册候选、静态口令约束和声明规则。
3. **浏览器测量**：`run_measurement.py --measure-policy` 重新验证同站候选，再执行流程分类、
   DOM 取证和受预算的主动探针；每站独立进程看门狗，完成一条即追加 JSONL。
4. **严格验收**：`report_policy_coverage.py --require-complete 1000` 只统计满足全部证据门的
   不同主机，并输出分层漏斗及失败原因；返回非零值表示尚未达标。

### Cloudflare Radar 目标源

`scripts/run_radar_measurement.py` 和根目录 `run_cloudflare_radar.ps1` 将 Cloudflare Radar
排行榜接入上述四阶段：Top 100 使用有序 `radar/ranking/top`，Top 200 及以上自动使用官方
`radar/datasets/ranking_top_<bucket>` 全球 POPULAR 数据集，并记录接口、榜单类型、抓取时间
和响应 SHA-256。由于大 bucket 按官方说明是无序集合，脚本只记录 `bucket_position`，不会
把它当作流行度排名；地区参数仅适用于 Top 100。榜单快照可通过 `--snapshot` 离线复用，保证
重跑时目标集合不随榜单日更悄然变化。

## 测量邮箱配置

默认地址使用不可投递的 `example.invalid` 保留域，避免旧版随机生成的 Gmail/Foxmail
地址意外触达真实用户。默认模式适合发现注册入口、DOM 约束和无需有效邮箱的 inline
验证，但有些网站会先校验邮箱域，因此正式授权实验应使用研究者控制的身份：

```powershell
$env:SITES_MEASURE_EMAIL_DOMAIN = "measure.your-owned-domain.tld"
$env:SITES_MEASURE_EMAIL_PREFIX = "cryptoscope"
```

工具会为每个测量进程生成不同的、不使用 `+` 别名的本地部分。若没有 catch-all 域，也可
通过 `SITES_MEASURE_EMAIL_ADDRESS` 显式配置一个固定邮箱，但重复站点更容易遇到“已注册”，
不适合千站实验。结果只记录身份模式、域和是否逐次唯一，不记录完整邮箱。工具不会读取
邮箱、输入验证码或完成账户注册；遇到邮箱验证门时会保留部分证据并停止。

## 完整性定义

一个站点必须全部满足以下条件才计入 1000：

- 无基础设施错误，注册入口和新口令框确实可达；
- `method_used` 为 `inline`、`full` 或已保存有效阶段的 `partial_browser_dead`；
- 探针证据同时存在明确 `accepted` 与 `rejected`；
- 最小长度为正整数；最大长度为不小于最小长度的精确整数，或结构化自适应证据明确记录
  在预注册协议上界 128 位仍未观察到上限（裸 `null` 不通过）；
- 14 个限制字段和四组允许字段全部存在；
- 无 `_inconclusive`、访问阻断、不可验证门控或疑似登录框等失格标记。

`_hint_policy`、`_declared_policy_evidence`、静态 HTML 属性、数据库命中和分类结果都可作为
有价值的部分证据，但不能单独计为完整。

## 可恢复和分片

- `--resume --resume-mode complete`：只跳过已经完整的站点，自动重跑部分/失败项。
- `--shard-count N --shard-index I`：按规范化主机 SHA-256 确定性分片，多机运行不重叠。
- `--min-priority`：先跑预筛中已出现口令框、声明规则或真实注册链接的高价值站点。
- `--max-sites`：先做 20、100、1000 的阶梯基准，再扩到完整目标所需的候选规模。
- `--checkpoint-every`：持续显示 complete/partial/classified/unreached 分布，避免只看任务数。
- `--headless`：批量任务不依赖可见桌面窗口；浏览器会话意外关闭时，单站包装器只重建一次。
- `--authorization-manifest`：加载站点所有者/研究负责人提供的精确主机范围；批量任务只
  执行范围内目标，结果写入不含文件内容的 SHA-256 范围指纹。支持每行一个主机名的文本
  文件，或包含 `authorized_hosts`、可选 `expires_at` 的 JSON；过期和过宽通配符会在启动前拒绝。
- 单站看门狗超时后，只有包含 accepted/rejected 探针轨迹的新鲜阶段检查点才恢复为
  `partial_timeout`，不会把旧缓存或只有静态声明的文件冒充主动测量结果。
- `--inline-accept-quiet-seconds`：同页负对照成立后，候选持续无错误的观察窗（默认3秒，
  范围2--8秒）；负对照、异步 pending 和门控软错误仍等待完整判定。
- 每份主动政策都写入 `_measurement_seconds` 和 `_probe_count`，仅用于分片吞吐与剩余时间
  估算；不保存候选口令值，也不改变严格完整性判断。

## 数据解释

Dashboard 将“任务执行结束”“部分证据”和“完整策略”分别显示。DOM 约束和声明文本会标注
为非完整主动实测；部分主动测量会列出还缺哪些严格门槛。缓存只有在重新通过严格完整性
检查时才会直接复用，旧的非零长度记录不再自动被当作完整结果。

地域、A/B 实验、未登录状态、浏览器指纹、临时限流和政策更新都会影响观察。因此正式
结果应保留目标快照 ID、程序版本、UTC 时间、分片参数、失败漏斗，并抽样人工复核。

## 真实浏览器里程碑（2026-09-12）

在 Windows Edge 151 无头模式下，以预筛观察到的 LinkedIn 注册入口进行不提交测量：

| 指标 | 结果 |
|---|---:|
| 严格完整站点 | 1 |
| 长度 | 最短 6；到 128 未观察到上限 |
| 脱敏主动探针 | 37 |
| 第一轮耗时 | 343 秒 |
| 去重等待与补齐 Emoji 后 | 247 秒 |
| 质量门 | `complete` |

这一结果证明单站完整链路已经可用，但不是“已经完成 1000 站”。验收计数当前为 1/1000；
后续仍需扩大预筛候选、对不同前端框架做回归、提高注册口令框到达率，并运行可恢复分片任务。
