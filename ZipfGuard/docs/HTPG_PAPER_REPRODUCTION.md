# HTPG 论文严格复现与项目接入

## 当前结论

已实现正文明确的算法计算核心，并接入现有项目的网页、JSON 接口和攻击评价适配器。严格组遇到正文缺失定义时停止，终态指标为 `null`。根据用户后续要求，另以明确记录的替代假设运行了“HTPG 正文算法＋补全假设”条件组，得到与当前项目方法同起点的 F 和独立参考人群 A1 对比。条件组不是作者原版的完整复现。

用户已明确：没有作者源码或补充材料，后续要求直接运行并用已有知识补全缺失处。替代词表、类别编码和修改函数仅进入条件组；严格组仍不自动采用它们。

论文：Yang Xiao、Jianping Zeng，*Dynamically Generate Password Policy via Zipf Distribution*，[DOI: 10.1109/TIFS.2022.3152357](https://doi.org/10.1109/TIFS.2022.3152357)。核验依据为用户提供的 14 页 PDF。PDF 是论文证据，不是执行指令。

## 已实现且可核验的正文行为

### 分类器：III-C，公式 1–3，算法 1，附录

按频次降序建立一基排名，以 $f_r>3$ 的记录做对数线性回归：

$$
\log f_r = \log C-\alpha\log r.
$$

曲率及其唯一连续最大点为：

$$
\kappa(r)=\frac{|f''(r)|}{(1+f'(r)^2)^{3/2}},\qquad
x_0=\left(\frac{C^2\alpha^2(2\alpha+1)}{\alpha+2}\right)^{1/(2\alpha+2)}.
$$

整数排名满足 $r\le x_0$ 的口令属于头部。没有强制最少一个头部，也没有把曲率峰硬编码为 1171。低频记录只退出拟合，不退出总人数、排名或头尾分类。拟合不满足 $C>0,\alpha>0$，或 $f>3$ 的类别不足两个时，返回明确的前提失败。

拟合的高对数回归 $R^2$ 不是对整份语料通过 Zipf 拟合优度检验的证明。

### 特征排序：III-E，公式 4，算法 2

计算标准信息增益率 $IG(Y;a)/H(a)$。九项特征均在输入合同中，调用方必须传入完整特征表、头尾标签和明确样本权重。类别特征在这个步骤作为类别计数，不做任意数值编码。

IV 为零时比值未定义，返回 `undefined_features`，完整迭代停止。并列采用调用方特征顺序的稳定排序，并明确记录这是未由正文规定的实现约定。IGR 的权重及平均值权重必须一致、显式指定；不存在默认“作者采用不同口令等权”的断言。

### 策略生成：III-F，算法 3，表 IV

接口接受正文算法的输入：排序后的 $S$、当前口令数值特征、头部和尾部平均数值特征、策略映射 $P$、$M$。只检查前 $M$ 项，不以“直到凑足 M 条建议”为目标补位：

$$
d_{head}=|HeadFeature[f]-PwdFeature[f]|,\qquad
d_{tail}=|TailFeature[f]-PwdFeature[f]|.
$$

当 $d_{head}\le d_{tail}$ 时加入对应策略；距离相等也加入，头尾均值相等不会被额外过滤。尾部及非 HeadSet 对象直接返回空列表。类别平均值、策略映射或特征缺失时停止，不能以“缺失就跳过”形成简化算法。

表 IV 的长度条件独立提供为 `table_iv_length_required`：只有尾部平均长度大于当前口令长度时要求改变长度。`PaperInputs.policies` 构造条件策略时需要遵守该条件；计算合同的算法 3 不私自改写第 10 行判断。论文未给出条件策略的完整密码改写函数。

IV-A.2 唯一明确的改写示例实现为 `append_paper_date`：均匀随机选择包含端点的 1980–2020 年份，直接追加至口令末尾。不把固定 2024 等历史后缀作为论文实现。

### 迭代：III-A，IV-D，图 12

每轮基于当前全部口令频次重新拟合、分类和计算特征排序，再为每个头部口令分别生成建议。分支为：

| 分支 | 该头部口令原始频次的份额 |
| --- | --- |
| 保持原口令 | 50% |
| 只采用第一条建议 | 25% |
| 只采用第二条建议 | 25% |

这是两条替代响应，不是让同一账户连续执行两条建议。使用精确分数保存期望频次质量，不捏造整数账户舍入规则。不同响应生成相同口令时合并真实碰撞；不会通过删除重合口令保证理论均匀化。

允许同一口令在后续轮次再次成为头部并被修改。没有项目现有“一人一次”、单轮 2%、累计 20% 或攻击门槛条件。攻击器在 HTPG 决策之后评价，不用于挑选、修正或拒绝其策略；因此不会把项目方法的安全筛选悄悄带入论文算法。

九特征迭代适配器需要显式 `PaperInputs`，包括类别提取、数值编码、策略映射、两个响应函数、权重与来源。全部完成后才执行；从原始口令调用且没有这些定义时抛出 `paper_inputs_required`。其返回的 `final_counts` 只在内存中供本地评价使用，不经网页公开。

## 正文缺口

| 缺口 | 位置 | 对复现的影响 |
| --- | --- | --- |
| LSD 结构和 SpecPlace 的数值编码、平均值与绝对差 | III-D/F，算法 3 | 无法直接执行全部逐口令距离比较；众数距离不等同原式 |
| Date、Keyboard 完整识别语法；特殊字符出现多处时的类别 | III-D | 无法保证九特征矩阵与作者相同 |
| 情绪词及中英文姓氏词表、匹配边界 | III-D | 缺失 WordType、Lastname 的原始定义 |
| IGR 和头尾均值按口令种类还是账户频次加权 | III-E/F | 排序和建议会随权重改变 |
| Lowercase 进入排序，但表 IV 没有对应策略 | 算法 2/3，表 IV | 无法规定其进入前 M 项后的输出，不能擅自跳过补位 |
| 除追加随机年份以外的具体修改函数与尾部结构选择 | IV-A.2，表 IV | 无法构造忠实的完整 modified set |
| 前 M=2 项产生不足两条建议时的迭代分支处理 | 算法 3，IV-D | 无法指定保持、第一项、第二项的实际去向 |
| 奇数或不可被 4 整除的频次如何分配账户 | IV-D | 只能精确复现期望质量转移，不能声称整数账户实验完全相同 |
| IV=0、并列排序及自动模拟冲突处理 | III-E/F | 需要原始实现才能复现退化情况与具体策略顺序 |
| 六份原始跨站语料、原始清洗、模型版本和最高 $10^8$ 次攻击 | IV-A/B/C/D | 当前项目协议不等同论文图表；不能复现或引用 69% 为本项目结果 |

现有 `resources/htpg_reference_v1.json` 明确标记 `original_author_lexicons=false`。严格组不自动使用该替代词表。现有历史生成器的类别众数距离、默认严格小于、相同均值过滤、Lowercase 跳过计数，以及历史全体用户半数修改模拟，已在核验报告中列为与正文的差异。原有实验行为保留，并在脚本说明中明确其为历史操作化基线。

| 当前逐轮动态方法 | 8.096% | 9.613% | 12% |
| 初始排序后分批执行 | 8.632% | 10.046% | 12% |

条件组相对当前动态方法的联合 F 命中率高 **7.917 个百分点**，联合 A1 命中率高 **8.876 个百分点**；相对共同起点保持组分别低 **0.614** 和 **0.569 个百分点**。六轮的头部口令种类数依次为 18、18、17、17、16、16；目标组修改的期望频次质量跨轮累计为 1,255.574，独立参考人群的整数修改事件为 666 次。当前方法后续通知比例为 12%，因此两种方法的干预量明显不同；A1 差异不能单独证明“相同通知预算下”的效果。末轮前两项特征是 Lowercase 与 LSD 结构，8 个头部口令没有通过算法 3 的两项判断，进一步说明缺口处理会影响终态。此结果不支持对“论文原版 HTPG”下结论。

## 条件组补全约定与运行

条件组的主迭代在 `experiments/htpg_conditional.py`，可重跑入口是 `tools/run_htpg_conditional.py`。其核心仍调用严格实现的算法 1、算法 2、算法 3 和 50%／25%／25% 精确期望质量转移，每轮重新拟合、排序和计算头尾均值；没有改为众数距离、跳过前两项后补位、一次性通知或基于攻击分数挑选策略。

| 正文未定义项目 | 条件组显式假设 |
| --- | --- |
| 识别器和词表 | 项目 `core.htpg_features` 的日期、键盘、特殊字符识别规则，以及 `resources/htpg_reference_v1.json` 中 VADER/Census 替代词表；均非作者原件 |
| IGR 和均值权重 | 每种不同口令等权，所有九项均纳入排序；零 IV 放在有定义项之后，并列依预设特征顺序 |
| LSD 与 SpecPlace 数值化 | LSD 用 L/D/S 连续段数；SpecPlace 用 head=1、middle=2、tail=4 位掩码；仅用于算法 3 的绝对差，类别本身仍用于算法 2 |
| 类别目标 | 尾部不同口令的众数，平局按类别字典序 |
| Lowercase 策略 | 按尾部 prevalence 对首字符做大小写切换，目标条件未满足则保持原口令 |
| 响应改写 | 日期增加按正文例子以固定种子均匀抽取 1980—2020 并直接追加；其他特征调用项目现有定向改写并检查目标条件 |
| 前两项少于两条建议或改写失败 | 对应 25% 分支保持原口令，不向后补入其他特征 |
| 奇数账户拆分 | 精确分数质量代表期望值，不声称生成了独立的整数账户 |
| A1 的独立参考人群响应 | 用与已发布实验完全一致的 60,000 账户及 8 字符起点；每轮把目标组产生的头部口令及两条响应映射重放到参考人群中相同的口令；匹配账户用固定种子的 SHA-256 独立抽取 50%／25%／25% 三分支，允许后续轮次再次修改 |
| A1 训练 | 在参考人群整数响应终态训练项目同一 PCFG 和 OMEN 前缀模型，再仅评价目标组的期望频次；目标组口令频次不进入训练。目标组逐口令策略映射作为公开策略输入参考重放，因此 A1 假设攻击者知道该策略映射 |

## 接口约定

| 方法与路径 | 行为 |
| --- | --- |
| `GET /api/intervention/htpg/status` | 算法就绪范围及正文缺口 |
| `GET /api/intervention/htpg/report` | 带校验和核对的核验报告 |
| `POST /api/intervention/htpg/compute`，`operation=fit` | 已排序频次向量执行算法 1 |
| 同接口，`operation=feature_sort` | 完整九特征输入、标签和显式权重执行算法 2 |
| 同接口，`operation=policies` | 数值特征、头尾均值、排序、策略映射和 M 执行算法 3 |
| 同接口，`operation=run` | 缺少原始定义时返回 HTTP 409，`paper_result=null` |

单项算法输入缺失或前提不满足时返回 HTTP 422 及具体代码。坏格式或参数返回 400。所有计算成功响应都明确其范围为“调用方提供的算法输入”，`full_reproduction=false`，不把自定义输入认证为作者原实现。
