# 第三板块补充：工具全流程的隐私可行性论证

**日期:** 2026-10-11。
**用途:** 补充[第三板块实验报告](第三板块_隐私保护口令统计与联合策略报告.md)，对照[双端前端计划](全新前端_用户端与网站端实施计划.md)说明完整工具怎样在不交付明文口令的前提下运行。已完成真实三方密码学小样本实验，以下区分可证明性质、实际原型证据和前端接入契约。

## 1. 先把保护对象说清楚

本方案保护的是**用户口令值及逐账户字符结构不被网站、管理员或单个计算方直接获得**。网站仍然需要知道哪个账户正在注册、登录或改密，也会知道操作成功与否、策略版本和任务是否完成。管理员可以查看差分隐私画像，以及经过权限控制的业务状态，不能查看完整热门口令名单、逐账户结构或确定性口令标签。

选定一个可以闭环的研究路线：可信客户端输入口令，三个独立计算方在多方安全计算（MPC）中完成认证、规则检查和统计。每方保存自己的秘密份额；同一个秘密变量贯穿三个环节。网站只接收有限结果。这样先论证功能能跑通，不需要假定 OPAQUE 已经替我们绑定了所有输入。

### 1.1 本轮安全模型

- 客户端代码及设备可信；直接向各计算方发送份额，使用经过认证的加密连接。网站提供的任意可变页面不能自动视作可信客户端，独立客户端或受控扩展需要独立分发。
- 使用三方、一次 Shamir 秘密分享，最多一个计算方受到被动腐化。被动表示按协议执行，但会记录它能看到的数据。
- 把网站、管理员及其控制的所有收集与计算服务算作**同一个腐化群组**。把三个进程开在同一管理员的机器上不能满足独立信任要求，只能用于实验。
- 公开账户标识、操作类型、策略版本、批次、随机请求标识、有限结果与通信时序；默认不隐藏账户关联、用户是否在线或操作次数。
- 隐藏口令和结构只通过批准功能使用，不开放任意比较接口。允许/拒绝与公共封包绑定令牌的重复关系都属于可观察信息。论证限定可信客户端及授权有限调用，不覆盖恶意客户端与腐化计算方联合实施不限次探测。

MPyC 可以支持这一被动安全、诚实多数的小规模研究路线 [1]。如果要抵抗计算方主动作弊、篡改或与另一方串通，本模型不能覆盖，需要改用与相应威胁一致的协议并重新检查组合，例如 MP-SPDZ 所支持的恶意安全后端 [2]。本轮的功能校验不能把被动安全升级为恶意安全。

## 2. 工具各环节如何接起来

| 工具环节 | 受保护处理与接口契约 | 网站或管理员得到什么 | 最小验证 |
| --- | --- | --- | --- |
| 助手与口令输入 | 客户端本地预检查；私密查询与本站注册相同受限通道 | 本地公开规则反馈，或有限查询结果 | 检查请求及日志没有口令、逐人结构、确定性标签 |
| 注册、登录、改密上传 | 固定16字节、128位编码，逐位秘密分享后通过双向认证 TLS 送至三方 | 账户、请求标识及状态；不得接收全部份额 | 单方只加载自己的份额；重构必须有超过一方信息 |
| 完整口令与结构统计 | MPC 中检查份额一致性和字节格式，从秘密字节推导 L/U/D/S 连续段，做相等性比较 | 不输出账户结构、秘密相等矩阵或真实频次 | 正确输入与畸形字节/份额的配对测试；结构与明文参考一致 |
| 画像与管理输出 | 私密构建结构条件频谱；固定队列、固定维度，加噪后发布 | 受保护结构人数与匿名频次、预算与版本 | 敏感度、输出字段和预算超限检查 |
| 隐藏联合规则 | 完整口令名单留在 MPC；检查字节是否命中隐藏集合及结构规则 | 通过/拒绝；公开规则可本地解释，隐藏拒绝只给合并提示 | 完整口令命中、仅结构命中、均未命中三类输入 |
| 认证与同口令绑定 | 登录时秘密相等；注册/改密时认证状态、政策与统计共用同一秘密输入 | 认证成功与操作结果，不返回对比中间值 | 政策检查用口令 A、试图认证或统计写入 B 时拒绝 |
| 注册及改密提交 | 成功提交才加入新贡献；改密先认证旧值，再原子撤销旧贡献并写入新值 | 提交结果与新账户版本 | 成功一次、重复请求、旧值错误、中途失败、并发冲突 |
| 存量整改 | 客户端参与时，在 MPC 检查其现有秘密口令是否符合群体条件 | 授权账户的最小任务资格/任务状态；不返回排名或口令 | 符合与不符合者、预算耗尽及重复领取 |
| 策略版本与失败回退 | 会话固定版本；入口在任何绑定计算之前鉴权及总限速，冲突 nonce 和拒绝也计入；业务检查再按操作限次 | 有限原因代码、保持/失败状态及令牌重复关系 | 版本变更、重放、所有封包调用超额度及业务次数/预算耗尽；全入口限制属于部署契约 |

当前原始明文 `accepts` 和 Counter 只能作为离线参考。工具接入时由上述 MPC 功能替代，不能把现有明文函数包装成网页接口就算完成。

## 3. 可证明的功能与隐私命题

### 命题一：单方份额不直接揭示口令位

口令编码为固定16个 ASCII 字节，不足处用零填充，共128位。在足够大的有限域中，对每一位 $b$，客户端独立取均匀随机 $a$，向第 $i$ 方发送 $y_i=b+ai$。任一单方看到的 $y_i$ 在域内均匀分布，不依赖 $b$。逐位独立随机化和固定长度避免单方份额直接还原口令或长度。

安全计算后续阶段依靠所选协议的隐私保证：该方的协议视图只揭示功能允许的输出。证明路线是秘密分享加安全计算的组合，而不是“看文件看不懂”。网络加密、操作系统隔离、可靠随机数及持久份额保护是这条路线的必要前提。

### 命题二：结构和统计不依赖用户自报标签

三方在 MPC 内检验各位一次多项式关系和二进制约束，再组合成字节，检验可打印 ASCII、最少8字节及连续零填充。随后从同一秘密字节计算类别与连续段结构。每个有效输入只对应一个秘密字节串和一份派生结构；用户另报错误结构不能改变派生结果。

原型用秘密随机线性组合验证约束，只打开组合是否为零。对固定非法输入，漏检概率至多有限域大小的倒数；这是统计健全性，不应写成绝无漏检的确定性检查。

这可以证明“各功能使用同一个有效输入”，不能证明受损客户端一定输入了用户本来想用的口令，也不替代主动安全协议的真实性保证。

### 命题三：隐藏热点可以被阻断而不公开字符串

秘密值间的相等性、字节分类、求和和比较都可表示为有限安全计算。对隐藏口令集合逐项相等、对结构集合逐项匹配，再组合得到一位结果，足以执行联合规则。集合规模与最大长度可以固定或填充；不输出匹配位置及精确人数。

因此“必须公开热门字符串才能执行阻断”并不成立。小规模协议实测验证功能正确性和具体成本；它不证明大规模网站已经达到可用吞吐量。允许/拒绝可成为字典查询信号，所以只能向授权会话提供有限次数检查。

### 命题四：认证、检查与统计采用同一输入可以避免换密绕过

注册或改密将一份秘密字节串 $[p]$ 同时用于规则条件 $P([p])$、新认证状态和统计更新；提交只有在这些条件同一会话全部满足时发生。不存在独立的“已经检查的口令字段”和“实际写入的口令字段”，因此不能先用 A 通过政策，再把 B 写入认证状态。

研究路线把认证定义为 MPC 内候选与秘密认证状态相等，结合 TLS、会话认证和在线猜测限速；这是有明确输入与输出的研究认证功能，**不是标准 PAKE，也不是 OPAQUE 实现**。若最终工具选用 OPAQUE，仍需另行构造政策—统计—凭据的组合绑定，不能沿用“同变量”证明去覆盖另一套独立协议。

### 命题五：成功一次、计数一次；失败不改变当前分布

维护带版本的秘密账户状态，每个活跃账户恰好贡献一次。提交包含账户版本和唯一请求标识。注册成功加一；改密成功对旧值减一、对新值加一；在同一原子事务中同时改变认证、统计及任务状态。重复标识返回原结果，旧版本失败，未提交状态不生效。

由状态归纳可得：初始计数与有效账户一致，每次合法事务保持一致，故改密不会不断累加已经不用的口令。本原型按当前活跃账户的秘密状态重新聚合，旧认证状态被替换后自然不再贡献。还实现了检查点的真实磁盘读取：恢复本方秘密份额、账户版本，以及请求、次数、预算和任务 guard；恢复后通过 MPC 仅打开“秘密画像是否与授权合成参考一致”的布尔值。测试在同一运行进程内完成，没有验证进程重启、磁盘回滚或故障共识。显式 `prepare_abort` 是运行进程内否决提交，不是机器崩溃恢复实验。

### 命题六：公开画像有单次保证，多轮按账户参与累计

固定公开账户队列、结构全集和每类前缀长度。邻接数据只替换队列中一个账户的当前口令：结构人数的 $L_1$ 变化最多2，排序频次的总变化最多2，拼接向量敏感度最多4。离线画像实验使用连续拉普拉斯机制；真实 MPC 原型改用每方独立贡献的离散拉普拉斯噪声，三份噪声在 MPC 内相加后才公开，不先恢复真实频次。

令 $q=\lceil 2^{64}\exp(-\varepsilon_0/4)\rceil/2^{64}$。每份离散噪声为两个精确有理几何抽样之差，其概率正比于 $q^{|z|}$；向上取整使 $-4\log q\leq\varepsilon_0$。对任意相邻向量，概率比至多 $\exp(\varepsilon_0)$。至少一方诚实且其噪声未知时，其他独立贡献只是额外后处理，因此理想无界抽样具有单次 $\varepsilon_0$-差分隐私。它比单份噪声更保守，效用不能直接照搬离线实验值。

有限实现对每个几何样本在 $M=2^{28}$ 处中止而不发布。若一轮画像有 $D$ 个坐标，三方共使用 $6D$ 个几何样本，中止概率由并集界至多 $\tau=6Dq^M$。通过与理想抽样耦合，可用保守界 $\delta\leq(1+\exp(\varepsilon_0))\tau$ 给出有限实现的近似隐私保证；不能把有界实现也无条件写成纯差分隐私。这里 $q<1$，该尾概率极小，但仍明确记入保证。

同一个人若在 $E$ 轮画像中各贡献至多一个账户，基本组合保证累计预算至多 $E\varepsilon_0$，有限实现另累计各轮的 $\delta$。若一人贡献多个账户，必须限制贡献或扩大敏感度；不能把账户级结论直接称为不限账户的用户级保证。加入、退出的参与隐私不是本轮替换邻接目标，若队列人数并非公开固定，需额外保护人数及参与信息。

实际部署的噪声必须在受保护计算内可靠生成，单个腐化方不能知道或控制完整噪声；公开固定种子仅用于离线复现实验。公开真实频次再加噪、公开可重构噪声或导出测试真值，都会绕开这一保证。

### 命题七：存量整改只泄漏被批准的个人资格

匿名画像不能生成账户名单。存量用户下次登录或参与时，将秘密现有口令与批准的群体条件比较，仅向其账户授权流程返回资格位，按分配人数预算创建任务。资格输出确实泄漏该账户满足某个条件，因此把它列为明确的业务输出，不声称它自动有画像的差分隐私。

任务完成仍走命题四、五的同输入原子改密流程。没有用户参与、没有秘密状态的历史加盐凭据，不能被假装转成精确站内分布；此时工具展示参与范围并保持参照/模拟模式。

### 合并后的全流程命题

在可信客户端及授权有限调用的模型，以及 HMAC 伪随机函数、签名和加密通道安全假设下，若秘密状态只通过批准的安全计算功能访问，传输与持久化不额外泄漏，且依赖秘密的分支、匹配位置和中间值均不公开，则网站与最多一方的联合视图限于元数据、自己的份额、批准结果以及公开绑定令牌的重复关系。单方外部份额独立于口令；HMAC 阻止没有诚实方密钥时的离线份额枚举；安全计算保护后续运算。部署入口还必须在绑定计算之前鉴权并限制所有封包调用，不能仅限制成功进入登录判断的请求。

本原型的绑定令牌在固定批次预处理中、业务 guard 之前计算并交换。恶意客户端若与腐化方合谋，反复送入推测份额取得诚实方令牌，仍可能把重复令牌变成在线核对信号。原型没有覆盖这类无限查询模型；不能从 HMAC 修正和每操作四次的 guard 推导出已具备全入口抗探测能力。

这里“只包含批准输出”包括业务结果可能带来的推断，不等于整个业务日志都满足差分隐私。协议实现还要固定或填充秘密相关计算规模，并避免秘密相关错误与时间差；本轮计时只能评价成本，不能自动证明所有侧信道已经消除。

## 4. 输出证书与业务状态的最小契约

实际回执字段为 `request_digest`、`nonce`、`account`、`op`、`outcome`、`committed`、`epoch`、`policy_version`。`committed` 只表示提交状态。每方以自己持有、独立生成且不传输的256位密钥，对本方随机份额封包计算 HMAC-SHA256；只交换这些密钥化绑定值，再构造公共请求摘要。相同本地密钥与封包维持幂等，重新随机分享的口令不产生统一确定性口令指纹。该组合额外依赖 HMAC 的伪随机函数安全和各方绑定密钥隔离。

不仅不能公开口令哈希，也不能公开其他方无密钥份额封包的哈希。对一次分享，已知 $y_1$ 与猜测位 $b$ 可推算 $y_2=2y_1-b$、$y_3=3y_1-2b$；若其余封包的普通哈希也公开，腐化方就可以离线核对完整候选。私有密钥化绑定阻断离线枚举，但不消除相同封包的令牌重复关系，也不能独自阻止主动获取新令牌的在线核对。必须鉴权并限制包括冲突 nonce、格式拒绝、重放等所有入口调用，且在令牌生成前执行；不能用“封包本来是随机的”代替分析。

三方分别使用 Ed25519 签署同一回执，网站独立验证三个不同已知签名者、相同回执及预期请求上下文。缺失签名、重复签名者、篡改字段或错误上下文一律拒绝，网站不能只凭用户自填结果接受。三方签名证明这些方认可相同消息，不会把被动安全 MPC 变成恶意安全 MPC。错误提示固定且粗粒度，避免把“第几个热门值命中”“某结构有几人”返回给网站。

预算账本至少区分两类：发布画像的隐私预算，以及整改分配的人数预算。已发布的隐私预算不能因策略失败而退还；失败且没有输出的计算可按冻结规则处理。人数预算按已分配任务记账，重复请求不再扣除。策略更新不符合原有风险与成本门槛时保持；协议、版本或事务出错时保留旧认证与旧贡献，不能因界面展示需要强行成功。

外部公开参照资料训练的攻击模型可留在客户端本地或进入受保护命中检查，仅返回受限评价。本站真实私密口令并不交给现有 PCFG 明文训练器；模型未知或计算失败不能显示为安全。本轮没有实现私密 PCFG 训练或线上风险成本控制器，原型刷新隐藏规则仅验证执行路线；实际应用仍须接入已有成本门槛与保持决策。

## 5. 最小实验与证据安排

上一轮[画像实验](第三板块_隐私保护口令统计与联合策略报告.md)已经验证表示误差、重复覆盖和注册重选效用。本轮只补它没有覆盖的密码学功能与状态闭环，不重训攻击模型。

| 证据 | 针对缺口 | 验证口径 |
| --- | --- | --- |
| 三方真实 MPC 小样本 | 不是普通进程内隐藏字段 | 三个进程各仅加载自己的外部份额；记录 MPyC 版本、腐化阈值与通信/耗时 |
| 格式、派生结构与相等性 | 输入是否正确且绑定 | 正常和异常输入，对照离线真值；测试程序真值不发布给管理员 |

| 同输入认证与改密 | 政策是否能换密绕过 | 正确/错误旧口令、检查输入与提交输入不一致 |
| 更新及撤销 | 统计是否反映当前账户 | 成功加一、旧值撤销、新值加入；重复与失败均不改总状态 |
| 私密资格及预算 | 存量工具是否闭环 | 资格结果、幂等分配与预算耗尽；不生成明文账户口令表 |
| 版本、次数及输出契约 | 防止无限探测和失效提交 | 过期、重放、超过次数、超隐私预算均保持或拒绝 |

### 5.1 最终证据表

最终运行使用 MPyC 0.11、cryptography 46.0.7，三方各只接收本方128位外部份额，上传和方间通信使用双向认证 TLS。有限域为58位，验证口令长度8—16字节；采用4个公开结构加 OTHER、每类3个频次槽、一个结构外完整热点。输入全是授权合成夹具，不含真实用户口令。

| 需要证明的工具能力 | 最终实验记录 | 得到的证据与边界 |
| --- | --- | --- |
| 真正受保护上传与计算 | 三个独立进程、逐位分享、mTLS、私有256位 HMAC 绑定；12个单方 JSON 的夹具字符串扫描命中0 | 已跑真实密码学协议，不是仅隐藏界面字段；扫描用于发现意外明文，不是保密证明；仍为单机测试 |
| 输入与结构可信派生 | 不一致份额、符合多项式但非二进制份额、非连续填充、自报伪造结构及另报认证输入均被拒绝 | 接口共用有效秘密输入，结构从字节生成；不升级为恶意计算方安全 |
| 秘密频谱与规则 | 完整热点拒绝、结构拒绝及合规注册符合预期；三阶段画像和两次加载后比较均一致 | 不输出热门字符串、账户结构或精确频次；原型规则规模很小 |

| 事务与恢复契约 | 精确重放返回原结果，冲突 nonce、旧账户/策略版本拒绝；显式否决未改变版本；两次磁盘加载恢复份额和 guard | 验证提交、幂等、份额保存/读取；不是进程崩溃、重启或分布式共识验证 |
| 存量整改闭环 | 认证后证明资格；分配1项、重复分配不加额、额外资格者因人数预算1被拒绝；私密改密完成1项 | 已有资格—分配—完成的功能基础；没有实现完整业务权限系统或自动寻找全站账户 |
| 隐私预算与限次 | 首次发布预算1、同快照缓存读取1次不再采样、下一快照预算耗尽；第五次登录检查被限次拒绝 | 已验证画像预算及业务登录次数；固定批次预处理尚无全入口额度，不能声称覆盖全部绑定探测；资格/登录结果不因此获得差分隐私 |
| 回执认证 | 44项事务及结果均验证三方不同签名；篡改、缺方、重复签名者、错误上下文4个负例均被拒绝 | 可独立验签的业务回执已实现；不是证明计算方主动作弊时计算正确 |

**总计48/48个外部检查通过**，其中44项事务和4项回执负例；另有18/18项内部诊断通过，每方6项。内部诊断只在合成实验中打开参考相等性布尔值，不提供给真实管理员任意查询。相关画像及事务单元测试11项通过，含无密钥份额哈希可枚举的反例回归；该反例说明为何需要私有 HMAC 绑定。

## 6. 本板块能够给工具的结论

在可信客户端、独立三方且最多一方被动腐化的模型内，所需功能都可表达为有限安全计算；公开画像另有明确的单次及组合隐私保证。认证、政策和统计共用输入，原子更新及有限资格输出，使用户端与网站端有一条完整的功能路线，不再依赖网站接收明文。

这条路线允许论文提出“全流程在所述模型内可行”，不允许扩大成恶意网站任意篡改客户端、两方串通、无限在线猜测和生产灾难恢复下都安全。已有研究支撑密码学基础；本项目的贡献仍然是结构条件匿名表示、去重隐藏联合策略，以及针对两类工具的闭环整合与实测。

实际原型已经补上此前只有理想功能模拟的缺口，证明输入、统计、规则、认证、改密撤销与有限整改能够接在同一密码学功能链中。前端接入仍需要业务权限、可信客户端分发、绑定计算前的全入口鉴权与总额度、真实跨组织运营、完整在线成本评估与故障恢复；因此论文可以主张“工具核心功能具有理论与小样本协议证据”，不把这些未实现的工程能力写成已经完成。
